# Conformance

The shape a specimen's evidence takes when it holds one library run to two cases: a positive case the run measures, and a negative case where the run takes the fallback it promises.

This is a **library namespace** holding one resource and the case-setup techniques. It declares no `workflow.yaml` and takes no place in any graph. A specimen under `corpus/specimens/` refers to a run, binds it twice, and reports both bindings against the [case report](resources/case-report.md) guide here, so twenty specimens share one report shape and one set of rules about what a row may claim.

A case that gates on a condition also needs a subject holding it, and where the run's own body settles the condition the subject is prepared per walk rather than chosen once. [`prepare-stale-fixture`](techniques/prepare-stale-fixture.md) is that technique for a graph behind its tree and [`prepare-unbuilt-fixture`](techniques/prepare-unbuilt-fixture.md) for a tree carrying none, and every specimen whose case reaches a rebuild or a first build binds the one definition. A case over a tree the index holds under a standing registry name names it by that name, and [`gitnexus::tree-for-graph`](/gitnexus/routines/tree-for-graph.yaml) reads the tree's path from the index. A case over the workflow-server tree binds the session's `host_repo_path`, which is that tree where the session opened from a workflow-server checkout, and [`gitnexus::covering-graph`](/gitnexus/routines/covering-graph.yaml) names the graph covering it. Either routine stops the case where the index holds no such graph.
