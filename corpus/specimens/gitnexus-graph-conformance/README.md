# GitNexus Graph Conformance

A specimen of one form: a reference that composes. `area-comprehension` refers to `index-refresh`, so the walk drives a run whose body contains another run's body — the inner steps splice inside the outer, carrying both reference ids on their identifiers, and neither run's internals reach the variable bag.

Around that sit the remaining runs that read a graph rather than a diff: the two refreshes, the symptom trace, the restructuring surface, and the diagram source referred to twice in one activity with a different argument each time.

Three properties the walk evidences:

- **Prefixes compose.** The refresh inside the area run carries `comprehend.refresh.` ahead of each of its own step ids, so the same run referred to directly in the first activity and indirectly in the second yields two identifier sets that cannot collide.
- **One run, two references, two answers.** The diagram source is referred to twice in `trace-and-draw`. Each reference binds its own argument, which selects which half of the branching body runs, and its own output name — so the package and sequence sources land side by side.
- **The graph is part of the answer.** `area-comprehension` produces the graph name it resolved, and the closing activity opens with it. An answer that does not name the tree it came from is one a reader has to guess at, which the namespace's own addressing rule is about.

The closing activity also holds the two index reads against each other — the one the first activity took directly and the one the nested refresh took — because they answer about one graph and a disagreement would be the nesting landing a value where the outer reference did not expect it.

| Activity | Refers to |
|---|---|
| `refresh-graphs` | `index-refresh`, `group-refresh` |
| `read-the-area` | `area-comprehension` (which refers to `index-refresh`), `restructure-surface` |
| `trace-and-draw` | `symptom-trace`, `diagram-source-select` ×2 |
| `report-conformance` | nothing — states what the three before it landed |
