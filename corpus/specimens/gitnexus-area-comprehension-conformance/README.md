# GitNexus Area Comprehension Conformance

A specimen of one form: one library run held to a positive and a negative case, so the measurement and the promised fallback are evidenced side by side.

The run is `gitnexus::area-comprehension`, which names the graph holding an area, brings it current through a nested reference to the index refresh, finds the execution flows the area's concept ranks into, and then iterates twice — once over the symbols those flows run, reading each one's connections, and once over the flows themselves, reading each one's ordered trace. The positive case names `technique loader composition`, a concept the workflow-server graph's flows rank into, so the query lands processes and process symbols and both passes fill their lists. The negative case names `zzqx quiddity nonesuch`, a concept no flow ranks into, so the query report lands with no process and no process symbol — its definitions may still fill — and both passes run zero times, leaving the contexts and traces empty. That is the fallback the run promises for a concept outside the graph, and the report names it as such rather than as an area read and found unconnected.

The run's first output is the graph it resolved, and both reference sites bind it under the one name `repo_name`, so the report's header names the graph every answer came from.

What the walk evidences is the reference under two bindings: the same run resolves under `gitnexus::area-comprehension` twice, its steps — a nested run and two per-item passes among them — splice into each activity under that activity's prefix, and its six outputs land under the names the reference sites bind. The closing activity reports both against the shared [case report](/conformance/resources/case-report.md) guide.
