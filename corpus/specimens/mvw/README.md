# Minimum Viable Workflow

The live sidecar's first walk: one orchestrator, one activity, one routine, one technique.

A miss here is a miss on the instance — it cannot open a session and dispatch one activity. The change-surface specimen is a different workflow, walked only after this one holds.

## The form

`dispatch` refers to `record-dispatch`, whose only step binds `note-ran`. The graph is that activity to `__terminal__`. `variable-binding` is listed so the worker receives the bind protocol; it is not a second step of the run.

Walk it as `workflow_id: mvw`. Do not open meta for this pass.

## Copying from it

Take this when a live instance needs a cheap dispatch that still loads a routine and a technique. Do not grow it. Extra activities, loops, fans, checkpoints or a second technique belong on a different specimen.
