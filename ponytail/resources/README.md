# Ponytail Resources

> Part of the [Ponytail Lean-Coding Workflow](../README.md)

The reference files hold the discipline the techniques apply, and each artifact a pass writes has a creation guide. A technique cites the section it needs by anchor rather than restating it.

The authoritative content lives in each `.md` file and is served by `get_resource`. This file is the catalog — what each resource owns.

---

## Resource Catalog

| Resource | Owns |
|----------|------|
| [the-ladder.md](the-ladder.md) | The understand-first trace, the seven rungs, and the non-negotiable safety floor |
| [review-taxonomy.md](review-taxonomy.md) | The five over-engineering tags, the one-line finding format, and the net-savings scoreboard |
| [ponytail-marker-convention.md](ponytail-marker-convention.md) | The `ponytail: <ceiling>, add when <trigger>` inline-comment convention and the `no-trigger` flag |

| [lean-brief.md](lean-brief.md) | Creation guide: `lean-brief.md` — the traced flow, reachable rungs, and obligations in play |
| [lean-change.md](lean-change.md) | Creation guide: `lean-change.md` — code first, then at most three lines on what was skipped |
| [audit-findings.md](audit-findings.md) | Creation guide: `audit-findings.md` and `review-findings.md` — one line per finding under its designator, biggest cut first, net scoreboard |
| [debt-ledger.md](debt-ledger.md) | Creation guide: `debt-ledger.json` — one row per marker with its ceiling and upgrade trigger |
