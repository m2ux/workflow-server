## Overview

Every work-planner command that needs the long-lived branch names reads `config/branches` at one revision, the tooling branch's remote head `origin/workspace`, fixed for every project. Epic bases, review pull requests, task targets and hot-fix targets are evaluated against those names, and an epic base need not carry the file.

## Problem

`sync.py` read the declaration at each `--revision` an epic sync gave it, the epic bases, and compared declarations across them. A project keeping `config/` on its tooling branch alone, as prosiform does, had no declaration at any epic base, so every branch-based check of its epics went unrun. Base preparation read it at the long-lived branch a base is cut from, and a delivery survey at `origin/workspace`: three readings of one statement.

## Proposal

- `sync.py` holds `TOOLING_BRANCH = 'origin/workspace'`; `read_branches(project)` reads there. The cross-base comparison, `epic_base_declarations`, is removed.
- `--revision` on an epic sync names the fetched epic bases whose commits the draft check reads, and needs `--project`. `--names` takes `--project` alone and refuses `--revision`.
- `deliver.py` drops `--revision`; `--project` alone reads the names.
- [Branches](https://github.com/m2ux/workflow-server/blob/workspace/skills/work-planner/artifacts/delivery-branches.md#branches) states the rule once; base preparation, Read Delivery Branches, List Long-Lived Branches, Sync Epic, Compute Available Work and their mode and protocol callers defer to it.
