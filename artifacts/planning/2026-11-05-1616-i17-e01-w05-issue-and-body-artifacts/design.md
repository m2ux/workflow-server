# Issue and Body Artifact Design

## Boundary

The authorized family comprises acceptance-criteria, epic, epic-issue-body, hotfix, hotfix-body, initiative, initiative-issue-body, issue, issue-body, proposal-body, pull-request-body, repository-labels, standalone-body and task-body artifacts. The live source is the content authority. Pinned examples supply layout alone. Work Planner is the acceptance scope.

## Operations and Contracts

An operation keeps its callable heading and moves each existing numbered action to a flush numbered heading step. A one-step operation has one heading step. Existing command anchors remain callable operation headings, with an executing step containing their command, conditions and explicit examples. Operations list linked Inputs and Outputs backed by third-level Fields contracts. Shared concepts have one contract home; command variables link that contract while retaining their exact shell quoting and order.

## Preservation

The baseline ledger records file hashes, Prerequisites, every fenced specimen and operative condition. All original Prerequisites remain byte-identical. Body templates remain literal Fields/Template specimens. Command payloads retain syntax, flags, ordering, quoting and line breaks after stripping the added argument-link markup. Explicit examples remain examples. The final ledger accounts for each source condition and specimen at its destination.

## Readers and Validation

The runtime template reader already identifies Fields/Template independently of operation layout; change it only if concrete evidence demonstrates a defect. Document-interface tests must recognize heading steps and discover scripts inside callable operations while retaining their existing guarantees for the installed families. Coordinate shared reader ownership with the parent before editing.

The installed structure and rules remain in place. Inject exact-file proposed-model declarations only into an isolated checker cache for this family. Run that strict family check and the complete installed Work Planner check, then complete Work Planner and shared suites. Reading-path validation uses repeated independent fresh-context walks when execution capacity is free; retain missing live inputs, broad inherited prerequisites and unavailable tracker/graph evidence explicitly. Structural passing is separate from workflow execution. Make no token-savings claim.

## Delivery Gates

Publish this plan before source implementation. Serialize engineering publication and epic/base writes through the parent. Keep the reservation until the task pull request has its required checks and disclosure evidence. Await the parent's exact-head merge clearance. No successor starts in this session.
