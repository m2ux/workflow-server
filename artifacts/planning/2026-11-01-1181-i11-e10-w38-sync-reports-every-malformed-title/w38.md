## Problem

- **An extensionless Changes path goes unmeasured (N3).**
  Delivery Findings says a span with a directory names a file, but the span pattern requires an extension, so an absent `scripts/missing-tool` is unreported.
- **A malformed title is reported by no finding (N4).**
  `no epic` reads only titles whose prefix parses, so `[I07:E1]`, `[I07: E00]` and `[I07 E00]` are neither delivery nor reported.
- **Docstrings lag the scripts (N5).**
  The sync docstring omits task-titled retitles and the Changes span rules; the board Outputs docstring omits the merge into a task branch that `read()` refuses.
- **The Target line names no base (N6).**
  A misrouted task pull request names the placeholder `i07/e00/<long-lived branch>`, so Sync mode's retarget handler has no base to use.
- **Three branches have no test (N7).**
  Board `integrated()`'s off-route check, the retitle de-duplication and closure's case-insensitive repository comparison survive mutation.

## Proposal

- **A span with a directory names a path by evidence at the head.**
  It names a path when it carries an extension or opens with a top-level directory of the head; a `#anchor` or `:line` suffix is not part of it; it stands where the head holds a file or a directory. A branch such as `i07/e00/main` opens with no head directory and names nothing.
- **No epic reads the initiative's id, not its parsed prefix.**
  A title opening `[I07` with no further digit that names neither an epic nor a task is `no epic`.
- **Target names the epic base a task pull request belongs in.**
  The long-lived branch its task branch's last slug word names, else the one its target names, else each epic base as one of them; Sync mode retargets to the one its work item's Component names.
- **Docstrings and Delivery Findings restate each rule; tests kill the review's three surviving mutants.**
