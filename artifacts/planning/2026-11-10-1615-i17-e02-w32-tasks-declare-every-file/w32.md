**Component:** workspace:skills/work-planner/artifacts/work-item.md

## Overview

A task row is one task, and it may change many files. Its work item declares every file it changes, and the dependency check and delivery survey group, join and route rows by any file they share.

## Problem

Work Item's Component field names one file and requires a task touching more to be split into a task per file. The dependency check and delivery survey read that single declaration. Applied to I17:E02, the rule turned three fix rows into thirty-five one-file rows and forty-one criteria.

## Proposal

- **Work Item.** The Component declaration lists each file the Implementation part changes as `<long-lived branch>:<path>`, one or more. Remove the split-per-file rule and the one-component wording from the field, the template and Sections.
- **Dependency Graph.** Candidate joined units are the undelivered rows of one epic that share any declared file; Component Contention is two rows of different epics sharing any declared file.
- **Epic Issue Body.** Joins' candidate-unit wording follows Dependency Graph.
- **Delivery Plan and Delivery Branches.** A unit changes every epic base its rows' declared files name; `undeclared` names a row none of whose files names a long-lived branch with an epic base.
- **Sync Mode.** Base confirmation reads the bases the work item's declared files name.
- **Scripts.** deps.py and deliver.py (and any other reader of the declaration, found by search) parse every declared file.
