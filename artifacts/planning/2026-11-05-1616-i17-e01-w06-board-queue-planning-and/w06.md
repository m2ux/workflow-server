## Overview

Board, queue, planning and review artifacts expose executing steps and linked input and output contracts.

## Problem

Operations and command specifications occupy separate reading paths. Readers must assemble their accepted evidence, guards and execution sequence across those paths.

## Proposal

Each artifact owns its state and operations. Preserve its live prerequisites, accepted input shapes, command bytes, literal specimens and action conditions while placing commands in numbered steps and contracts in Fields. Lane remains the home of Ready Unit Lanes. Temporary strict-model validation exercises converted files; installed declarations remain the final adoption task's responsibility.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Capture the supplied base, fifteen-file manifest, commands, literal specimens, prerequisites and operative conditions in a preservation ledger. |
| Plan | Register the family design and validation requirements before source edits. |
| Implementation | Convert the assigned family, retain callable anchors where possible, and coordinate consuming support owned by the concurrent reader delivery. |
| Review | Check shared and skill guidelines, semantic fidelity, DRY, SOLID, resolving links, exact input alternatives, retries and guard scope. Record representative repeated fresh-context disclosure walks and their limitations. |
| Test | Run strict proposed-model Check Skill Files over the exact family with current declarations elsewhere, literal installed-model diagnostics, complete Work Planner and shared suites, command/literal/prerequisite preservation checks and final exact-head integrated validation. |
