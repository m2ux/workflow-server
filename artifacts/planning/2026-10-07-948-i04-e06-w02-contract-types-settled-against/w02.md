# W02 — Contract Types Settled Against Filling Operations

## Overview

An activity's contract declares each value it puts in the session bag, with a type. The technique bound to the step that fills that value declares its own output, and where that output names the parts it carries, the value is a structure by the technique's own account. Eleven declarations call such a value a string. This task settles each of those values against the operation that fills it — moving the contract where the operation genuinely publishes members, and moving the operation where the value is one string and the declaration is residue — and adds the run that holds the corpus to the result.

## Problem

- **Eleven declarations describe one value two incompatible ways.**
  `check-operation-contract` reports [eleven `declared-type-mismatch` findings](./declarations.md#the-eleven-declarations) against the corpus, over six values in six workflows.
- **Both sides are internally consistent, so nothing failed on them.**
  The contract guard [never opens the technique file a step binds](https://github.com/m2ux/workflow-server/blob/1caa9ff5/guards/check-operation-contract.ts#L4-L6), and it narrows every derived name to the declared namespace — which is assembled out of the declarations. A disagreement between the two sides is invisible to it by construction.
- **The mismatch is not one defect repeated.**
  Three of the eleven are an operation stating what the artifact's own template already states; one is a [closed value set written as components](https://github.com/m2ux/workflow-server/blob/860e107b/corpus/prism/techniques/emit-run-manifest.md#L50-L64) rather than as the [`#### values` the loader reads](https://github.com/m2ux/workflow-server/blob/1caa9ff5/src/loaders/markdown-technique-loader.ts#L267-L269); five are a report whose tables the technique really does publish. Each direction is a different fix.
- **Nothing runs the check over the corpus.**
  The guard is [outside the registry](https://github.com/m2ux/workflow-server/blob/1caa9ff5/guards/check-operation-contract.ts#L27-L31), so the standard sweep does not reach it, and the test file beside it carries fixtures only. A declaration reintroducing the class would land unmeasured.

## Proposal

The direction is decided per value, because the question — which of the two descriptions is wrong — is a question about the workflow rather than about the notation. A rewrite rule would get three of the six backwards.

- **Where the operation publishes members, the contract declares the structure.**
  `audit_prompt` is addressed at member grain by the technique's own protocol phases, and `verification_report` is emitted as four named tables. Both become `object` in the contracts that declare them.
- **Where the value is one string, the over-declaration comes off the operation.**
  `change_block_index` holds a path a checkpoint message links; `comprehension_artifact` holds document content the artifact template already lays out; `overall_progress` holds `3/7 complete`, with a map of planning-folder paths misfiled beneath it. Each loses the sub-section, and the statement it carried stays where it belongs — in the output's description, or in the resource template that owns the document's shape.
- **A closed set is written as a closed set.**
  `run_status` admits `complete`, `partial` or `error`. Three `####` sub-sections name them, which is the notation for components; `#### values` is the notation for the set, and the contract already declares the same three.
- **A run holds the result.**
  The guard's test file gains the run over the corpus, beside the fixtures that prove the guard still fires. It is the instrument the criterion names, and it is asserted here rather than left to the sweep because enrolling the guard is the task after this one.

## Work Breakdown

| Part | Description |
| --- | --- |
| Measure | Run `check-operation-contract` against a worktree of the integration branch, and record every finding with the declaration and the operation output behind it. |
| Settle | Decide each value's direction against what addresses its members, what its description claims, and what the step binding does with it. Record the direction and its evidence per value. |
| Corpus | Apply the six settlements: two contract moves across five activity declarations, three operation moves across four technique files, and one closed set rewritten as `#### values`. Bump each edited definition's version. |
| Server | Add the live-corpus run to the guard's test file, skipped where no corpus checkout is present, as the other corpus-clean guards assert their own zero. |
| Review | Re-run the full guard sweep on the edited corpus against the same sweep on the unedited base, so a guard this work turns red is told apart from one already red. |
| Test | The guard's own fixture cases; the live-corpus run in `tests/operation-contract-guard.test.ts`, shown failing on the unedited corpus and passing on the edited one; `check-operation-contract` over the corpus; the full `check:all` sweep, base against edited; `npm run typecheck`; and the whole `vitest run` suite, base against edited. |
