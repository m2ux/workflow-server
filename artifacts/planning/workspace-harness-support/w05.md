## Overview

W05 shows a Claude Code session acting on the workspace command policy, so that the harness whose six registered hooks one adapter replaces is known to keep the enforcement it had.

## Problem

Six command hooks whose verdicts the harness merged become one registration reaching one verdict. A differential suite measures that the verdicts agree; no session has shown the single registration firing. A command matching a grant directly was allowed by the harness's own allow list and is now allowed by the adapter, so only a session shows an allowlisted single still running without a prompt. A denial that stops a command without delivering its corrective message changes how the session behaves, because that message is what makes the agent re-issue the command.

## Proposal

A session opened in the rendered workspace, after deployment has written the settings, so the registration it loads is the generated one.

- One tool call per outcome: a command the policy denies, a command it grants directly, a compound command every segment of which it grants, and an operation it holds for confirmation.
- The record covers whether the corrective message reached the agent, not only that the command stopped.
- The observed outcomes are read from this session alone. No outcome from Cursor or Codex is carried into this record.
- Only Claude Code delivers this task. The record carries the runtime identity Claude Code reports, which the harness identity check compares with the declared harness, so a Cursor session cannot discharge it by sharing the adapter.
