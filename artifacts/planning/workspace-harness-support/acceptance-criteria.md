# Acceptance criteria

The conditions the shared harness policy holds to, each with the instrument that
observes it and where that instrument stands. The criteria are carried by the
standalone issue the README's Links table names; this file holds the reasoning
behind each one and the evidence for its standing.

Instruments are the suites `python3 scripts/test-harnesses.py` runs, named by
their test method, and the read-only runtime diagnostic
`.codex/scripts/check_runtime.py`. Standing is measured at `fe430e51`, where
twenty of the twenty-three criteria hold.

## Shared policy

| Id | Criterion | Instrument | Standing |
| --- | --- | --- | --- |
| AC1 | Every request in the equivalence corpus reaches the same effective outcome through the generated Claude registration as through the six-hook pipeline at revision `41717141`. | `test_shell_requests_reach_the_same_outcome`, `test_web_requests_reach_the_same_outcome` | Holds |
| AC2 | The rendered Claude allow list carries the grants the settings template at revision `41717141` carried, treating a trailing `:*` and a trailing ` *` as one pattern. | `test_permission_grants_match_the_baseline_allow_list` | Holds |
| AC3 | No command pattern in `config/permissions.json` ends in `:*`. | `test_command_patterns_carry_no_retired_spelling` | Holds |
| AC4 | A request the adapter cannot read receives a deny decision naming the fault. | `test_invalid_payloads_deny`, `test_unknown_event_denies`, `test_permission_load_failure_denies`, `test_invalid_input_denies` | Holds |
| AC5 | A tool event outside the shell, web and MCP kinds receives no decision. | `test_unknown_tool_abstains` | Holds |

AC1 is the criterion the refactor turns on. The adapters reach one verdict where
six registered hooks each reached their own and the harness merged them, so the
effective outcome is the only thing an agent can observe as unchanged.

AC2 and AC3 hold the compensating change in place. A direct single command is
granted by the permission file rather than by the Claude allow list, so a
dropped grant or a retired pattern spelling silently narrows what an agent may
run. Both are invisible to AC1 alone in a harness that keeps its own allow list.

AC4 states a deliberate departure from the preceding pipeline, which exited
silently and left the harness to prompt. It is a criterion rather than a
regression because the denial is the wanted behaviour for a harness with no
allow list of its own.

## Documentation

| Id | Criterion | Instrument | Standing |
| --- | --- | --- | --- |
| AC20 | Every script path named in `rules/bash-composition.md` and `docs/harness.md` resolves to a file on the branch that names it. | Inspection of both documents against the file tree | Holds |

Seventeen paths are named and seventeen resolve. The criterion exists because
`.claude/hooks/edit_guard.py` resolves the corpus guard by a path it hard-codes
and `docs/harness.md` states the same path, so a document and an adapter agree
on a file neither of them creates. A branch that carries the adapter without the
guard scripts registers a PostToolUse hook that answers exit status 2 on every
edit, reporting that corpus guards cannot measure it.

## Live enforcement

| Id | Criterion | Instrument | Standing |
| --- | --- | --- | --- |
| AC21 | The Codex runtime diagnostic lists the workspace hook registrations in its discovered inventory. | `.codex/scripts/check_runtime.py` exit status | Fails |
| AC22 | A Codex session opened in the rendered workspace applies a workspace hook decision to a tool call. | The observed transcript of that session | Not observed |
| AC23 | A Claude session and a Cursor session each apply a workspace hook decision to a tool call. | The observed transcript of each session | Not observed |

AC21 fails against standalone CLI 0.157.1 and Cursor's Codex runtime
0.154.0-alpha.6.2. Both load the rendered instructions and resolve the skill
link, and both report an empty hook inventory. The cause is unresolved.

AC22 and AC23 are the criteria no adapter contract test can reach. A contract
test proves the adapter decides correctly when it is called; only a session
shows that the harness calls it. They stay unobserved until a session is opened
in the rendered workspace, its hook registrations are reviewed through `/hooks`,
and a tool call's decision is seen.

### Open question

Whether the Codex adapter is delivered while its runtime discovers no hook
registration, or delivery waits on that discovery.

The recommendation is to deliver. Claude and Cursor gain enforcement from the
same change, and the Codex adapter at rest costs nothing: a runtime that
discovers no hook behaves exactly as it does today, with the rule text and no
local checks. Holding the whole change back would keep two harnesses on the old
arrangement to wait on a third. AC21 to AC23 stay unticked and name what is
owed, and the runtime diagnostic reports when the inventory fills.
