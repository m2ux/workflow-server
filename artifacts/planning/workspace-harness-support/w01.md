## Overview

W01 delivers one workspace command policy and the per-harness adapters that carry it, so Claude Code, Cursor and Codex are held to the same blocking rules, confirmation requirements and approval grants.

## Problem

The policy is expressed in one harness's configuration: the command grants live in the Claude settings template, and the compound classifier reads Claude's own settings to find them. The seven scripts that template registers weld classification to Claude event decoding and Claude-shaped responses, so no other harness can reach them. Codex receives the rule text with no hook behind it. A change to the policy is a change in three places, and nothing measures them against each other.

## Proposal

A common permission file holds the command patterns, file grants, web domains, MCP servers, skills and tools. A shared evaluator checks blocking rules, then confirmation requirements, then approval grants, and abstains on anything it does not recognise. Each harness owns an adapter that translates its events into a neutral request and the decision back into its own response format, linking to the shared classifiers rather than copying them.

- The quote-aware shell splitter, the URL checks and the bubblewrap launcher stay as they are, so what a command means does not change with where it is evaluated.
- One renderer discovers each harness's configuration adapter, writes that harness's machine-local files and reports drift from what it would write.
- Codex discovers hooks through an installed plugin, so the workspace is a local marketplace of one and deployment registers it.
- Native approval keeps its authority: an operation requiring confirmation receives no automatic grant rather than a forced denial.
