## Overview

W02 gives a live-session validation record a fixed shape carrying the runtime identity its harness reports, and a check that reads it, so a session attempting a row that belongs to another harness is flagged rather than accepted.

## Problem

Nothing in a validation record ties it to the harness that produced it. The epic has one row per harness and the rows read alike, so an agent holding the Codex row can write a plausible record from Cursor and the only thing standing in the way is a reader noticing the file name. Each harness reports its identity differently — Codex's app-server returns a user agent and home directory on `initialize`, Cursor's client reports a build and reaches the adapter under its own shell tool name, Claude Code reports its own runtime — and none of those can be read from inside another.

## Proposal

A record holds the harness's own report, copied verbatim, beside the declared harness its row names. One check reads every record: it maps each task id to the harness its row names, compares that with the declared harness and the carried identity, and fails on a disagreement, an absent identity, or an identity whose shape could not have come from the declared harness.

- The identity shape is tested per harness, so a record cannot be transplanted by editing the declared name alone.
- A failure names the task, the declared harness and the identity read, so the mismatch is actionable without opening the record.
- The check runs over the whole record folder, so a later task's record is covered without changing it.
