## Overview

W04 shows a Cursor session acting on the workspace command policy, so that the harness which reaches the adapter through an import, rather than through a registration of its own, is known to enforce it.

## Problem

Cursor reads the Claude registrations only while its third-party import is enabled, and nothing in the workspace reports that setting's state. Cursor sends a shell tool under a different name, which a contract test covers and no session has exercised. Claude and Cursor share one adapter, so an outcome observed in one establishes nothing about the other: the event payloads differ, and so does what each client does with a decision.

## Proposal

A session opened in the rendered workspace with the third-party import enabled, its state recorded as the client shows it, before any tool call.

- One tool call per outcome: a command the policy denies, a command it grants, and an operation it holds for confirmation.
- The record covers what the client does with a denial, not only that the command stopped. The corrective message is what makes the agent re-issue the command in a form the policy allows.
- The observed outcomes are read from this session alone. No outcome from Claude Code or Codex is carried into this record.
- Only Cursor delivers this task. The record carries the runtime identity Cursor reports, which the harness identity check compares with the declared harness, so a Claude Code session cannot discharge it by sharing the adapter.
