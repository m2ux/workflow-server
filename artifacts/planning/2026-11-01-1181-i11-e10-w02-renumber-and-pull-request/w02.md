**Component:** workspace:skills/work-planner/scripts/sync.py

## Overview

Renumber and pull request delivery checks: the renumber refusal of delivered identifiers gains fixtures, the epic sync reports pull requests off the epic branch routes and initiative pull requests whose title names no epic, and a row naming another epic's row starts on that row's outputs being available at the consumer's base.

## Problem

- **The renumber refusal is unobserved.**
  `renumber.py` refuses a map moving a delivered task or a pull-request-named epic, but no test the repository holds shows it.
- **Off-route pull requests pass unreported.**
  A task pull request into a long-lived branch or another epic's base, and an integration pull request into the wrong long-lived branch, are only caught by review. An initiative pull request whose title names no epic is skipped silently, since nothing reads it as delivery.
- **Cross-epic starts follow the wrong evidence.**
  A row naming another epic's row waits for that whole epic to close, which gates on unrelated producer rows, and never checks that the output reached the consumer's base.

## Proposal

- **Renumber fixtures.**
  Task mode refuses a map moving a row linking a pull request or commit and writes no file; it applies a map moving only undelivered rows. Epic mode refuses a map moving an epic an open or merged pull request names, and ignores other initiatives' and epicless titles.
- **Branch routes in the epic sync.**
  `sync.py` reports `target` for an open or merged pull request naming the epic whose base is not one of its epic bases, or whose head is an epic base and whose base is not the long-lived branch that head names. It is a long-lived-branch check, so it is `not checked` without the branch names. An integration into the wrong branch leaves the base unmerged, so the epic is not closable; another epic's incompleteness does not hold it.
- **Epicless titles.**
  An epic or initiative sync reports `no epic` for each pull request carrying the initiative's prefix whose title is not `[Ixx:Eyy]`.
- **Producer outputs.**
  `board.py` gains `Outputs`, which reads a producer row's outputs in the project checkout: each merged delivery's merge commit on the long-lived branch its base names, and each linked commit. An output is available when it is an ancestor of the consumer's base on that branch at the remote, or of the long-lived branch while no consumer base exists. An output another repository holds is available once delivered to its long-lived branch or carried there by a later integration merge. `Board.met` uses it for a cross-epic task entry once the producer row is delivered; producer-epic closure is no gate. `deliver.py` passes its `--project` and prints an `output` line for each reading. Missing, stale or unfetched evidence, and a consumer base moved off the output, leave the row blocked.
- **Owning instructions.**
  `delivery-branches.md` gains Producer Outputs and the route report; `dependency-graph.md`, `board-queue.md`, `delivery-plan.md`, `epic.md` and `pull-request-body.md` state the same rules.
