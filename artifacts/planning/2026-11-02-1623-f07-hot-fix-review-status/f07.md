## Overview

An open hot-fix whose delivering pull request is ready for review stands In Review on its board, and one whose delivering pull request is a draft stands In Progress. Board Status in `artifacts/hotfix.md` states the rule once; `hotfix.py`, `board-queue.py` and `statuses.py` follow it.

## Problem

- **A hot-fix never stood In Review.**
  Board Status barred it, `hotfix.board_status` returned In Progress for a hot-fix held In Review, and Advance moved one set In Review by hand back to In Progress.
- **The board queue read no link evidence.**
  `board-queue.py` took pull request records without the issue-link snapshot Advance already fetches, so it could not tell which pull request delivers a hot-fix.

## Proposal

- **Board Status reads the delivering pull requests.**
  `board_status` takes them: an open delivering pull request ready for review gives In Review, an open draft one In Progress, and otherwise the held status decides as before.
- **Advance supplies them.**
  `board-queue.py` takes `--links`, attaches it to the pull request records and passes each hot-fix's delivering pull requests; a board lacking an In Review option keeps In Progress through `StatusField.settle`.
- **The queue jurisdiction admits it.**
  QUEUE allows In Review for an open hot-fix and Done for one closed as completed.
- **One statement of the rule.**
  Board Status states it; every statement that only an initiative or an epic stands In Review names the hot-fix.
