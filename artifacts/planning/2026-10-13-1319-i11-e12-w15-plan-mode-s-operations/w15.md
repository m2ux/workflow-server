# W15 — Plan Mode's Operations Placed or Recorded

## Overview

This task reads the eight command specifications Plan mode reaches through Work Planner's catalog against the symmetric caller test the epic settled, places any the test finds unshared, and names in the record the ones the catalog keeps against the procedures that share them. The caller sets come from the shared check `skills/scripts/check_skill_files.py`, so the placement decision is the check's and the record is where AC19 is observed.

## Problem

- **Plan mode is the one mode the localisation rule never reached.**
  The retrieval walk counts zero operations in `references/plan-mode.md` and eight reached through `references/commands.md`, and the mode's files opened rose from thirteen to fourteen — the widest retrieval in Work Planner.
- **The eight were counted by citation, not by the caller test.**
  A citation count answers which files name a command. The test the epic settled answers which files run it: a file is a caller where one of its procedures — a top-level section carrying a numbered step — carries the citation. A cross-reference between two specifications, and prose that routes a command without stating steps, count for neither.
- **Nothing in the record says which of the eight are shared.**
  AC19 asks for each specification the catalog keeps to be named against the procedures that share it. Without that naming the criterion cannot be observed by reading the record, and the mode's remaining retrieval cost reads as an open question rather than a floor.

## Proposal

The caller sets decide the placement, and the record carries them. Every one of the eight is read with the check's own `citations()` result, and the outcome is written down per specification rather than asserted in aggregate.

### The options weighed

- **Read the eight against the caller test and record the sets.**
  The check is the instrument the epic already trusts for this question. Running it over `skills/work-planner` reports any specification whose procedure-callers number one; printing the same result per specification gives the naming AC19 asks the record to hold. Taken.
- **Move the eight into `references/plan-mode.md` to close the retrieval gap.**
  It would put seven specifications in a file six other modes do not open, and each of the seven would then be cited across files by procedures that no longer hold it. It trades one mode's file count against six modes' correctness, and contradicts the rule it claims to apply.
- **Take the citation counts as the caller sets.**
  Cheaper, and wrong in both directions here: it reads Delivery State as reaching six callers when no procedure runs it, and it would read a specification's sibling cross-references as runs.
- **Retire AC19 as already satisfied by W08.**
  W08 moved the specifications a single procedure ran. It did not write down which specifications stayed, or why, so the catalog's remainder is unrecorded. The criterion asks for the record, and the record does not exist until this row writes it.

### What the sets show

- **Seven of the eight are shared in fact.**
  Add Planning Record, Check Dependencies, Check Format, Create Issue, Patch Body, Retarget Pull Request and Sync Epic each carry between two and seven procedure-callers. The [caller sets](caller-sets.md) name every one of them.
- **Delivery State is run by no procedure at all.**
  Plan mode cites it from Prerequisites, which carries no numbered step, and Align, Deliver and Sync cite it the same way. It states what delivery state means, read ahead of the operations that act on it, so the catalog is where each of its six readers already looks.
- **No specification moves.**
  The rule fires only where procedure-callers number exactly one and the holder is not that caller. None of the eight qualifies, so `references/plan-mode.md` gains no Commands section and its mode-file section set stands unchanged.
- **Plan mode's fourteenth file is the floor.**
  Opening the catalog buys it seven operations, each shared with a mode that opens the same catalog for the same reason. A mode cannot reach a shared specification in fewer than one file.

### The defect the instrument found

- **The check reports three findings over `skills/work-planner` before this row's work.**
  `references/work-breakdown.md` lines 118 to 120 carry inline bold leads of 230, 110 and 214 characters against the hundred-character limit, from the Corpus Audit section pull request #1359 added.
- **The fix belongs with the run that found it.**
  The test row for AC19 runs the shared check over the skill, and a non-empty report stops it. The three bullets take the skill's bold-lead form: the bold statement stands alone on the bullet, and its body sits on the next line indented under it.
