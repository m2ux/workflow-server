**Component:** workspace:skills/work-planner/scripts/closure.py

## Overview

The closure gate passes or blocks an issue on the issue and its Development links alone, the two things GitHub exposes, so a delivered issue can always be checked.

## Problem

- **The gate demands a setting GitHub does not expose.**
  `closure.py` blocks unless its Development snapshot carries `auto_close_issues: false`. No REST field and no GraphQL field of `gh` 2.46 carries the repository's auto-close setting, so the value is typed in by hand and the gate passes on a claim, not on evidence.
- **The snapshot is hand-written.**
  [Write Development Snapshot](https://github.com/m2ux/workflow-server/blob/workspace/skills/work-planner/artifacts/issue.md) has the caller compose `{repo, number, complete, auto_close_issues, pull_requests}`. `complete` is the caller's word that the read finished, and `--prs` asks for a second, REST copy of each linked pull request.
- **Two rules decide the same thing.**
  `closure-sweep.py` reads the snapshot `links-by-issue.py` writes and decides support with its own `findings`; `closure.py` reads a different shape and decides with its own `blockers`.

## Proposal

A closing session fetches the issue, runs `links-by-issue.py` on it, and hands both files to the gate.

- **The gate reads what GitHub writes.**
  `closure.py --issue issue.json --development links.json`. The snapshot is `links-by-issue.py`'s output, which carries each linked pull request's repository, number and state as the tracker reports them.
- **Absent evidence is not empty data.**
  An issue mapped to `[]` has an empty Development field and adds no requirement. An issue the snapshot holds no entry for was never read, and blocks as `Development links not captured`. `links-by-issue.py` writes no file when a relation is unreadable, so an absent or unreadable snapshot blocks as unreadable evidence. A link entry lacking its repository, number or state is unreadable evidence.
- **The setting gates linking and merging, not closure.**
  The auto-close setting stays a session prerequisite in [Auto-Close Setting](https://github.com/m2ux/workflow-server/blob/workspace/skills/work-planner/artifacts/issue.md#auto-close-setting), where it gates the links and merges that precede closure. The gate takes no input from it.
- **One rule for one decision.**
  `closure.py` owns `blockers`; `closure-sweep.py` imports it, so a closed issue is listed exactly when the gate would block it.
- **Retired.**
  `--prs`, the `complete` and `auto_close_issues` keys, and the Write Development Snapshot command.
