id: gitnexus-guarded-rename-conformance
version: 1.1.0
title: GitNexus Guarded Rename Conformance Workflow
description: >-
  Hold the gitnexus guarded-rename run to three cases. The positive case binds a symbol the graph
  holds, so the preview lands an edit list, the gate accepts it, the rename writes the edits and the
  diff is read back. The negative case binds a symbol the graph does not hold, so the preview
  refuses with an error naming it, the gate refuses too and the steps after the gate stay unreached
  — the fallback the run promises for a symbol outside the graph, distinct from an empty edit list,
  which is a symbol that resolved and moved nothing.
  The ambiguous-name case binds a name two symbols carry with no file to separate them, so the
  preview answers with a status of ambiguous and ranked candidates, the gate refuses it and nothing
  is written.
author: m2ux

techniques:
  activity:
    - variable-binding
variables:
  - name: repo_name
    type: string
    description: Name of the indexed graph every operation in the run addresses.
    defaultValue: workflow-server
  - name: positive_symbol_name
    type: string
    description: A symbol the graph holds, so the positive case previews an edit list with rows.
    defaultValue: walkArtifactPath
  - name: positive_new_name
    type: string
    description: The name the positive case's rename moves to.
    defaultValue: walkArtifactPathRenamed
  - name: positive_file_path
    type: string
    description: The file holding the symbol, which separates one of that name from the others; empty where the name alone is enough.
    defaultValue: ""
  - name: negative_symbol_name
    type: string
    description: A symbol the graph does not hold, so the negative case's preview refuses with an error naming it.
    defaultValue: no_such_symbol_zz
  - name: negative_new_name
    type: string
    description: The name the negative case's rename moves to.
    defaultValue: no_such_symbol_zz_renamed
  - name: negative_file_path
    type: string
    description: The file holding the symbol, which separates one of that name from the others; empty where the name alone is enough.
    defaultValue: ""
  - name: ambiguous_name_symbol_name
    type: string
    description: A name two symbols in the graph carry, so the ambiguous-name case previews a status of ambiguous with ranked candidates.
    defaultValue: isDirectory
  - name: ambiguous_name_new_name
    type: string
    description: The name the ambiguous-name case's rename moves to.
    defaultValue: isDirectoryRenamed
  - name: ambiguous_name_file_path
    type: string
    description: The file holding the symbol, which separates one of that name from the others; empty here, so the name alone is offered and the graph cannot choose between its holders.
    defaultValue: ""
initialActivity: positive-case
graph:
  positive-case:
    gated: negative-case
  negative-case:
    gated: ambiguous-name-case
  ambiguous-name-case:
    gated: report-cases
  report-cases:
    reported: __terminal__
