# GitNexus Symptom Trace Conformance

A specimen of one form: one library run held to a positive and a negative case, so the measurement and the promised fallback are evidenced side by side.

The run is `gitnexus::symptom-trace`, which follows a symptom into the graph — the flows its text ranks into, the suspect symbol's connections, the ordered trace of every flow that symbol runs, and the call chains that reach it within two hops from a raw graph query. The positive case binds error text the ranking matches and a suspect the graph holds, so the run lands ranked flows, the suspect's connections, a trace per flow it runs and the chains reaching it. The negative case binds text no flow's keywords match and a suspect no graph holds, so the ranking lands no flow, the context resolves nothing, the flow cycle runs no iteration and the raw query returns no chain — which is the fallback the run promises for a symptom outside the graph, and which the report names by those four marks rather than as a suspect the graph holds and nothing calls.

What the walk evidences is the reference under two bindings: the same run resolves under `gitnexus::symptom-trace` twice, its steps and its loop splice into each activity under that activity's prefix, and its four outputs land under the eight names the reference sites bind. The closing activity reports both against the shared [case report](/conformance/resources/case-report.md) guide.

| Activity | Refers to | Binding |
|---|---|---|
| `positive-case` | `symptom-trace` | text the graph ranks and a suspect the graph holds |
| `negative-case` | `symptom-trace` | text no flow matches and a suspect no graph holds |
| `report-cases` | nothing — states what the two bindings landed | |
