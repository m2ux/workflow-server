id: dispatch-client-workflow
version: 6.0.0
name: Dispatch Client Workflow
description: Drive the client workflow's activity loop, each worker carrying a bounded run of activities.
variables:
  reads:
    - client_initial_activity
    - client_session_index
    - component_path
    - host_repo_path
    - planning_folder_path
  writes:
    - name: client_workflow_completed
      type: boolean
      description: Whether the dispatched client workflow has reached workflow_complete
      defaultValue: false
    - name: current_activity
      type: string
      description: The client activity the walk holds, and null once the client graph routes to none
    - name: from_activity
      type: string
      description: The client activity an advance retires
required: true
steps:
  - kind: routine
    id: client-activity-loop
    routine: activity-loop
    with:
      session_index: client_session_index
      initial_activity: client_initial_activity
    outputs:
      current_activity: current_activity
      from_activity: from_activity
  - kind: action
    id: record-client-completion
    when: current_activity == null
    actions:
      - action: set
        target: client_workflow_completed
        value: true
exits:
  - id: "null"
    when: current_activity == null
outcome:
  - The client workflow has executed end to end with its artifacts committed and state persisted at every activity boundary
  - Each worker carried a bounded run of activities in one context, so the harness baseline was paid once a run rather than once an activity
  - The user retained control over every decision point — checkpoints surfaced to them and their selections steered the workflow
  - The client workflow has no further activities to run, so the meta can proceed to close it out
  - Reaching the end of the activity loop is recorded, so close-out can tell a completed run from one that stopped at the iteration bound
