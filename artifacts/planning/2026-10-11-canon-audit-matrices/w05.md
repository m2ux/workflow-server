# Shared Authoring and Retrospective Audit Lifecycle

## Overview

Route Author and Audit through the verified-map method and keep all affected evidence current as drafts and fixes change the source.

## Problem

- **Authoring and audits select work differently.** A shared map must be reached from both entry paths with the needed context.
- **Edits change the meaning of prior results.** Source, canon and relationship changes can invalidate apparent completion.

## Proposal

Publish shared mapping and dispatch guides, bounded command specifications and mode entry links. Preserve existing edit authority, finding verification and reporting policy. Refresh the map and invalidate dependent evidence after changes, then qualify the behavior with independent seeded and clean agent scenarios.

## Work Breakdown

| Part | Description |
| --- | --- |
| Skill integration | Update shared rule homes, mode procedures, command references, dependencies and representative scenarios; retire duplicate manual coverage and dispatch paths. |
| Refresh | Implement dependency invalidation, draft-byte capture and current-state reconciliation for authoring and resume. |
| Qualification | Compare representative existing and proposed skill runs under matching inputs; record misses, false positives, coverage and cost. |
| Test | Deliver T12 fresh-context entry-path walks, T13 source/canon mutation cases and T14 repeated seeded evaluations, plus applicable existing skill checks. |
