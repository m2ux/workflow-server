W36 fixes findings 7-12 of the [agent review of #1555](https://github.com/m2ux/workflow-server/blob/engineering/artifacts/planning/2026-11-01-1181-i11-e10-epic-review/review-1555.json) on `i11/e10/workspace`, so sync, deps, board and closure decide each case the review raised, and Sync mode handles every finding the epic sync reports.

## Problem

- **Sync misreads review bodies and titles.**
  A Changes code span such as `board.Outputs` or `main:src/x.ts` is measured as a file. A task-titled pull request `[I07:E00:W01]` is reported `no epic`, and the prefix test also matches `[I070`.
- **Deps bounds a lone row.**
  A single row covering seven criteria is reported as a joined unit over the bound.
- **Board reads a stacked merge as a long-lived branch.**
  A producer merged into a task branch is read as landing on a branch named after the task, and one merged into the consumer's own task branch reads as available. The linked-commit reading has no test.
- **Closure accepts another repository's snapshot.**
  The Development snapshot carries no repository, so a file for another repository's issue of the same number passes.
- **Sync mode lists no handler for several findings.**
  Step 6 omits `retitle`, `changes`, `target`, `no epic` and others, and its Unevaluable handler covers only declarations.

## Proposal

- **A span names a file by evidence at the head.**
  A path with a directory is a path; a bare name is a file name only when a file at the head carries its extension; a component `<branch>:<path>` names its path for that branch's base alone.
- **Titles are read by their full prefix.**
  `no epic` holds titles prefixed `[I07]` alone; a task-titled pull request is a `retitle` to `[I07:E00]`.
- **The unit bound applies to joined units.**
  A lone row's criteria are format.py's split rule.
- **An off-route merge lands on no long-lived branch.**
  A base under `iNN/` that is not an epic base, task branches included, leaves the output unverified with that reason.
- **The snapshot names its repository.**
  links-by-issue.py writes `{repository, issues}`; closure.py and closure-sweep.py refuse a snapshot of another repository and validate it in one loader.
- **Sync mode step 6 names a handler per finding.**
