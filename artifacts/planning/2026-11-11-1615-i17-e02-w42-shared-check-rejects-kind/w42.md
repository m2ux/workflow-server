## Overview

The shared skill check fails when a general artifact, mode, protocol or script names a registered kind of work or imports a kind module outside the registry, so the kind separation E02 delivered cannot regress.

## Problem

- **Separation is guarded only per script.** Script tests search their own file for kind names, but the general docs (W22, W23, W34, W35) were checked by planning-folder scripts that never run with the suite.
- **A kind's rule restated in a general file.** artifacts/agent-review.md still states the hot-fix review rule (base_ref currency, every finding fixed) as the rule for every kind-tagged pull request, though W40 moved that rule onto the kind interface.

## Proposal

- **Kind-name check.** check_skill_files.py reads the registered kinds (SKILL.md registration and scripts/kinds.py) and reports any general artifact, mode, protocol or script that names one or imports a kind module outside kinds.py. Kind files, the registration and literal examples (code spans, fenced blocks, ids such as `[F00]`) pass. rules.json maps the check to its rule.
- **Agent Review.** agent-review.md states that the selected kind supplies its review rule through the registered Review Before Merge operation, and restates no kind's rule.
