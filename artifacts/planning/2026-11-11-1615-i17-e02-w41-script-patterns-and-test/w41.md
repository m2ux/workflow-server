## Overview

The Work Planner scripts compile the title-tag pattern and the pull-request home pattern in two places, sync.py and board.py. This issue gives each pattern one definition, so a change to either rule lands once. The Work Planner template test imports the format script without putting the scripts folder on its import path, so it runs only beside a module that does.

## Problem

- **Two title-tag patterns.**
  sync.py's `PREFIX` and board.py's `PREFIX` are the same `[I00:E00:W00]` pattern. board.py owns title tag parsing (#1667), but sync.py matches titles with its own copy at five call sites.
- **Two pull-request home patterns.**
  sync.py's `PULL_HOME` and board.py's `PULL_REF` are the same pattern under different names.
- **Import direction.**
  board.py imports sync.py, so sync.py cannot import either pattern from board.py without a cycle.
- **The module fails alone.**
  `python3 -m unittest discover -s test -p test_templates.py` in `skills/work-planner` fails with `ModuleNotFoundError: No module named 'format'`.
- **The full suite hides it.**
  Discovery imports an earlier module that inserts the scripts folder into `sys.path`, so the module passes only by load order.

## Proposal

- **One definition per pattern.**
  Each pattern is defined once, in the module the import chain lets both callers reach, and every caller imports it. Title tag parsing, `tags`, stays in board.py and uses that definition.
- **Searches enforce it.**
  The shared-rule tests check that each pattern is defined in one script only.
- **The module states its own import path.**
  [test_templates.py](https://github.com/m2ux/workflow-server/blob/01f84933a/skills/work-planner/test/test_templates.py#L7-L8) takes the scripts folder onto `sys.path` before importing `format`, as the other script-importing test modules do.
