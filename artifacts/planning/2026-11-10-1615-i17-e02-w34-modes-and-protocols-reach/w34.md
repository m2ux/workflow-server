## Overview

Deliver Mode, Hoist Mode, Unit Dispatch, Issue Delivery, Task Merge and Issue Closure name no individual kind of work and reach each kind's operations through the kind registration.

## Problem

- **deliver-mode.md.** Deliver Mode names hot-fix cases inline: the Hot-Fix Hold release, held-unit confirmation, draft opening and the Review a Hot-Fix route. Adding a kind means editing this general file again.
- **hoist-mode.md.** Hoist Mode names hot-fix cases inline: the hot-fix destination, number, body and status settlement steps. Adding a kind means editing this general file again.
- **unit-dispatch.md.** Unit Dispatch names hot-fix cases inline: the Hot-Fix Unit, new, retained and confirmed-hold branches. Adding a kind means editing this general file again.
- **issue-delivery.md.** Issue Delivery names hot-fix cases inline: its Hot-Fix step and Sync Hot-fix Issue call. Adding a kind means editing this general file again.
- **task-merge.md.** Task Merge names hot-fix cases inline: its Record a Hot-Fix step. Adding a kind means editing this general file again.
- **issue-closure.md.** Issue Closure names hot-fix cases inline: its task-or-hot-fix delivery result step. Adding a kind means editing this general file again.

## Proposal

Replace each kind case with the general operation the kind registration names, and keep every kind-specific rule in the kind's own artifact. Preserve each caller's inputs, results, authorization, lifetime and evidence gates. Literal examples stay as controls. Already-merged rows moved some steps (W20 hot-fix operations, W21 hot-fix body, W23 board membership); start from the epic base, not the per-file inventory.
