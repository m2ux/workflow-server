## Overview

This epic turns three defect classes a reader finds into something that finds the next instance: an instruction that reaches a role that cannot act on it, a fallback stated only in a description, and a rule that carries more than one constraint under one heading.

## Problem

- **An instruction can require a call the role is barred from making.**
  The defect lives in the relationship between files, and every existing check reads one construct at a time. The same shape arises wherever a shared contract describes a call one of the roles is barred from making.
- **A fallback can live only in a description.**
  An input's description says what happens when no value arrives. The declaration carries no default. A caller that binds nothing gets nothing, and the sentence is the only record of what was supposed to happen.
- **The one-invariant entry is outside the audit's scope.**
  [AP-156](https://github.com/m2ux/workflow-server/blob/6355c392/corpus/canon/resources/anti-patterns.md#L2289) names one invariant per rule. The [rule-hygiene audit](https://github.com/m2ux/workflow-server/blob/6355c392/corpus/workflow-design/techniques/audit-rule-hygiene.md#L33) walks `no-rule-protocol-restatement` through `no-one-step-rules` and does not name it.

## Proposal

- **Register the role check.**
  It reads the bundles each role receives, the unconditional prohibitions each role states, and the registered tool surface, then flags an instruction that turns on a call that role is forbidden to make, including an instruction to take a value from the call. A call named only in a conditional clause is not read as prohibited. It registers under the rule ids the [visibility rules](https://github.com/m2ux/workflow-server/issues/939) publish.
- **Register the fallback check.**
  It flags a description of an absent-value fallback whose declaration carries no default, and registers under a rule id the [formal specification](https://github.com/m2ux/workflow-server/issues/937) publishes.
- **Walk the catalogue entry.**
  The rule-hygiene audit walks AP-156. The entry stays silent on a single constraint stated with the failure mode that makes it matter, and on successive paragraphs elaborating one constraint across two cases.
