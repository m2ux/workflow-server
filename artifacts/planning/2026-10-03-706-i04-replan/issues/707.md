## Overview

This epic locks two records with walks: a findings file announced once on the delivered contract, and a review-mode run that records no assumption answer.

## Problem

- **The contract is built from technique declarations.**
  [composeActivityArtifacts](https://github.com/m2ux/workflow-server/blob/ab680d9d/src/tools/workflow-tools.ts#L336-L339) unions `#### artifact` filenames and dedupes them. The calling activity persists the file with `write-artifact`.
- **Review mode gates the batch record.**
  [residual-assumption-interview](https://github.com/m2ux/workflow-server/blob/6355c392/corpus/work-package/routines/residual-assumption-interview.yaml) gates `record-batch` with `is_review_mode != true`.
- **Neither fact has a failing walk.**
  The [review-mode snapshot](https://github.com/m2ux/workflow-server/blob/ab680d9d/tests/e2e/snapshot.test.ts#L139) asserts that create-mode checkpoints stay unpresented. It does not assert that no assumption outcome was recorded.

## Proposal

- **Fail a doubled announcement.**
  An assertion in the all-workflows walk fails a delivered activity whose artifact contract announces the same artifact twice.
- **Fail an unasked answer.**
  An assertion in the snapshot suite's review-mode walk fails any recorded assumption outcome.
