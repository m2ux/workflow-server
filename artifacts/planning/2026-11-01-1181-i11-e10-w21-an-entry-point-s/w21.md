**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

A skill's entry point has a named structure in the shared guidelines, and the shared check measures nothing about it. This task names the entry point's top-level sections as a set and an order, and has the shared check read every `SKILL.md` against that set, so the one file every reader opens first is held to a shape.

## Problem

- **Entry points carry sections no rule names.**
  The gitnexus entry points and `server-in-the-loop/SKILL.md` carry headings such as After Indexing, Troubleshooting, Typical flow and Trees under test. Widening the procedure-file section rule to them reported 21 findings before `SKILL.md` was excluded.
- **The exclusion is stated in the check, not measured.**
  The check passes `SKILL.md` over because the guidelines name a different structure for it. Nothing then reads the entry point against that structure, so the exclusion removes a measurement rather than deferring it.
- **The structure is prose, not a set.**
  The guidelines' SKILL.md structure section describes Opening, Modes, Rules, Dependencies and Commands one by one. It names no order, places Conventions nowhere although the Commands guideline sends skill-wide conventions to the entry point, and lists Commands beside sections although the entry point holds no command.
- **An entry point decides whether a skill loads at all.**
  Its description and its Modes list are what a session reads before anything else, and a departure there costs every mode.

## Proposal

The shared check already measures a procedure file's top-level sections against a named set and order. The entry point is the one file it passes over.

- **State the set as a set.**
  - The guidelines' SKILL.md structure opens with its top-level sections: Modes, Rules, Conventions and Dependencies, in that order, each optional.
  - The Opening stands under the title, ahead of them; anything else is a sub-section under one of them.
  - Conventions holds the skill-wide prerequisites the Commands guideline places in the entry point. Commands is a rule about content: the entry point takes no Commands section.
- **Measure the entry point against it.**
  - `check_skill_files.py` names the set as `ENTRY_SECTIONS` and reads every `SKILL.md` against it, whatever the file carries and whatever a skill's `structure.json` declares.
  - One function, `sections_against`, reports a section outside a set, a section out of its order and a required section missing. The procedure-file and declared-contract measurement and the entry-point measurement both call it, so the three finding kinds read alike.
