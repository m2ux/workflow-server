**Component:** workspace:skills/work-planner/artifacts/pull-request.md

## Overview

Sync reads every pull request the plan links, whatever its title, so a task pull request raised before titles carried the initiative prefix still settles its row.

## Problem

- **The fetch filters by title.**
  Read Initiative Pull Requests and the repository-wide fetches keep only pull requests whose titles start with the initiative prefix.
- **Older links go unread.**
  Rows of the skill's own initiative link task pull requests raised before that prefix was required, and those went unresolved until fetched by hand.

## Proposal

A planner syncs an initiative whose early rows link pull requests titled without the prefix.

- **Links select the records.**
  The fetch takes each pull request a Work Breakdown row links or a Development link of the plan's issues names, in whichever repository it lives.
- **One command adds them.**
  A Fetch Linked Pull Requests command runs `scripts/linked-pull-requests.py` over the title-matched collection and the plan's issues: issue files for an initiative, the board's items for a board. It reads each issue's Development field from the issue end, collects the pull requests the rows' id cells link, and appends each one the collection lacks, read by REST. An unreadable relation or pull request appends nothing and exits 1.
- **Both fetch operations run it.**
  Read Initiative Pull Requests runs it with the initiative, epic and task issues; Fetch All Delivery Pull Requests runs it with the board items Read Board State returned. Their callers pass those issues, and Delivery Evidence and Sync drop the hand fetch of linked pull requests absent from the list.
- **Title matching stays where it is the only signal.**
  A pull request no row or Development link names is still found by the epic its title names, so an unlinked delivery is reported.
