## Problem

`belongs()` in `sync.py` read any task branch's last hyphenated word as the long-lived branch it belongs to, ahead of the target. [Task Branches](https://github.com/m2ux/workflow-server/blob/workspace/skills/work-planner/artifacts/delivery-branches.md#task-branches) reserves that word for a unit changing several long-lived branches; a single-branch unit's slug comes from its Description and may end in a branch name. A pull request from `i01/e00/w04-tidy-workspace`, whose work item names `main:src/...`, into a stacked branch was reported as belonging in `i01/e00/workspace`, a single base, and Sync mode retargeted it there without reading the Component.

## Proposal

A unit changing several long-lived branches opens one task branch per base, each the unit's branch with that base's long-lived branch as its last slug word. Another task branch of the epic sharing the stem is the evidence the sync holds of such a unit.

- **Slug word.** `belongs()` names the long-lived branch a task branch's last slug word names only where another pull request naming the epic comes from a branch with the same stem ending in another long-lived branch. Otherwise the target names the branch, else every epic base is named as one of them.
- **Target handler.** Sync mode retargets an open pull request to the epic base of the long-lived branch its work item's Component names, which confirms the base the finding names or chooses among several. A multi-branch unit's task branch goes to the base its last slug word names.
- **Prose.** The `sync.py` docstring and epic.md's Target row state the slug-word condition; sync-mode.md's Target handler states the Component confirmation.
