## Overview

Hot-fix readiness confirms draft restoration.

## Problem

A post-ready validation failure can leave a ready pull request while the repair result describes it as draft.

## Proposal

Select the existing draft command on failed readiness for an open ready PR, read current metadata to confirm the write, and preserve any restoration discrepancy before repair or blocked return.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Refresh integrated source and trace current callers, result fields, guards and failure/success continuations against pinned review evidence. |
| Plan | Confirm the owning capability and observable continuation with the recovery design, retaining existing authorization and command contracts. |
| Implementation | Apply the scoped component design with linked capability calls, command-owned I/O and explicit selected continuation. |
| Review | Check ownership, DRY/SOLID, exact current evidence and terminal branches, including discrepancies and no unsupported state assertions. |
| Test | Ordered initial/post-ready failure, changed-head, restoration-refusal, readback-disagreement and success fixtures; no merge/In Review after failure. Run document/contract checks, installed model and full required fixing-PR suites; retain bounded fresh-context route evidence. |
