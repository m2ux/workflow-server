**Component:** workspace:skills/workflow-canon/test/audit_fixtures.py

## Overview

The Workflow Canon audit tests need an engine checkout, read from `CANON_TEST_ENGINE`, that nothing in the skill tells a contributor how to supply. A session without it sees 38 of the suite's 76 tests fail. This task names the prerequisite where the skill lists its dependencies and makes an unset variable skip the tests that need it, so a run from a fresh checkout separates an environment gap from a defect.

## Problem

- **Half the suite fails on a missing environment variable.**
  [`AuditFixture.setUp`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/workflow-canon/test/audit_fixtures.py#L22-L24) fails the test outright when `CANON_TEST_ENGINE` is unset: `CANON_TEST_ENGINE must name an engine with its installed yaml package`. 38 of the suite's 76 tests fail that way at `ba441c2b8`.
- **Nothing states what the variable should name.**
  The message asks for "an engine with its installed yaml package". The skill's [SKILL.md](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/workflow-canon/SKILL.md#dependencies) Dependencies name the paired YAML parser but not the variable, and [Run Audit Script Tests](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/workflow-canon/references/change-surface.md#run-audit-script-tests) passes `<engine-root>` without saying which checkout satisfies it or how to prepare one.
- **A failure reads as a regression.**
  The failures surface as 38 red tests rather than as skips, so a contributor running the suite after an unrelated change cannot tell an environment gap from a break they caused.

## Proposal

A contributor clones the workspace and runs the Workflow Canon tests without an engine checkout to hand.

- **The suite states its prerequisite.**
  SKILL.md's Paired YAML parser dependency names `CANON_TEST_ENGINE` and what it must point at: the root of an engine checkout whose dependencies are installed, so `node_modules/yaml` resolves. The prerequisite is readable before the suite is run.
- **An unmet prerequisite skips rather than fails.**
  `AuditFixture.setUp` raises `unittest.SkipTest` when the variable is unset, with a message naming the variable and what it must point at. Run Audit Script Tests states that each engine-bound test skips while it is unset. A set variable keeps its present behaviour: a wrong path still fails, since it is a misconfiguration rather than an absent prerequisite.
- **The skip is itself tested.**
  A unit test runs an `AuditFixture` subclass with the variable removed and asserts one skip and no failure.
