**Component:** skills/work-planner/scripts

## Overview

An unread relation named as missing evidence. Each Development capture, from either end, names every relation the tracker did not return whole and exits nonzero, so a caller never reads an unread relation as an empty one.

## Problem

The shared reader treats only a missing subject node as unread. A node returned beside an error that names it, a linked node returned as null, a page that reports more links without a cursor to read them, and an error carrying no path all pass as a complete relation. The capture then writes a link set short of the links it could not read, and an empty array in it reads as a checked, empty field.

## Proposal

The capture reads each subject's relation page by page through `development.py`, which both link scripts share. A relation is read only when every page of it arrives whole.

- **A subject is unreadable when the tracker:**
  - returns no node for it, on any page;
  - names it, or anything beneath it, in an error, even beside returned data;
  - reports an error with no path, or one naming only its repository, which reaches every subject that error covers;
  - returns the relation, its nodes or its page information as null, or a linked node as null;
  - reports a further page without the cursor that reads it.
- **An unreadable subject contributes no links.** Its pages already read are dropped, its reason is printed with its repository and number, and the capture writes nothing and exits 1.
- **An empty relation read whole stays an empty array**, so a checked, empty field is still told apart from an unread one.
- **The operations treat an unreadable relation as a blocker.** Capture Pull Request Links, Capture Issue Links and the operations that call them stop on incomplete evidence rather than continue with a partial snapshot.
