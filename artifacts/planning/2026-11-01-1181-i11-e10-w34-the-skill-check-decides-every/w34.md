## Overview

The shared skill-file check decides each case the [agent review of #1555](https://github.com/m2ux/workflow-server/blob/engineering/artifacts/planning/2026-11-01-1181-i11-e10-epic-review/review-1555.json) raised against it (findings 1-5), so E10's handoff carries no known escape or false report in the check.

## Problem

The interface check misses Projects (classic) REST routes rooted at `projects/` or `user/projects`, and the GraphQL `project(number:)` field, yet reports prose such as "several projects (repositories)" and a function named `projects`. A bulleted `**REST gap:**` line goes unread, and an unbolded mode bullet is never checked for its trigger phrase. Several branches — the column route, the gap's spec span, fenced-only GraphQL, the multi-word mode join, the heading exclusion in the wrap check, fence-language case, the entry point's refusal of Commands, and the mood group's parent — have no test that fails when they are removed.

## Proposal

A skill author writes a GitHub call, a REST gap or a mode bullet in any form the guidelines allow, and the check reports exactly the departures.

- `CLASSIC` matches the classic REST routes by their root (`projects/<id|columns|cards|placeholder>`, `user/projects`, repository, organization and user `projects`) and the GraphQL `project`/`projects` fields only when called with arguments. A segment beneath another path, a placeholder included, names no route, so board web links and local folders stay clear.
- `REST_GAP` accepts the label opening a line or a bullet.
- `MODE` accepts a mode's link bold or plain.
- A `ReviewedCheckCases` test class states each case, and the mood test that compared levels rather than parents is named for what it observes.
