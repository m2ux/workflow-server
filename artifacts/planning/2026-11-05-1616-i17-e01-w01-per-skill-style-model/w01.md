**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared checker validates each declared skill model, including heading-based procedures and HTML command invocations. Specimen skills prove the target presentation while installed skill declarations retain their selected models.

## Problem

Entry-point sections are fixed in the checker, and its procedure and command readers recognize numbered lists and fenced command specifications. They cannot enforce the target model's heading steps, linked contracts and inline HTML invocations as a declaration selected by a skill.

## Proposal

The scene is the current shared checker, its structure resolver, Markdown parser, citation relations, interface checks and seeded-skill test suite.

- Extend each declared structure entry with typed options for heading steps, inline HTML commands, linked field contracts, preamble links and operation-call routing. A file-name selector gives an entry point its own declared section set.
- Keep parsing, structural checks, contract checks and invocation checks in focused helpers. Reuse the existing resolution, finding registry, source model and citation relations.
- Recognize balanced HTML invocation wrappers without altering their payload. Command payload headings and shell text do not become Markdown structure; explicitly bold linked arguments retain actual link checks.
- Validate new-model specimens against accepted and rejected inputs, including misplaced/fenced commands, malformed model declarations, sequence/detail errors, unresolved or non-contract argument links, missing preambles and call routing.
- Installed declarations and other skill files retain their bytes. The current whole-tree baseline is recorded separately from the touched skill's zero-finding baseline.
