## Overview

An epic's integration pull request never holds a task issue. `board.py` reads a task's open pull request through `delivers()`, which excludes the pull request merging the epic base into its long-lived branch; a test observes it.

## Problem

The merge of `workspace` into `i11/e09/workspace` reads a task issue's open pull request through `delivers()`. No test fixture gives a task pull request a head and base, so nothing observes that an integration pull request linking a task issue leaves the task out of In Progress.

## Proposal

- **Fixture.**
  `task_pair` takes the pull request's base and head.
- **Test.**
  An integration pull request (`i01/e00/workspace` into `workspace`), draft or ready, linking the task issue moves no task, and the inactive epic returns to Backlog.
