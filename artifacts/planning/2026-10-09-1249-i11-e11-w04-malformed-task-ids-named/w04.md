# W04 — Malformed Task Ids Named

## Overview

Every task id a Work Breakdown row's Task cell carries is held to the form a task id takes, and one that departs from it is reported with the epic and the id as written.

## Problem

- **An extra digit becomes a different row.**
  The head of the cell is matched as a W and two digits, so a cell carrying a third digit resolves to the row its first three characters spell. That row's dependencies, Joins and coverage are then read onto a row the author did not write.
- **Too few digits leaves no row at all.**
  A cell holding a W and one digit matches nothing, so the row is skipped and contributes no node and no edge — the fault the preceding row of this epic was raised to close, reached by a different route.
- **Neither case is reported.**
  The run prints no problem for either, so the column that holds a row's identity is the one column where a typo passes without a word.

## Proposal

The Task cell is the row's identity, so every id it carries is checked against the form an identity takes before any of it is believed.

- **One form for a task id.**
  A W and exactly two digits. Every id-shaped token the cell carries is held to it.
- **A departure is reported, not guessed at.**
  The run names the epic and the id as written. A malformed head leaves the row out of the graph, since nothing in the cell says which row it is; a malformed id after a sound head leaves the row in place and reports the id.
- **A cell holding no id-shaped token is not a task row.**
  It is skipped without a report, which is what a prose row in another table needs.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The id-shaped spellings a Task cell can hold, and which of them the head match believes today. |
| Implementation | Every id-shaped token in the cell collected and checked against the form, with the head deciding whether the row survives. |
| Documentation | The module docstring's statement of the form a task id takes and what the run reports when one departs from it. |
| Test | Unit tests in `test/test_deps.py`: a cell whose head carries an extra digit is reported and yields no row; a cell whose later id carries too few digits is reported and keeps its row; a prose cell is skipped in silence.
