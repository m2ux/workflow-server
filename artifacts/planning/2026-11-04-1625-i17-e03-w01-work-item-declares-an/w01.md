**Component:** workspace:skills/work-planner/artifacts/work-item.md

## Overview

A work item may declare the lane that delivers it, so two sessions delivering one board can tell their rows apart. The declaration is the source every lane reader takes: the delivery survey, the dependency check and the board queue.

## Problem

- **A work item declares one thing.**
  [Component](https://github.com/m2ux/workflow-server/blob/b2844c821ce800ed3d12735bdf339049594e5ec5/skills/work-planner/artifacts/work-item.md#component) is the only declaration line ahead of the first heading, so nothing in a row's plan says which session delivers it.
- **Projects are inventing the line.**
  prosiform's I10 work items carry a `**Lane:** <n>` line under Component, which no reader of the skill knows.

## Proposal

A planner splits one initiative's rows between two sessions and writes each row's lane where its component is declared.

- **An optional Lane declaration.**
  A second declaration line, `**Lane:** <id>`, sits beside Component ahead of the first heading. A work item without it is unlaned.
- **The id is an opaque, board-wide index.**
  It says the rows differ in who delivers them, never why, and lane 2 is one lane across the theme board. The work item states no reason for its lane.
- **Populate Work Item writes a supplied lane.**
  The operation takes an optional lane input and writes the line only when one is supplied.
- **The template and Sections carry it.**
  The template shows the optional line, and Sections names it beside Component.
