**Component:** workspace:skills/work-planner/scripts/kinds.py

## Overview

One script registry maps each kind of work to its module, so general scripts reach kind logic without importing a kind directly.

## Problem

General scripts import `hotfix` and test `is_hotfix` or `hotfix_tag` inline; no registry exists, so every caller keeps its own kind switch.

## Proposal

Each general script currently decides for itself whether an item is a hot-fix. Create `scripts/kinds.py`: the registered kind modules, the kind interface they implement, and the lookup that selects an item's kind from its title. It lands with the hot-fix module's conformance in one pull request.
