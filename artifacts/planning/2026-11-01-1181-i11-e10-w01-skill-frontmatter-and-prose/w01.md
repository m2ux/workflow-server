**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check decides two rules the shared guidelines state and nothing checks: a description carries a trigger phrase for each mode, and each paragraph or list item is one line. A skill that departs from either now fails the check rather than waiting on a reader to notice.

## Problem

- **Mode triggers.**
  [`guidelines.md`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/guidelines.md#frontmatter) requires a trigger phrase for each mode, and [`check_skill_files.py`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/scripts/check_skill_files.py) never reads the description. At `ba441c2b8` the work-planner description carries no phrase for its Understand mode.
- **One line per item.**
  The Layout rule forbids hard-wrapping, and the check reads no line against the next. At `ba441c2b8` seven items in work-planner and gitnexus-guide continue onto a second line, and each renders as one paragraph the author wrote as two.

## Proposal

The shared check already reads each skill's markdown with its fences and frontmatter resolved; both rules read from that scan.

- **Mode without a trigger phrase.**
  An entry point's modes are the bold linked names under its Modes section. The description, folded lines joined, carries a mode where a word opens with the mode's name, a final "e" dropped, so "revising" carries Revise. The guidelines state that form.
- **Hard-wrapped line.**
  A line a following non-blank line continues, where that line opens no new block (list item, heading, table row, quote, fence, rule or HTML), is reported once per item. A bold label standing alone takes its body on the next line, the one continuation the layout allows. Fences and frontmatter are not prose.
- **Bounded prose.**
  With every paragraph one line, the blank line between paragraphs continues a prose run, so the eight-line limit counts the paragraphs under one heading together.
- **Corpus.**
  Each finding the new checks report in the repository's skills is fixed in the same change, so every skill the change touches checks clean of them.
