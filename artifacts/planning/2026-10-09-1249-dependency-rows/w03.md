# W03 — Dependency Rows Read by Task Id

## Overview

The dependency check reads each Work Breakdown row by the task id at the head of its Task cell, so a row linking several pull requests takes part in the graph it belongs to, and a cell whose links name different ids is reported as a defect in the table.

## Problem

- **A delivered row often links two pull requests.**
  The Work Breakdown Guide states that a further pull request is linked after the ones already there, so a unit spanning the server and corpus trees writes its id twice, once per link. `deps.py` documents that spelling in its own header example.
- **The parser requires the whole cell to be one id.**
  `cells` replaces each markdown link with its text, so a doubly linked cell becomes the id, a comma, and the id again. The row filter then tests `re.fullmatch(r'W\d\d', wid)` against the whole cell and skips the row.
- **A skipped row is invisible to every later pass.** It is absent from `rows`, so:
  - dependencies naming it are reported unknown;
  - Joins entries naming it are reported unknown;
  - the levels, the longest chains and the whole-epic report are computed over a table with holes in it.
- **The false reports are not rare.**
  A run over I04's fourteen epics reported eight problems, every one of them this, spread over six epics: two Joins entries and six dependencies, each naming a row that exists and is delivered. A run over I00, whose rows carry one link apiece, reported none.

## Proposal

The Task cell holds the row's identity and its delivery links together, so the parser takes the identity from the head of the cell and checks the rest of the cell against it.

- **Read the id from the head of the cell.**
  Match a leading `W\d\d` in the Task cell rather than the whole cell, so a cell repeating its id across several links resolves to that id. A cell holding no leading id is not a task row and is skipped as it is today.
- **Report a cell whose links disagree.**
  Every `W\d\d` the cell carries is compared with the head id. A cell naming a second, different id is a problem the run reports, naming the epic, the head id and the id that disagrees.
- **Hold the test to the spelling the guide defines.**
  A fixture carries the repeated-id form, the single-link form and the bare id, and a separate fixture carries a cell naming two different ids.
