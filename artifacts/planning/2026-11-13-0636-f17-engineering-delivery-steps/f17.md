## Overview

A unit whose rows change the planning-records branch, `engineering`, pushes those files directly, as rules.md's Planning-records branch rule states. This hot-fix gives Run Delivery Session the step that pushes them and Sync Epic the scripted commit link a unit changing only that branch finishes with.

## Problem

Run Delivery Session pushes no `engineering` file, every unit opens and merges a pull request, and Sync Epic's `--link` takes only pull request numbers, so a unit changing only `engineering` cannot finish its delivery.

## Proposal

- **Step 6.** Once the unit's tests pass, the session commits each declared `engineering` file in the engineering worktree and pushes it; a unit changing only that branch runs Sync Epic with the project checkout, the fetched epic bases and the pushed commit, saves the body, follows Task Merge with the commit as its delivery, and continues to Arising Issues.
- **sync.py --link.** `W01=<full sha>` links `[W01](<repo>/commit/<sha>)` beside any pull request link on the row, idempotently; a short SHA is refused. `RECORDS_BRANCH` has its one home in sync.py.
- **Delivered.** A commit delivers a row that links no pull request; beside a pull request, the row waits for that pull request to merge, in sync.py and board.py alike.
- **Task Delivery.** One example and the `--link` map description name the commit form.
