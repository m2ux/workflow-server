## Overview

Plan Mode publishes epics and their parent rows with confirmed tracker identities.

## Problem

Existing-initiative planning reaches saved-context validation without an explicit epic and parent-row publication sequence.

## Proposal

Select parent creation only for a new initiative. Save new epics in dependency order for either parent path, replace temporary links with confirmed issue identities, save the parent and refresh all saved context before validation and preparation. Retain existing issue identities on updates; use the owning issue save/readback capabilities without duplicating their contracts.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Trace current Plan Mode publication, issue identity/readback capabilities and the new/existing parent branches at the integrated revision. |
| Plan | Define one publication sequence with conditional parent creation, confirmed epic identities, parent save, fresh validation and terminal save failures. |
| Implementation | Express the sequence in Plan Mode and extend its existing consumer tests within this component. |
| Review | Confirm progressive context, DRY/SOLID ownership, stable existing identities and no placeholder or unsaved context reaching delivery preparation. |
| Test | Ordered offline scenarios cover an existing parent with one/two dependent new epics, a new parent, an update using an existing epic identity, failed epic save, failed parent save and disagreeing readback. Observe calls/identities and terminal states; do not rely on keyword presence or mutate a live tracker. Map results to AC1–AC3 and run required planner/model checks. |
