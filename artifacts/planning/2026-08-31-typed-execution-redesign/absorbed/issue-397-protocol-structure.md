## Summary

A technique file tells an agent how to perform one operation, and the steps live in the file's Protocol section. Authors already put two kinds of structure in that section that the server cannot see: **alternatives** — one operation with several mutually exclusive ways to run it — and **delegation** — a step that tells the agent to apply another technique, with arguments. Today the server reads both as ordinary prose: alternatives get smuggled into the Rules section, and an inline call resolves to nothing — the agent receives a raw file path and improvises.

This epic gives both a structural home. **Protocol variants**: a technique file may carry several named sub-protocols, and the caller says which one it wants. **Technique folds**: an inline reference to another technique resolves, gets its arguments checked against what the called technique declares, and the called technique's body is delivered alongside the caller. And because alternatives appear one level up too — an activity picking between several techniques on the value of one variable — the design canon gains the test that no guard's unit of comparison currently spans: whether the arms of such a set still agree where a common consumer reads across them.

Delegation has a harder case inside it. Some steps name the technique to apply with a variable rather than a link, so the callee has no name until an agent reads it. Protocol variants answer that for the family it most affects, and for the rest the guard's job is to report the site as beyond its reach instead of passing over it — checking an argument against a callee nobody can identify is not on the table.

## The gaps

**Alternatives have no home.** The current workaround stores each alternative as a named Rules section that a resolver picks at runtime, and the inputs those procedures use are declared nowhere. The corpus is already shaped for the fix: of 554 technique files, 300 use numbered phases and 161 use flat step lists (both keep their meaning unchanged), zero files mix the two shapes, and exactly one file needs refiling.

**Alternatives are never compared with each other.** The same shape appears one level up, where an activity picks between several techniques at runtime: a step applies one technique when a variable holds one value, a neighbouring step applies a different one when it holds another. Each of those steps declares what it needs and produces, and each is checked on its own, but nothing ever puts them side by side, so one can require an input the others do not or produce an output the others do not and every guard stays quiet — no guard's unit of comparison spans two of them. Three such sets exist in the corpus. The interesting one has four arms, picking between a structural run, a single-lens run, a portfolio run and a behavioural run on the value of one mode variable; across those arms there are five distinct declared inputs and eight distinct declared outputs, and not one of either is common to all four. That is not the defect — a portfolio run really does produce different artifacts from a single-lens run. The defect is at the seam: after the four alternatives, an ungated step writes an accumulator variable whose contents are described in a sentence, and the next activity reads that one variable uniformly whichever arm ran. Eight declared output ids on one side, a prose description on the other. The catalogue also creates this exposure for itself, because one existing entry prescribes exactly this construction as its own remedy — split an operation whose artifact name is selected by a mode input into one operation per mode, gated at the bind sites — after which nothing checks the arms still agree where they have to.

**Inline calls evaporate.** Nothing resolves an inline reference, nothing checks its arguments, and the called technique never arrives. The August survey found 118 call edges between techniques — 99 of them (84%) invisible to the activity layer — and 56 call sites that omit at least one required input of the technique they call. Neither figure reproduces, because neither was recorded with the basis it was measured on: re-derived at the delivered corpus commit under the published counting grammar, the same surface measures 198 call sites over 101 calling files reaching 73 distinct callees, and 230 genuinely unbound arguments across 111 sites. Both readings are kept with their bases rather than one replacing the other, and the discrepancy is the reason acceptance now turns on a published grammar instead of on a count. Every link target exists; the rot is entirely in the contracts. About ten hand-maintained entries in the server's core-operations list exist only to paper over the missing delivery.

**Some calls name their callee with a value, so the survey could not see them either.** A step can say to apply a technique whose name is not written down anywhere — it arrives as the value of a variable, resolved when the agent reads it. The clearest case is the harness group: `Apply {harness_technique}'s {harness_operation} Rules section` picks the file from one variable and the section inside it from another, at three call sites. The dispatch stub does the same with `Apply {agent_technique}`, and one analysis loop with `invoke the bound {analyse_technique}`. The 118-edge inventory counted the link *to* the resolver, which exists, and not the dereference that follows it, which has no link to count — so these sites are absent from the survey rather than dispositioned in it, and no static check reaches them by construction.

Where the value comes from a set the corpus enumerates, closure over that set is the answer and it works: a guard added during the batched-dispatch work proves the harness resolution map's rows, the adapter files and the server's core-operations list describe one set, and it caught a partial adapter, a renamed slice, a map row naming no file, and a deleted slice — four mutations that had passed the whole suite. W1 replaces that prose-held obligation with a declared contract per variant, which is the better answer for this family. What no mechanism covers is a call site whose callee cannot be named at all until runtime, and the honest minimum there is that the scan reports it rather than skipping it silently — a call the guard cannot check must read as unmeasured, never as clean. Measurements and the reasoning are in the [review record](https://github.com/m2ux/workflow-server/tree/engineering/artifacts/planning/2026-08-04-solid-affinity).

## The work

**W1 — Protocol variants.** Shape decides meaning: a flat list is one protocol, numbered sub-sections are phases, unnumbered sub-sections are named variants, and a mix fails to load with a clear error. Selection is mandatory and fail-closed in both directions; step bindings gain a selector; guards verify every selector and each variant's contract. The Initial/Final wrap machinery is removed in the same change — zero containers author such blocks — with its two titles reserved as parse errors.

**W2 — Check the calls we already write.** A guard resolves every inline reference through the same loader the server uses and checks arguments against the callee's declared inputs, classifying the 56 argument-omitting sites into name-match-satisfied versus genuinely unbound. Its grammar is a shared module that fold delivery later imports. Unambiguous defects fail hard from day one — including the three rule-addressed-as-operation sites, repaired in the same change — while contract classes are delta-gated, failing only the change that introduces new drift. The same scan also resolves the neighbouring reference kinds that have no static check today: dotted rule citations, bare resource links (the anchor checker only covers links carrying a heading anchor), and the placeholder tokens inside declared artifact filenames. The guard's mechanical bins seed the edge-disposition worklist. Call sites whose callee is a variable are enumerated in the same pass and reported as beyond static reach rather than passed over, so the count is visible and a new one cannot appear unnoticed; where such a site draws from an enumerable set, the disposition is a closure check over that set rather than an argument check at the call. The anchored half of this same surface belongs to the section-delivery epic: its first work item (#398 W1) builds the one slug computation the anchor guard and the runtime share and closes that guard's blind spots. This scan takes the references that carry no anchor, and it must not grow a second slugger — whichever work item lands second builds on the first's shared module rather than beside it.

**W3a — Deliver the mentioned techniques.** The server already sends along the templates and reference documents a technique mentions; this work item points the same pipeline at technique references. Referenced bodies arrive deduplicated within the delivery budget, followed transitively and tolerant of a reference that leads back somewhere the walk has already been rather than failing the load on one, composed under the home-ancestry rule (W0, the subsumed #405, lands first). Conduct-layer targets and variant-carrying callees stay step-bound, their names arriving as plain references. The core-operations workarounds retire, and the canon and specification amend here — at this point references resolve, conform, and deliver. Delivered reference text is rewritten to the canonical group-and-operation display form on the way out, and the token benchmark gains a referenced-technique scenario so the delivery-cost comparison exists at review time. Call sites keep prose semantics; the reading material just arrives.

**W3b — Verified call joints (dormant, evidence-gated).** Built only if post-delivery evidence shows runtime misbinding the static check cannot catch, and then only for **operation-grade** callees — one flat protocol, no variants, no document outputs; a shape grade within the technique format, already the shape of 161 files. Ships as marked blocks with checked seams, the reserved variant-selection argument, and flag-gated activation. Larger multi-phase techniques compose at activities, where the workflow can see them.

**W4 — One catalogue entry for a variant set whose arms have drifted apart.** Named for the smell, not for the principle behind it: entry names in this catalogue identify what has gone wrong, and an entry named after a design axis hands an auditor a framework to re-derive rather than a test to run. It states the seam, not the arms — requiring the alternatives to declare the same inputs and outputs would be wrong, and this folder's own review already ruled that out for the four-arm set, whose members differ by role deliberately. What is checkable without that error is narrower: where a common consumer reads across all the arms, each arm's contribution to what that consumer reads must be traceable to a declared output rather than to a sentence. Three things then become flaggable — a required input the bind site supplies on one arm only, an output a sibling omits where a common consumer reads them uniformly, and an arm that writes the discriminator a sibling's gate reads. The scan is bounded inside Detect at one bind site plus the consumer that reads across it; this would be the catalogue's first entry comparing two files against each other, and an unbounded version is unapplicable. Where W1 has landed, the entry keys on the declared-variant construct rather than growing its own way to find sibling arms. Its relationship to the entry that prescribes splitting by mode is stated in one direction only, so following that entry's Fix leads here rather than the two overlapping.

**Migration batches.** Each admitted call site is dispositioned — migrate, fold, documentation-only, or deduplicate (19 edges are also step-bound) — under the visibility rule, worked off the worklist, with call forms normalised per batch.

## The rule that sorts the edges

A technique may call another technique when the result of the call stays inside the calling technique's own work. The moment the workflow itself acts on the outcome — a gate reads it, a checkpoint presents it, a loop retries it, a dispatch depends on it — the call must be an activity step. This is the **visibility rule**. The twenty-five supporting decisions — delivery form, binding conventions, reach, telemetry, rollout sequencing — are recorded with rationale and alternatives in the [doctrine decision record](https://github.com/m2ux/workflow-server/blob/engineering/artifacts/planning/2026-08-02-protocol-structure-consolidation/doctrine-decision.md).

## Repeated references are tolerated, not rejected

When one technique's instructions name another technique, and following those names eventually leads back somewhere the walk has already been, the walk carries on. It does not stop, and it does not treat the repetition as a fault. Each body is handed over the first time it is reached, and a second route to the same body adds nothing, so the walk records the repeat and continues.

The reason is categorical rather than a judgement about how much repetition the corpus happens to contain. Handing over a body is a question of what can be reached, not a calculation whose inputs have to settle: no technique in a closure computes a value another technique in that closure then consumes. A body is therefore complete the first time it arrives, and would be identical the second time. Rejecting the repeat would buy nothing and would refuse work that is correctly written.

The corpus makes the point concretely. The index-freshness check and the indexing operation each name the other, and the freshness check also names itself, retrying after the indexing it triggered. All three are correct as authored, and both arms are guarded in prose — one optional, one branch-conditional — which is why the corpus loads today and why the repetition is invisible until something actually follows the names. A policy that failed the load on repetition would reject all three.

Measured over the delivered corpus, walking every one of 572 technique files as a starting point: 230 bodies handed over, 110 edges reaching a body already handed over, 9 of those naming the technique they sit in, and 0 references resolving to no file. Every walk terminates.

## Why now is cheap

Both surveys are fresh against the same corpus head and reproducible by script; variant validation lands with no migration (zero mixed shapes); roughly 80% of the delivery machinery already exists in the server, pointed at resources; and the doctrine was settled with the inventory in hand, so the canon amendment lands in one pass.

W4 is cheap for the same reason and one more: the three variant sets are already enumerated and their contracts tabulated, so the entry is drafted against real content rather than an invented example, and both mistakes worth making have already been made and recorded — a first pass keyed on steps sharing a gate variable returned 67 sets, nearly all of them one loop advancing, and a tightened pass requiring one value per arm dropped the four-arm set entirely because one of its arms tests the discriminator against two values. Whoever writes the Detect starts from both.

## Acceptance criteria

- [ ] W1: the loader parses the three Protocol shapes and rejects mixes loudly; selection is fail-closed both ways; the wrap machinery is removed with its titles reserved as parse errors; non-variant techniques are wire-identical to today.
- [ ] W2: every call site whose callee is named by a value is enumerated and reported as outside the static check, and the total is asserted, so a new one fails the guard rather than joining an unmeasured remainder. The count is published in both planes it can occur in, because one of them is empty and reading the zero alone would mislead. Where a call names its destination through a placeholder the author left unwritten, the corpus has none: 0. Where a callee is chosen in the activity rather than in the instructions — supplied as the value of a step's input, or drawn from a table mapping a setting to the file serving it — the counts are 8 and 4, twelve together. No widening of the word list or the link rules reaches those twelve, because they are addressed in a different plane from a link in prose.
- [ ] W2: ten counting decisions are published with the answer each is fixed to, and each is pinned by a test corpus built so the count under the published answer differs from the count under the alternative — so changing a decision changes a fixture rather than only a number. Coverage is published beside the total, because the two are different facts: the published list of five invoking words admits 198 of 254 resolvable references, 78%, and the remainder are real callers the grammar does not admit. A clean report over a region never examined must not read as a report that examined it, and a decision to retire an operation needs someone to read the corpus rather than this number. The guard classifies argument conformance, hard-fails the unambiguous classes with the known sites repaired, and its grammar lives in the shared module; dotted rule citations, bare resource links, and artifact-name tokens resolve under the same scan.
- [ ] W3a: referenced bodies arrive deduplicated, transitively, under home ancestry, with a delivery event per body and the stealth reachable-text scan running over the delivered closure; delivered references render in the canonical display form; the token benchmark carries a referenced-technique scenario; the core-operations workarounds are removed; the canon, construct inventory, and addressing specification say what the loader does.
- [ ] W3b (evidence-gated): checked seams for operation-grade callees behind a flag, gated on the executed worklist and green guards; the evidence case is written down before anything is built.
- [ ] W4: the catalogue carries one appended entry whose Detect names the variant-set shape, keys on the seam between the arms and their common consumer, and bounds its own scan to one bind site; it fires on the four-arm analysis set as the corpus stands and stays silent on arms whose outputs are read only by their own downstream path; it states why it does not require the arms to match, so a later reader does not widen it into the sameness check that was ruled out; and its relationship to the split-by-mode entry is stated in one direction only.
- [ ] Every edge is dispositioned on the worklist, and the corpus reproduces zero regressions: 554 files load with unchanged meaning; the one nonconforming section is refiled.

## Non-goals

- No server-side execution of called techniques — this is composition and delivery only; the agent still does the work.
- No second orchestration vocabulary — multi-unit coordination stays with the activity-level patterns owned by the shared-homes epic.
- No resource-link behavior changes beyond the one misclassification bug fix.
- **No guard behind W4, in this epic.** A narrower version of that check lands red on the corpus as it stands, which makes it canon work before it can be mechanical work. The same reasoning holds the rule-versus-procedure guard out of #436.
- **No requirement that a variant set's arms declare the same contract.** Their differences are the point of having arms, and W4 must not be widened into that check.
- **No member-set version of W4.** Comparing the full set of values a discriminator can take against the set of arms that exist needs an enum variable type in the schema; without one, the member set would have to be read out of prose descriptions.
- **No repair of the three live variant sets under W4.** The entry is authored; whether the sets it flags are then fixed is a separate call made against what it reports.

## Amendments

**23 August 2026, from the W0/W2/W3a delivery.** Two positions in this body were contradicted by the delivered work and are corrected above. The cycle policy read that a reference cycle fails the load; the platform tolerates a repeat instead, on categorical grounds set out in its own section. ## A live instance for W2's guard

`update-pr::verify-body` is referenced by a step in `work-package` and is not served by
`get_technique { step_id }`. A step whose technique cannot be loaded cannot be executed as written,
so the worker either skips it or improvises, and nothing in the run says which happened. Under
progressive step-technique load the fetch is the only delivery path for a step outside the eager
bundle, so the failure is silent by construction.

This is the class **W2**'s loader-backed reference guard exists to catch, and it is a ready
regression case: resolve the reference through the same loader the server uses and the mismatch
surfaces at check time rather than at dispatch time.
