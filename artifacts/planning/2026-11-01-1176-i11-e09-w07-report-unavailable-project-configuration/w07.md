**Component:** skills/work-planner/scripts/sync.py

## Overview

Epic sync reports long-lived branch names it cannot read, with the source of each statement it tried, and names the epic checks it therefore did not make. Without that report, a run that read no declaration looks the same as one that read an empty set, and a skipped check reads as a passing one.

## Problem

- **A failed read ends the run.**
  The source-aware reader exits on a revision resolving to no commit and on a missing or empty statement. An epic sync therefore reports nothing else, and a missing statement and a statement that is a directory read alike.
- **A run given no branches is silent about what it skipped.**
  Without `--project`, epic sync skips the epic-base, draft, References and review-link checks and reports only `long-lived branches not given` on a closable epic.
- **One revision per sync.**
  An epic with bases on several long-lived branches is checked against whichever base the caller names, so declarations that disagree across its bases are never compared.

## Proposal

The reader in `sync.py` returns each statement's names, its source (path, commit, repository) and, where the names are unevaluable, why. `--names` and `deliver.py` keep exiting on an unevaluable statement; epic sync reports it and carries on.

- **Source identity.**
  `read_branches` reports an absent statement, a statement that is not a file, one that is not UTF-8 text, an empty statement and a revision resolving to no commit, each with the configuration path, the commit (or the revision, where none resolves) and the repository. No name is derived from branch naming, another revision or project defaults.
- **Every epic base is evaluated.**
  `--revision` repeats, one for each epic base. Each is read at its own commit; revisions resolving to one commit are one source. Agreeing statements give the names, with a `source` line each. Disagreeing statements are each reported `unevaluable` with their source and names, and none is selected.
- **Unmade checks are named.**
  Where the names are unevaluable, or no `--project` is given, epic sync reports an `unevaluable` line for each cause and a `not checked` line for each check that reads the long-lived branches: epic-base pull requests set apart from task deliveries, unmerged epic bases, draft epic bases, review pull request References and review pull request issue links. A complete epic reports `closable: no (long-lived branches unevaluable)`.
- **Callers.**
  Record Epic Delivery, Sync Epic, Sync Mode, Align Mode, Issue Delivery and Task Merge pass the fetched epic bases. Sync Mode's findings carry an Unevaluable entry; Delivery Findings documents the Source, Unevaluable and Not checked lines.
