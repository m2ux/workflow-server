## Overview

The mode family presents ordered heading steps and explicit artifact and procedure calls while preserving its live instructions.

## Problem

Mode steps are numbered list items and their shared context arrives through the entry point. The approved style requires steps with their own headings and an explicit common-context preamble.

## Proposal

The ten mode files coordinate the same user goals through heading steps. Preserve prerequisites, Runs in declarations, every operative condition and child procedure boundary; call artifact operations with Apply and modes, protocols and child procedures with Follow. Revise commands use the approved HTML presentation and linked arguments. Necessary consuming links and test readers follow the source structure.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Capture the baseline, inventory operative instructions and command specimens, and inspect pinned style references as presentation only. |
| Plan | Map every mode step to a heading and every call to its owning operation; preserve child procedures and literal syntax. |
| Implementation | Convert the ten mode files, inline owned commands at their calling steps, and update necessary consuming links and source readers. |
| Review | Review source accounting, common-context paths, DRY and SOLID ownership, exact literals and the absence of unrelated changes; conduct repeated independent fresh-context disclosure walks when capacity permits. |
| Test | Require zero Work Planner Check Skill Files findings, strict temporary proposed-model checks over all ten modes, the complete Work Planner and shared suites, preservation-ledger verification, and disclosure evidence distinct from workflow execution. |
