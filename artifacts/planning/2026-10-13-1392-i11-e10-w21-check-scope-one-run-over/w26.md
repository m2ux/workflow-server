**Component:** skills/scripts/check_skill_files.py

## Overview

Final verification runs the shared skill-file check over every repository skill after the epic's checker, instruction and cleanup changes land on the epic base. Completion requires no findings at the recorded revision.

## Problem

- **A partial scan cannot establish whole-repository conformance.**
  Excluded skills and remembered findings leave the acceptance criterion unverified.
- **A pass can precede its final inputs.**
  Later checker or instruction edits invalidate a run against an earlier revision.

## Proposal

- **Every skill is included.**
  Enumerate the repository's complete skill directory set and run the shared check over that set. Any finding prevents completion; exclusions, suppressions and accepted-failure baselines cannot satisfy AC27.
- **The run measures the settled revision.**
  Wait for every prerequisite in the epic row to land, then record the commit, command, enumerated skill set, exit status and complete output. Changes to measured inputs require a fresh run.
- **Cleanup has an implementation owner.**
  The prerequisite tasks implement their fixes. This task verifies the combined result; a newly discovered defect returns to its owning change, followed by a fresh final run.

### File-change declaration

The delivery change is bounded by these paths (directory and `**` entries include their descendants):

- `skills/scripts/check_skill_files.py`
- `skills/**`

Tests, command definitions, callers and structure declarations are part of this boundary. Record actual changed paths and the evaluated commit in delivery evidence. If implementation needs another path, update this declaration and recheck contention before concurrent work proceeds. Planning evidence lives in this task's record folder.
