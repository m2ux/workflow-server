**Component:** skills/work-planner/scripts/board.py

## Overview

A board's initiative and epic statuses follow current work. An epic is In Progress while a session holds one of its rows or a delivery pull request is open on it, until it passes the reviewed-handoff gate, and an initiative is raised to In Progress only by an epic its table still lists.

## Problem

- **Delivered rows read as work under way.**
  One delivered row keeps an open epic In Progress, or adds it there, with nothing open on it.
- **A reservation goes unseen.**
  A row a session holds puts its task issue In Progress, but the epic itself stays where it was until a pull request opens.
- **The integration draft reads as task work.**
  The epic's persistent integration pull request carries the epic's prefix, so an epic with no task under way still reads as In Progress, and its initiative waits on it.
- **Completed work starts an initiative.**
  An initiative not yet on the board is added at In Progress on the strength of a completed epic alone.
- **The queue reverses the delivery reading.**
  Advance mode puts every partly completed epic In Progress, and holds an initiative on any open pull request carrying its tag, whether or not its table lists the epic named.

## Proposal

Delivery sync and Advance mode each read a board's epics from the initiative's Work Breakdown and each derives whether an epic is under way. Both read the same activity, from one definition in `board.py`.

- **Activity.**
  An open epic is active when a task row links a reserved planning folder, or an open pull request whose title names the epic is not that epic's integration pull request. The integration pull request is identified as `agent_review.py` identifies it for the handoff gate, through one shared predicate.
- **Epic status.**
  - Closed as completed is Done.
  - Every criterion ticked takes the reviewed-handoff gate: In Review with current agent review of the integration head and base, In Progress otherwise.
  - Active is In Progress.
  - Inactive keeps Ready or Backlog; In Progress and In Review become Backlog, and an epic not yet on the board is added at Backlog. A delivered row alone is not activity.
- **Initiative status.**
  - In Progress when an epic its table lists is In Progress or In Review. An epic that has left the table is not read.
  - Otherwise the held status stands: Advance mode places and lowers an initiative. In Review becomes In Progress, and one not yet on the board is added at Backlog, so completed work alone starts nothing.
- **Advance mode.**
  - An active epic of the In Progress initiative is In Progress; an inactive one is a Ready candidate when it can start, and leaves Ready or In Progress for Backlog when it cannot.
  - An initiative waits only on an open delivery pull request naming an epic its table lists.
