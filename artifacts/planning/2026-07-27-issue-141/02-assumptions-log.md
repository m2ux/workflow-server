## Wrap-Up

25 assumptions across two activities — 5 validated, 2 partially validated, 7 invalidated, 11 user-resolved, **none open**. Design Philosophy raised 15 and carried 4 open into elicitation; Requirements Elicitation raised 10 and closed every one. One analyse–challenge–combine pass at design philosophy; challenge perspectives (stakeholder-gap, rejected-paths, evidence-strength) run sequentially — this worker cannot spawn agents, and sequential scatter is the `concurrency = 1` case. Elicitation ran one reconciliation pass, converging immediately because its residue was stakeholder-dependent by classification; the user then settled both residual assumptions at the `elicitation-complete` gate.

- **DP-3 invalidated** — the delivery-hash invariant is token efficiency, not correctness; the real exposure is a single-segment ref resolving to a different section. Constraint corrected in the philosophy doc.
- **DP-12 invalidated** — path refs cannot be written in prose markdown links: the guard's anchor pattern excludes `/` and GitHub renders no such anchor. Constrains the delimiter decision and AC 6's implementation.
- **DP-14 invalidated** (stakeholder-gap) — the duplicate title heading is a deliberate convention in all three `prism-evaluate` templates, not an accident, so heading renames need that workflow owner's agreement.
- **DP-15 invalidated** (rejected-paths) — erroring on an ambiguous flat slug addresses all 7 measured over-deliveries with no new syntax; an option neither the issue nor this log had considered.
- **DP-11 partially validated** — AC 1's GitHub `-N` dedupe alone reaches every duplicate-slug case measured in the corpus. Its untested half, flagged by evidence-strength: the claim that paths buy *stability* over positional `-N` anchors is argued, not measured — no test of what an inserted heading does to existing `-N` refs. Elicitation or research should settle it, since it is the whole remaining case for Defect 2.
- **DP-9 partially validated** — the submodule worktree mechanism is house-standard but not yet prepared; a setup step is owed before any corpus criterion can be met.
- **Evidence-strength notes:** all corpus figures come from purpose-built probes rather than project tooling, though the probe's link count matched the guard's own extraction exactly (403 both ways), and each of the 5 runtime-`null` links is individually named and reproducible. Severity rests on 2 hard failures in core workflow READMEs plus 7 over-deliveries confined to one workflow — real, but narrow in breadth rather than broad.
- **All four carried-open assumptions resolved by user decision at elicitation** — DP-6 confirmed (shared slugger module plus the differential guard check; no new dependency), DP-7 corrected to fix-3-defer-1, DP-10 corrected so path-scoping leaves the package, DP-5 deferred with it. DP-15's ambiguity-error option — surfaced by the challenge pass as an option neither the issue nor the log had considered — became the chosen approach.
- **RE-1 invalidated, and it decided the chosen approach.** A runtime-only ambiguity error would re-create the CI-green/runtime-fail divergence the package exists to end, because under GitHub semantics a bare `#slug` legally means the first of N. The user resolved RE-2 accordingly: the loud failure is a **guard** capability (comprehension Q10's `ambiguous-anchor` reason), and the resolver's GitHub semantics stay exactly faithful. The package therefore adds no new divergence of its own — the property that made the descoped design defensible.
- **RE-5 resolved as measure-first.** Guard fence hardening is not committed here; an implementation-analysis task counts what a CommonMark-correct tracker newly exposes, and the criterion is conditional on that count (SC-9). Nothing else in scope depends on it.
- **RE-3 validated, and it adds work the issue does not name.** The differential guard check turns the 7 live `prism-evaluate` refs red, so repointing them to `-1` is a merge gate, not an optional corpus improvement.
- **RE-6 and RE-7 invalidated — both loosen verification rather than tighten it.** Hash stability needs no session replay (it follows from content stability, already measured as zero-change), and the two AC-2 links cannot be verified through `get_resource` at all, since neither targets a `resources/` file.
- **Three new corpus measurements taken at elicitation**, all bearing on the descope decision: the issue's strongest hierarchy case (`static-analysis-patterns.md`, 8 sweeps) has file-unique slugs for every leaf it wants and needs no hierarchy; `intermediate-artifact-schemas.md`'s 5 duplicate slugs have zero live referencers; and 3 of the 4 known anchor breaks form one unnamed class — links into headings that exist only inside fenced template bodies — which is what makes RE-5's exposure count unknown.
- **Takeaway:** the issue's two defects are unequally evidenced. Defect 1 is measured, live, and cheap. Defect 2 is well-designed, but by the end of the challenge pass every case the issue cites for it turned out reachable three other ways — AC 1's dedupe, a three-heading rename, or an ambiguity error — while the one consumer that genuinely wants hierarchy sits behind the issue's own out-of-scope line. The pattern to watch is inheriting a proposal's framing when its own fix-first advice already covers the evidence.
