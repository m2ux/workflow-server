**Component:** skills/work-planner/scripts/sync.py

## Overview

The long-lived branch names a run uses are read from `config/branches` at the repository commit the run evaluates. Runs evaluating one commit therefore agree whichever worktree invokes them, and an epic sync reads the names its pinned epic-base commit states. The run reports the repository, resolved commit and configuration path it read.

## Problem

`long_lived_names` reads `config/branches` from the files of the checkout's main working tree. Which worktree the run starts from, and whatever uncommitted edit that tree holds, decide the long-lived set, so two runs evaluating the same change can return different names. An epic base that changes the declaration is read only after its initiative merges into the long-lived branch, so an epic sync checks its bases against a set the evaluated change never contained. A run given no `--project` falls back to whatever the invoking directory's main working tree holds.

## Proposal

- **Scene.**
  A sync of an epic whose base carries a revised `config/branches` runs from a linked worktree whose main working tree sits on the long-lived branch, possibly with an unsaved edit to the file. The epic checks gated on the set — unmerged bases, draft bases, review references — must use the base's declaration.
- **The evaluated commit is named.**
  `sync.py` and `deliver.py` take `--revision` beside `--project`, and neither reads the names without both. The revision is resolved to a commit in the repository the checkout locates; the checkout's working files and which worktree it is choose nothing.
- **The declaration is read from the commit.**
  `long_lived_names(project, revision)` reads the blob at `<commit>:config/branches` through git and returns the names with their source: `config/branches at <commit> in <repository>`, the repository being the shared git directory every worktree of it resolves to. A revision that names no commit, or a commit with no or an empty declaration, is unevaluable. No other ref, working tree or default substitutes for it.
- **The source is recorded.**
  `--names` prints the names on standard output and the source on standard error. An epic sync prints a `source:` report line; a delivery survey prints one ahead of its units.
- **Callers name their revision.**
  The Branches field of `delivery-branches.md` states which revision each run evaluates: an epic sync and a read of one epic's branches evaluate its epic base; base preparation evaluates the long-lived source it cuts from; a delivery survey evaluates the fetched long-lived branch that states the project's branches. The commands and their callers pass it.
- **Out of scope.**
  Naming the epic checks an unevaluable declaration leaves unmade (W07).
