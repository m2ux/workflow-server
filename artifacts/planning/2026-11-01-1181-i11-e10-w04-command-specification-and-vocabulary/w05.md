**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check gains a guides check and an interface check, so a convention stated in both the shared guide and a skill's own, and a command reaching GitHub through the wrong interface, are reported.

## Problem

A skill's guide can restate a shared convention under the same label, and the two copies drift. A command specification can send GraphQL where REST would serve, or reach a deprecated Projects (classic) interface, and nothing reports either; a blanket refusal of GraphQL would block the reads and writes only current GraphQL supports.

## Proposal

A convention is a guide's labelled rule, placed by the section that holds it. The interface a command uses is read from its specification and from the script it runs.

- **Guides check.**  A skill's guide (`guidelines.md` beside SKILL.md or under `references/`) is read against the shared guide in the skill's parent folder. A rule whose label and section title match a shared rule is reported as a convention in both guides.
- **Interface check.**
  - A command specification whose command block sends GraphQL, directly or through a script of the skill it runs, carries a `**REST gap:**` line stating what REST cannot do; one without it is reported.
  - A REST command and a GraphQL command with its gap stated pass.
  - A Projects (classic) field, type, mutation or REST endpoint is reported anywhere in the skill's markdown or scripts, whatever else the file states.
- **Corpus.**  Work Planner's Prose rules that repeat shared labels take labels of their own, and its four GraphQL specifications state their REST gap.
- **Guidelines.**  The shared guide's One home per rule rule states the guides check, and a new Interface rule under Commands states the capability policy.
