**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check gains a rules check, so every house rule a guide states names the operation that decides it, and one that names none is reported.

## Problem

A guide's rule carries no trace to whatever decides it. A reader cannot tell which rules a script enforces and which rest on review, and a rule can lose its check, or never have one, without anything noticing.

## Proposal

A house rule is a labelled rule entry of a guide, the shared guide or a skill's own. Its deciding operation is declared beside the guide rather than inferred from its prose.

- **Declaration.**  `rules.json` beside each guide maps each rule, keyed `<section-anchor>/<label-anchor>`, to the list of operations that decide it: the finding kinds of the shared check, or `review`, the read against the guidelines each Revise procedure runs.
- **Rules check.**
  - A rule with no entry, or naming an operation the check does not register, is reported as a house rule no operation decides.
  - An entry for no rule is reported as a declared rule absent.
  - Two rules of one guide under one key are reported as ambiguous.
- **Registry.**  The check registers every kind it reports in one tuple, which its own suite holds against the kinds the source reports.
- **Reach.**  The shared guide of every checked skill is read, so a run over the skill folders reaches it.
- **Declarations.**  The shared guide, Work Planner's guide and Workflow Canon's guide each carry a `rules.json`.
