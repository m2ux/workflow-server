**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check gains a commands check and a vocabulary check, so a mode that spells a command out, and a concept a skill names by two terms, are reported rather than remembered.

## Problem

A mode file can inline a command block that its operation already specifies, and nothing reports it. A concept renamed in one file keeps its old term elsewhere, in prose, docstrings or identifiers, and the skill then names one concept two ways.

## Proposal

The check already recognises each command specification by the section its structure names. The vocabulary of a skill is declared rather than guessed.

- **Commands check.**  In a mode file, named `<mode>-mode.md`, a shell or unlabelled code block outside the file's command specifications is reported as a command spelled out in a mode.
- **Vocabulary check.**  `vocabulary.json` beside a skill's SKILL.md maps each concept's term to the terms it retires. The nearest declaration at or above a file governs it. A retired term, matched whole and case-sensitively, is reported in the skill's markdown outside code blocks and code spans, and anywhere in its `scripts/` files.
- **Declarations.**  Work Planner declares `pull request` over `PR` and `PRs`, and `Align mode` over `Review mode`; the uses of `PR` the check finds are restated.
- **Guidelines.**  The shared guide's Named by link and Terms rules state both checks.
