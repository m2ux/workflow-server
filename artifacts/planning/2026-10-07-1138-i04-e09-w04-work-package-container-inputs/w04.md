## Overview

Work-package container inputs that an operation never reads are optional on the container those operations share, or they live on the operation that reads them. A step that binds an operation is not handed a required slot nothing produces.

## Problem

- **Session facts are required of operations that never read them.**
  The [work-package root](https://github.com/m2ux/workflow-server/blob/c6774bff/corpus/work-package/techniques/TECHNIQUE.md#L16-L38) requires the branch, the target path, the pull-request number, the component checkout, the problem statement and the requirements of every operation. Bindings from other workflows hold none of those values.
- **Two assumption inputs sit on the group, and one operation reads them.**
  [`assumption_source` and `assumption_categories`](https://github.com/m2ux/workflow-server/blob/c6774bff/corpus/work-package/techniques/review-assumptions/TECHNIQUE.md#L12-L18) are required of every operation in the group. `collect` is the operation that reads them.
- **The pull-request group restates branch and checkout as required.**
  [`branch_name` and `target_path`](https://github.com/m2ux/workflow-server/blob/c6774bff/corpus/work-package/techniques/update-pr/TECHNIQUE.md#L12-L30) stay required on that group. `post-review-comment` reads neither, and a review workflow that binds it holds neither.
- **The closing group requires a test plan no operation reads.**
  [`test_plan`](https://github.com/m2ux/workflow-server/blob/c6774bff/corpus/work-package/techniques/finalize-documentation/TECHNIQUE.md#L16-L18) is required, and no operation under that group references it. The pull-request template variant is already optional, with default `final`.

## Proposal

- **The scene.**
  The work-package root holds the session facts every operation may inherit. The assumption group holds the source and the categories. The pull-request group restates the branch and the checkout. The closing group holds the test plan.
- **Session facts are optional on the root.**
  Each of the six is optional. Absent means the run has not produced that fact, and an operation that never reads it is not owed a value.
- **Assumption inputs live on the operation that reads them.**
  `collect` declares `assumption_source` and `assumption_categories`. The group no longer does.
- **The pull-request restatement is optional.**
  `branch_name` and `target_path` on that group are optional, with the same absence as the root. The template variant stays optional, default `final`.
- **The unread test plan is optional.**
  `test_plan` is optional. Absent means the run has not written one.
- **A borrowed input the step never reads is bound empty.**
  Jira steps bind `cloudId`, readme and session steps bind `session_index`, the lean-coding audit binds `task_description`, and the prism reads bind `target_content`.
- **Activity reads follow the contract.**
  A read of one of the six session facts is dropped where no step, gate, loop or transition consults it once the input is optional. The triage entries for the unproduced reads that drop with them go with the change.
