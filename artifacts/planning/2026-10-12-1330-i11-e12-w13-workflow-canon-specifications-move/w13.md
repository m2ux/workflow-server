## Overview

Six command specifications of the Workflow Canon skill stand in a reference file while a single procedure elsewhere runs each. This task carries each one into the file whose procedure runs it, in a `## Commands` section last among that file's top-level sections, and leaves the reference files holding what several procedures share. The destination of each is read from the shared skill-file check's own output rather than chosen, and every carried body is compared against its original before the work is reviewed.

## Problem

- **A reader opens a reference file to reach one operation.**
  A step dispatching an audit assignment opens [`change-surface.md`](https://github.com/m2ux/workflow-server/blob/d1dea57e/skills/workflow-canon/references/change-surface.md), which states capture, identity, applicability, evaluation, completion, freshness and artifacts, to reach the one command the step runs. A step answering a canon question opens [`canon-context.md`](https://github.com/m2ux/workflow-server/blob/d1dea57e/skills/workflow-canon/references/canon-context.md), 244 lines of terms, criteria, scope, homes, checks and conventions, for the same reason.
- **Six specifications have exactly one caller.**
  The shared check names each with the single file whose procedure cites it: three in `canon-context.md` run from the audit and revise modes, and three in `change-surface.md` run from the dispatch route. The work list is a measurement rather than a reading.
- **This move is where specifications get corrupted.**
  The same restructure in this skill damaged four specifications, and the damage was found by reading the files, after a link check, 71 tests and a structural check had all passed over it. No check reads a specification's body.

## Proposal

Carry each specification whole, and verify the bodies rather than the links.

- **The check's report is the work list.**
  Each of the six moves to the file the check names, and a specification several procedures run stays where it is.
- **The move is mechanical.**
  Each specification's lines are lifted by line range and laid under its destination's Commands section without being retyped, reworded, summarised or merged. Only link targets change, because an anchor that named the holding file must now name the file holding it.
- **Each destination.**

  | Specification | Lands in | Because |
  | --- | --- | --- |
  | List Units for a Construct | `references/audit-mode.md` | Its Procedure's scoping step runs it |
  | Fetch Unit | `references/audit-mode.md` | Its Procedure's canon-question step runs it |
  | Run the Edit Guard Tests | `references/revise-mode.md` | Its Procedure's check step runs it |
  | Plan Audit Assignments | `references/audit-dispatch.md` | The Dispatch Route's first step runs it |
  | Bind Audit Agent | `references/audit-dispatch.md` | The Dispatch Route's second step runs it |
  | Write Audit Packet | `references/audit-dispatch.md` | The Dispatch Route's third step runs it |
- **The Commands section is last.**
  A mode file's top-level sections are Prerequisites, Procedure, Reference, Rules and Commands in that order, so the audit mode gains a Commands section at the end of the file and the revise mode's existing one receives its specification.
- **The dispatch file keeps its own order.**
  `audit-dispatch.md` is not a mode file. It carries Phases, which holds the Dispatch Route's steps, then Sizing and Returns. Its Commands section stands last, after Returns, because the planning step's sizing input and the packet step's return contract are what the reader must already hold when they reach the commands, and a section that governs a command sits ahead of it. The conventions governing these three commands stay in `change-surface.md`, so the Commands section opens by naming them.
- **A same-file prerequisite citation does not survive the move.**
  `Plan Audit Assignments` opens by asserting the reader has read Sizing. Sizing now stands above it in the same file, where position carries the requirement and the shared guidelines drop the citation, so the sentence goes and the rest of the bullet stands unchanged. It is the only difference in any carried body beyond a link target.
- **A section the move empties does not remain.**
  Each source file's Commands section keeps other specifications, so no heading is emptied.
- **A specification believed wrong is not corrected here.**
  Anything the move exposes is raised as its own issue.
