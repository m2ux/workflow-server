## Overview

Prism's container input `target_content` gets a source at every step binding an operation that never reads it.

## Problem

- **4 steps owe a value nothing supplies.**
  [`target_content`](https://github.com/m2ux/workflow-server/blob/bb38d574/corpus/prism/techniques/TECHNIQUE.md#L12) is required on prism's container. `plan-analysis`, `emit-run-manifest`, `link-report-references` and `generate-report` never read it, and the run holds no variable or earlier output of that name.

## Proposal

- **The scene.**
  The content under analysis reaches the lens passes, and the mode, delivery and report activities bind ops that work on what those passes produced.
- **The source.**
  Move the declaration down to the ops that read it, or give it a source the run already holds, as the entry's Fix orders.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | List the prism ops that read `target_content` |
| Implementation | Re-home or source the input |
| Test | The guard over prism, the standard sweep, and the prism coverage walk |
