## Overview

Work-package's group containers give every inherited input a source at each step binding an operation that never reads it.

## Problem

- **14 steps across three group containers owe values nothing supplies.**
  - [`pr_template_variant`](https://github.com/m2ux/workflow-server/blob/bb38d574/corpus/work-package/techniques/update-pr/TECHNIQUE.md#L32) on update-pr: 6 steps.
  - [`test_plan`](https://github.com/m2ux/workflow-server/blob/bb38d574/corpus/work-package/techniques/finalize-documentation/TECHNIQUE.md#L16) on finalize-documentation: 6 steps.
  - [`assumption_source` and `assumption_categories`](https://github.com/m2ux/workflow-server/blob/bb38d574/corpus/work-package/techniques/review-assumptions/TECHNIQUE.md#L12-L16) on review-assumptions: 1 step each.

## Proposal

- **The scene.**
  Each group container declares inputs its ops share, and the start, strategic-review, submit and complete activities bind them.
- **The source.**
  Move each input down to the ops that read it, or give it a default or source the run already holds, as the entry's Fix orders.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | For each input, the ops that read it and what the run lands under that name |
| Implementation | Re-home, default or source each input |
| Test | The guard over work-package, the standard sweep, and the work-package snapshot and coverage walks |
