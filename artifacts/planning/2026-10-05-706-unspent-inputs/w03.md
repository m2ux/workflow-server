## Overview

The CI/CD audit's group containers give every inherited scanner input a source at each step binding an operation that never reads it.

## Problem

- **20 steps across four group containers owe values nothing supplies.**
  - [`sub_workflow_scan_outputs`](https://github.com/m2ux/workflow-server/blob/219b4f37/corpus/cicd-pipeline-security-audit/techniques/dispatch-scanners/TECHNIQUE.md#L16) on dispatch-scanners: 7 steps.
  - [`scanner_assignment`](https://github.com/m2ux/workflow-server/blob/219b4f37/corpus/cicd-pipeline-security-audit/techniques/scan-injection-patterns/TECHNIQUE.md#L12) on scan-injection-patterns: 7 steps.
  - `scanner_outputs` on [merge-scan-findings](https://github.com/m2ux/workflow-server/blob/219b4f37/corpus/cicd-pipeline-security-audit/techniques/merge-scan-findings/TECHNIQUE.md#L12) and [verify-scan-output](https://github.com/m2ux/workflow-server/blob/219b4f37/corpus/cicd-pipeline-security-audit/techniques/verify-scan-output/TECHNIQUE.md#L12): 4 and 2 steps.

## Proposal

- **The scene.**
  Each group container declares the inputs its ops share, and each group's activity binds its ops in turn.
- **The source.**
  Move each input down to the ops that read it, or give it a source the run already holds, as the entry's Fix orders.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | For each input, the ops that read it and what the run lands under that name |
| Implementation | Re-home or source each input |
| Test | The guard over cicd-pipeline-security-audit, the standard sweep, and the coverage walk |
