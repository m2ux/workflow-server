**Component:** workspace:skills/work-planner/scripts/deliver.py

## Overview

A free row of a multi-base epic that links no work item is offered for dispatch with a task branch and worktree for every epic base. A row whose linked work item names no long-lived branch with an epic base stays `undeclared`.

## Problem

W12 ([#1526](https://github.com/m2ux/workflow-server/pull/1526)) gives a unit only the bases its rows' work items name, and reports a row linking no work item `undeclared`. A row's work item is written inside its delivery session, at Run Delivery Session step 3, after dispatch. So an unplanned row of a multi-base epic can never be offered: 20 free rows of I13:E00 (#948), I13:E01 (#1138), I14:E04 (#708) and I15:E02 (#750) are reported `undeclared` against `b9705f5ce`.

## Proposal

- **Scene.**
  A survey reaches a free row `W01` of an epic with bases `i07/e00/main`, `i07/e00/workflows` and `i07/e00/workspace`. The row links nothing, or only its task issue.
- **An unplanned row changes every base.**
  `changed_bases` gives a row linking no work item every epic base. The unit line names a suffixed branch and worktree for each, as Task Branches states for several bases. The session writes its work item, works on the branches its component needs and opens a pull request only from those.
  - Rejected: offering the unit with its bases undecided for the session to choose. Dispatch creates the task worktrees from the unit line before the session plans (Deliver Mode step 8), so an undecided base needs a second branch-creation path inside the session.
- **A declared work item still decides.**
  A row linking a work item keeps W12's rule: its Component names the base, and a work item that names none with an epic base, or cannot be read, is `undeclared`.
- **A joined unit takes the union.**
  A unit joining an unplanned row and a declared one changes every base.
