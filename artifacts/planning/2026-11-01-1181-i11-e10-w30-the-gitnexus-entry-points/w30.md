**Component:** workspace:skills/gitnexus/gitnexus-guide/SKILL.md

## Overview

The shared check measures every `SKILL.md` against the entry-point set the guidelines name: Modes, Rules, Conventions and Dependencies, in that order. Five gitnexus entry points depart from it. This task brings each to that set, so the gitnexus skill reads clean again and the final verification over every skill passes there.

## Problem

- **Five entry points carry sections outside the set.**
  The shared check reports 30 `section outside the set` findings across the debugging, exploring, guide, impact-analysis and refactoring entry points, under headings such as When to Use, Workflow, Checklist, Tools and Example.
- **The gitnexus skill was clean before the measurement.**
  The skill reported no finding once its CLI entry point moved its procedures into an operations file. The entry-point measurement reaches the five entry points that still hold theirs.

## Proposal

The CLI entry point already has the shape: an Opening that routes each request to a procedure in its operations file, then Dependencies.

- **Each entry point keeps what selects it.**
  - The Opening states what the skill does and lists, for each request it answers, the procedure that answers it.
  - What binds every use stays in Rules; what it relies on stays in Dependencies.
- **What a session reads once selected moves out.**
  - Workflow, checklists, tool and resource tables, patterns and the worked example move to a file under the skill's `references/`, which takes the procedure-file sections: the workflow and checklist as Procedure, the tables, patterns and example as Reference.
  - The Opening links that file's sections at the point a request needs them.
