## Overview

Work Planner's command specifications stand in the file whose procedure runs them, in a Commands section at the end of that file, and the catalog holds the operations several procedures share. The execution conventions stand in a file of their own, so a procedure reaching them opens the conventions rather than the file holding every specification. The move is measured by the shared skill-file check, which names the file each misplaced specification belongs to, and reviewed by a comparison of every moved specification against its original.

## Problem

- **A reader meets an operation through a link out of the file they hold.**
  `references/commands.md` is 870 lines and 79 third-level sections, 30 percent of the skill's markdown. Every mode file links into it to reach the few operations its procedure runs, so a step that needs one command costs the catalog.
- **Thirty-six of those specifications have exactly one caller.**
  The shared check reports each with the file whose procedure cites it, so the work list is a measurement rather than a reading. Twelve files are named between them, and `references/work-breakdown.md` is named eight times.
- **The conventions sit at the head of the catalog.**
  Session setup, execution location and the example values are read once a session, and seventeen files cite them. Reaching them through `commands.md#conventions` takes the whole catalog for four paragraphs of prerequisite.
- **This move is where specifications get corrupted.**
  The same restructure in Workflow Canon damaged four specifications, and the damage was found by reading the files, after a link check, 71 tests and a structural check had all passed over it. Nothing in the existing checks reads a specification's body.

## Proposal

Carry each specification whole, and verify the bodies rather than the links.

- **The check's report is the work list.**
  The destination of each of the thirty-six is read from the check's own output at the base, not chosen. [destinations.md](destinations.md) records them.
- **The move is mechanical.**
  Each specification's lines are lifted from the catalog and laid under its caller's Commands section without being retyped, reworded, summarised or merged. Only link targets change, because an anchor that named the catalog must now name the file holding it.
- **The Commands section is last.**
  A mode file's top-level sections are Prerequisites, Procedure, Reference, Rules and Commands in that order, so a received specification lands at the end of the file.
- **The conventions become a file.**
  `references/command-conventions.md` holds the execution conventions, and the seventeen citations name that file whole. The catalog's lede states what the catalog now holds.
- **The catalog survives, smaller.**
  A specification several procedures run stays. Forty-three do, beside the Graph Conventions block that governs the graph commands.
- **Two specifications have no procedure to move to.**
  List Initiative Titles and Development Access are named only from `SKILL.md`, from Themes and Boards and from Dependencies. Neither is a procedure running the command, and the shared guidelines state that SKILL.md holds no command of its own, so moving either there would break the rule this epic wrote. Both stand in the catalog.
- **The symmetric caller test uncovers ten more.**
  W09 asks of every citing file, the holding file included, whether a procedure of it carries the citation, and reads a procedure by the numbered step it carries rather than by the word in its heading. Ten specifications that had appeared to have several callers prove to have one, each masked by a citation that names a command without running it. They are this row's remainder under AC3, moved the same way and compared the same way.
- **A section the move empties does not remain.**
  `Sources` and `Sessions` hold nothing once their specifications leave, so neither heading stands.

## Work Breakdown

| Part | Description |
| --- | --- |
| Conventions | The execution conventions stand in `references/command-conventions.md`, read once a session, and every citation of them names that file |
| Catalog | The catalog's lede states that it holds the commands several procedures run, and a section the move empties goes with its last specification |
| Move | Each specification the check names is carried whole into a Commands section at the end of the file whose procedure runs it, with its link targets rewritten to name the file that now holds each anchor |
| Remainder | The ten the symmetric caller test uncovers move the same way, and the catalog keeps no heading the move has emptied |
| Citations | Every citation of a moved specification, in the catalog and in the mode files, names the file holding it, and every anchor resolves |
| Test | The shared check over `skills/work-planner` reports no command-specification finding; the skill's own suite passes; every moved specification's body is compared against its original and every difference accounted for |
