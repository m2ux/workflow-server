## Overview

Work Planner is used through prosiform. Its entry point tells the reader to run `pf` and follow it, every mode compiles within the default output budget with no warning, and each mode's bundle size is compared against a fixed baseline revision. Once these hold, the skill is named to the shared check's prosiform findings, so a later change that breaks them draws a finding.

## Problem

- **The entry point is read, not compiled.**
  [SKILL.md](https://github.com/m2ux/workflow-server/blob/785a5ee8c/skills/work-planner/SKILL.md#L19-L67) selects a mode by a link the reader follows; compiling SKILL.md itself yields a 405673-byte bundle carrying every mode.
- **Five modes overflow the default budget.**
  At [785a5ee8c](https://github.com/m2ux/workflow-server/tree/785a5ee8c/skills/work-planner): Deliver 353717 bytes, Plan 328950, Advance 314874, Standup 273929 and Sync 264276, against 262144.
- **Nothing fixes what a change costs.**
  No record holds each mode's bundle size, so a change that grows a bundle is seen only when it crosses the budget.

## Proposal

- **SKILL.md bootstraps through `pf`.**
  The entry point's one instruction is to run `pf` and follow it, and its Modes list selects a mode through a link prosiform compiles.
- **Each mode fits its bundle.**
  A mode still over the budget once its links carry prosiform's meaning is cut to its own procedure, moving a section only some steps use to a file of its own.
- **The skill is held to the prosiform findings.**
  It is named to the shared check's prosiform findings once every mode compiles within the budget.
- **One comparison fixes the cost.**
  Each mode's bundle at the settled revision is compared with its bundle at the baseline revision, compiled by one prosiform version on both.
