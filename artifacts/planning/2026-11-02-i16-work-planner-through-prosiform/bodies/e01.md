## Overview

The shared skill guidelines define each check the workspace runs: what it decides, which skills it binds, how it is run and where its tests live. Prose names a check by linking to its definition, and the shared skill-file check reports a check named by its bare path.

## Problem

- **A check is named by its path.**
  The shared guidelines' [Verified rule](https://github.com/m2ux/workflow-server/blob/785a5ee8c/skills/guidelines.md#L198) names the shared check as a code span, so the reader meets a file path rather than a check with a purpose.
- **No check is defined.**
  The [Files rule](https://github.com/m2ux/workflow-server/blob/785a5ee8c/skills/guidelines.md#L27-L28) says shared checks sit in `skills/scripts/` and per-skill checks in the skill's own folders, and nothing says what any of them decides, which skills it binds, how it is run, or where its tests live.
- **Nothing reports a bare path.**
  The [shared skill-file check](https://github.com/m2ux/workflow-server/blob/785a5ee8c/skills/scripts/check_skill_files.py#L1025-L1029) treats a code span as specimen text and reads nothing in it.

## Proposal

- **The shared guide has a Checks section.**
  One entry per check the workspace runs, stating what it decides, which skills it binds, how it is run and where its tests live. The prosiform compile run the shared check gains is one of them.
- **Prose links the definition.**
  A sentence naming a check links its Checks entry, as a command is named by linking its specification.
- **The check reports a bare path.**
  A code span naming the script of a check the Checks section defines is a finding, in the skills the check reads.
