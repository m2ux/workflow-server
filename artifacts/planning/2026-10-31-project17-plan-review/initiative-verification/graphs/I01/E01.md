## Summary

A checkpoint is a place where a workflow stops so a person can decide something. Across the corpus that stop is not reliable at any of the three points it has to hold.

It can fail to happen: gates meant to reach a person resolve themselves, because nine surfaces state a presentation rule and four of them license skipping it. It can happen and change nothing: an approval records an effect that moves no state, so a design run closes with a clean audit, three judgements still open and twelve approved removals still unapplied. And it can be recorded and then not survive: a close-out ledger stays open, with follow-ups noted in an artifact and no register holding them.

The three are one path failing at three points. This phase makes the path hold end to end: a gate reaches the person, the answer applies, and what the answer produced is recorded where the next run can read it.

## The three gaps

**Presentation is governed by rules that contradict each other.** The engine's own rule says every resolution of a gate must be preceded by actually showing the question — never a wait and an automatic advance. Four workflow-level rules say the opposite for gates carrying a default answer and an interval: resolve without asking. Nine surfaces in the corpus state a presentation rule; five agree with the engine and four license skipping it. Three of those four sit in the bucket delivered to workers, and resolving a gate is not a worker's job — so the licence reaches an agent that cannot act on it and misses the one that can. The fourth sits in the orchestrating bucket, which makes it the operative contradiction. No guard in the suite reads rule text, so none of this is visible to the check.

**An approval records an effect that moves nothing.** Open judgements reach a gate that does not resolve them, or resolve them into a variable no reader consults. The assumption-decision array has no producer. A remediation path can apply a removal without inventorying it, so a row added after a batch approval is indistinguishable from one that approval covered.

**The ledger is left open.** Four follow-ups sit actionable and unowned: resource frontmatter, a protocol phase whose only content is mode selection, a capture bullet that closes no gap, and a README table that transcribes routing. Twelve inventoried removals are unapplied. Four variables have no reader, and one terminal gate offers two options that carry no effect at all. Two structural limits need an explicit outcome: a correction loop whose cap bounds its comparison while prose advances its counter, and a workflow holding no validation action anywhere, so the integrity of a canonical document rests on prose.

## The work

**W01 — One presentation contract.** State it once, in the engine technique the orchestrating role actually receives: presentation is mandatory, except for a genuine soft mid-flow gate under a headless posture, which resolves to its default; safety gates and self-attestation gates are never soft; and the interval field is documented for what it does on each path. Collapse the four workflow-level licences to short deferrals citing that home. Settle which construct owns softness and retire the other spellings rather than validating the overlap, resolving the gate that declares two of them contradictorily. Move every self-attestation gate that authorises rather than records onto the interactive list, and record each soft gate's classification with its reason. Take the nine consent clauses one at a time — harden the gate where consent is load-bearing, restate the clause where the approval verb was decoration. Add the guard the suite lacks: one that reads rule text and fails a presentation claim stated outside its single home.

**On the headless posture, take the deletion branch.** The original item offered a choice — give it structural reach, as a declaration the bag holds and a condition each soft gate carries, or give it no existence at all. Give it none. Structural reach is machinery for a posture that is a property of a whole run rather than of each gate it passes, and #527 E07 already sites it there as a value a session is constructed with. Building it per gate now would be building it twice.

**W02 — Approvals that apply.** Give open judgements a gate that resolves them, sited where the evidence to resolve them exists, following the batch-then-per-item pattern the corpus already uses. Give the assumption-decision array a producer, or delete it along with its readers. Require the remediation path to inventory any removal it applies or refuse the fix, reusing the existing append operation and artifact writer, and record each row's provenance so a row added after the batch approval stays distinguishable from one that approval covered.

**W03 — Close out the ledger.** Apply the four actionable follow-ups. Apply the twelve inventoried removals under three dispositions — removal with replacement effects on the options it would otherwise strand, a plain announcement in place of a gate, and a self back-edge so rework options keep a destination and gain an effect. Settle the one remaining reader-less variable and the terminal gate whose two options carry no effect. Give both structural-limit findings an explicit outcome.

## Why now is cheap

**The walk that found these was already done.** Each gap came out of reading a real design run against the live definitions, so the sites are located and the dispositions are drafted rather than needing discovery.

**The contradiction is cheap to resolve in one direction.** Four licences collapse to deferrals citing one home. That is a deletion plus a citation, not a design.

**The damage compounds per run.** A design run that closes with three judgements open and twelve approved removals unapplied does so again next time. Nothing about the current arrangement degrades gracefully.

**One caveat, recorded rather than hidden.** W01's new guard reads rule text, and the rules it reads are addressed to an agent that resolves gates. When #527 E04 lands, a program resolves them and that surface goes quiet — so expect the guard to stop finding things. That is a reason to expect it to fall silent, not a reason to delay the contract: the contradiction is live for as long as the current execution path runs.

## Acceptance criteria

- [ ] The presentation contract is stated in exactly one home, and no surface in the corpus states a competing one; the guard that reads rule text fails a claim stated elsewhere.
- [ ] Softness is owned by one construct and the other spellings are retired; the gate that declared two contradictorily is resolved.
- [ ] The headless posture has no structural existence, and the decision to give it none is recorded with its reason.
- [ ] Every self-attestation gate that authorises rather than records is on the interactive list, and every soft gate carries a recorded classification with its reason.
- [ ] Each of the nine consent clauses is either a hardened gate or a restated clause, with the choice recorded per clause.
- [ ] Every open judgement reaches a gate sited where the evidence to resolve it exists.
- [ ] The assumption-decision array has a producer, or it and its readers are gone.
- [ ] A remediation path that applies a removal has inventoried it, and a row added after a batch approval is distinguishable from one that approval covered.
- [ ] The twelve inventoried removals are applied under a recorded disposition, and no option is left stranded without a destination or an effect.
- [ ] The four actionable follow-ups are applied, the reader-less variable and the effect-free terminal gate are settled, and both structural-limit findings carry an explicit outcome.

## Non-goals

- **Which gates should exist, or what they ask.** This epic makes the path from a gate to an applied outcome hold. Whether a particular decision is worth stopping for is a corpus-design question and is not opened here.
- **Structural reach for the headless posture.** Declined above, with the reason.
- **Anything the engine change owns.** How a gate is presented mechanically, or how an answer is recorded in a session, belongs to #527. Nothing here is gated on it and none of it blocks a phase of it.
- **A guard for the rule-versus-procedure distinction.** Worth having and separable; a guard over a corpus that currently fails it is a canon question before it is a mechanical one.
