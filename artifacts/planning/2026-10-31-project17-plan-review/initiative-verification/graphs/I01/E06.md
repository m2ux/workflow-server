## Overview

This epic gives three settled pieces of standing work a check that keeps them settled: the lockfile denylist gating the server's own pull requests, the citation-grain outcomes held in a ledger a guard reads, and graph reach held by a guard rather than by a one-off audit. The work that made each true is delivered. What holds it true is not.

## Problem

- **The lockfile guard does not gate the server.**
  `guards/check-lockfile-denylist.ts` is registered with `scope: 'repo'` in `guards/guards.ts` and runs only in `check:all`, which `verify-corpus.yml` runs on the corpus branch against `main`'s lockfile. `.github/workflows/verify.yml` on `main` runs `check:schemas`, `guards/check-tool-call-shape.ts` and `test:ci`, and no lockfile check. `tests/lockfile-denylist.test.ts` feeds the scanner fixture lockfiles and never reads `package-lock.json`. A server pull request that changes `package-lock.json` is not gated.
- **Citation-grain outcomes live where no check reads them.**
  `guards/check-citation-grain.ts` reports only the bare-plus-anchored tell. The outcome recorded for each bare citation of a sectioned resource sits in a planning record, and `ledgers/` on the corpus branch holds no citation-grain triage. Its sibling `guards/check-section-framing.ts` reads `ledgers/section-framing-triage.json` and reports a stale entry. Citation grain has no equivalent.
- **No guard counts graph-operation bindings.**
  The graph operations live under `corpus/support/gitnexus/` on the corpus branch, and no guard registered in `guards/guards.ts` reads which workflows bind them. A new workflow that binds none, or an existing one that drops its last binding, passes every check.

## Proposal

**Run the lockfile guard in the server's CI.**
`verify.yml` runs `check:lockfile` beside the other guard it already runs, so the pull request that changes `package-lock.json` is the one that fails.

**Give citation grain a triage ledger.**
A ledger under `ledgers/` records each bare citation of a sectioned resource with its outcome, in the shape the framing ledger uses. `check:citations` reports a bare citation the ledger does not record, and an entry that matches no citation as stale. The ledger is seeded from the outcomes the citation-grain planning record holds.

**Fail a workflow that binds no graph operation.**
A graph-reach guard counts, per workflow, the bindings of operations under `corpus/support/gitnexus/`. A workflow with none fails unless an exemption list records it with a reason, so `remediate-vuln` and workflows like it are recorded once rather than re-derived. An exemption matching no zero-binding workflow is stale.

**Ownership.**
This epic owns the three checks. The fan-out ownership guard belongs to [E05](https://github.com/m2ux/workflow-server/issues/634), whose decision names the home it enforces.

## Acceptance Criteria

- [ ] **AC1.** A server pull request whose lockfile resolves a denylisted version fails the server's verify job.
- [ ] **AC2.** Every bare citation of a sectioned resource carries an outcome in the citation-grain triage ledger, as `check:citations` reports.
- [ ] **AC3.** `check:citations` reports a triage-ledger entry that matches no citation as stale.
- [ ] **AC4.** Every workflow that binds no graph operation carries a recorded exemption reason, as the graph-reach guard reports.
- [ ] **AC5.** The graph-reach guard reports an exemption that matches no zero-binding workflow as stale.
