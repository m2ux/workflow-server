## Summary

Six things are wrong right now. Not designed badly, not awaiting a decision — wrong, in the sense that something behaves incorrectly every time it is reached, and has done for months.

They have nothing in common except that. One is a shell command that cannot work as written. One is a set of bindings that resolve to nothing. One is an activity that can be entered a second time and has no way out. One is a guard that exists, passes its own test, and never runs. One is an operation handing every caller a value nobody asked for. One is an install that would accept a version known to be poisoned.

What they share is why they survived: each was found, written down, and then owned by nobody. Individually every one of them loses to anything larger whenever it is triaged alone, and none is large enough to argue for on its own.

Together they are one phase, and it goes first because these are faults rather than gaps. Every run executed before they land pays them again.

## The six

**Five content defects have never been fixed.** An earlier review found them, quoted them and located them, and no backlog item ever owned them: an environment assignment placed after the `nice` command it is meant to configure, which is not valid shell; a test-thread budget stated one way in the cargo group's rule and another in the check and clippy operations; a first step in the create-issue operation that contradicts its own scoping; a concurrency instruction in the suite runner in tension with its group's foreground-only rule; and a checkpoint message interpolating `{problem_complexity}` while its own default option sets a variable named `path_gating_complexity`, so the message renders with a hole in it.

**Bindings resolve to nothing.** A close-out artifact whose three names disagree and whose seeded link points elsewhere. An outcome list whose declared type is not the list every reader treats it as. A trace-token relay named in seven files and wired end to end in none. A usage-recording signature that does not match its caller. A default branch name with no producer. A review-path ticket landed under a name the bindings do not read. Three values used without being declared. Each is silent: a binding that resolves to nothing returns an ordinary-looking empty, and nothing anywhere holds the difference.

**A re-entered activity has no way forward.** The flag guarding the onward transition is set at classification and cleared by nothing, and no backward transition into an activity is modelled — so a second pass through routes to a stage that has already finished.

**A guard never runs.** The branch-as-step guard has a script and a test and no registry entry, so the suite skips it. It has been passing its own test and checking nothing.

**An operation announces its bookkeeping as a result.** The operation that creates a work package's tracker issue carries a switch inside it — is there already an issue, or does one need making — sets it early and reads it later. That is ordinary internal bookkeeping. What makes it a defect is that the operation also *declares* the switch as one of its results, so every caller receives it whether or not it wanted it, and every workflow borrowing the calling activity has to account for a value it has no use for.

**An install is not checked against what is known to be bad.** On 4 August 2026 attackers published trojanized versions of widely used packages, and nothing in this repository would notice a version known to be poisoned. Nothing is failing today; this is the shape of defect where the next occurrence is the expensive one.

## The work

**W01 — Fix the five content defects.** One corpus pull request; each fix is small and none is blocked. The fifth kind is already catchable mechanically — the binding-fidelity guard walks checkpoint messages and gate expressions — so this is purely the five fixes with no guard to build alongside them.

**W02 — The binding sweep.** Align the close-out artifact's three names and its seeded link. Resolve or drop the outcome-list binding and correct its declared type to the list every reader treats it as. Decide whether the trace-token relay earns its keep, then wire it end to end or retire it from the seven files that name it. Correct the usage-recording signature. Give the default branch name a producer. Land the review path's ticket under the name the bindings read. Make the evaluation workflow's adjust option record what to adjust, and declare the three values used without being declared. Clear the guard suppressions and dead triage entries the sweep leaves behind.

**W03 — A re-entered activity has somewhere to go.** Either the guarding flag is cleared where a second pass begins, or a backward transition into the activity is modelled — the item settles which, and records why the other was not taken.

**W04 — The guard runs.** A registry entry for the branch-as-step guard, and a check that a guard with a script and a test cannot be absent from the registry. The second half is what stops this recurring; without it the fix lasts until the next guard is added.

**W05 — The switch stops being a result.** The create-issue operation keeps its internal switch and stops declaring it as an output. Callers stop receiving it, and the workflows borrowing the calling activity stop accounting for it. The anti-pattern catalogue already names this shape and quotes this exact field, so the entry needs no new work.

**W06 — Pin the seed family and fail the build on a known-bad version.** An overrides block resolves the eleven seed packages to their last known-good releases even if a future dependency asks for a bad one, with the lockfile regenerated afterwards as its own clear commit. Beside it, a check reads the lockfile and fails when any name-and-version matches a checked-in denylist, running in continuous integration next to the existing guards and invocable locally. The wider four-hundred-package worm list is detection input for that check rather than a permanent pin list, and the note explaining how to refresh the denylist ships with it. Install hygiene is documented rather than enforced blindly: installs stay lockfile-only in continuous integration and in agent worktrees, new direct dependencies prefer exact pins, and a blanket refusal to run install scripts is not turned on without an allowlist and a green build behind it.

## Why now is cheap

**Nothing here needs investigating.** Every defect is enumerated, quoted and located. W01's five have been findable-but-unowned through two review generations; W02's list came out of walking a real design run; W03 and W04 were met by a run passing through the code rather than by anyone reading the files.

**Most of it is small.** The registry entry is minutes. The declared switch is one field and its readers. Two of W02's entries are name alignments.

**W02 pays a second time.** The defects it fixes — a value nothing produces, a declared type every reader disagrees with — are the same class that #527 E03's conversion of all 122 activity definitions would otherwise meet one at a time. A sweep that knows what it is looking for is much cheaper than a conversion discovering them individually.

**W06's cost is asymmetric.** It is not failing today and the dependency scan came back clean. It is the shape where the next occurrence is expensive and the fix is to make it fail loudly rather than quietly.

## Non-goals

- **Whether concurrent execution should be a named, bound structure.** W01 fixes the suite runner's contradiction as a contradiction between two pieces of text. Whether that structure should be bound rather than described is **I01 E03**, which retargets the same call site — whichever of the two lands second inherits the other's resolution.
- **A guard for every class fixed here.** The one that can be caught mechanically already is, and W04 adds the one that prevents its own recurrence. Nothing else here gets a guard built for it.
- **The engine change.** Nothing in this epic is gated on any phase of #527, and none of it blocks one.
- **A blanket refusal to run install scripts.** Not turned on without an allowlist and a green build behind it.
- **Action pinning and automated-bump cooldown.** Available as follow-ons; not in this epic.

**This epic is complete.** Six items: five delivered, one closed without a change.

**W02 could not be costed until its first action ran, and what that reported is most of the item.** The binding guard read clean — every finding triaged, no live bugs, nothing untriaged — against verdicts made 302 corpus commits earlier, and nothing in the instruments distinguished a completed sweep from a guard that could no longer see. Re-stamping the verdicts was therefore the first action, and it was bounded by the drift rather than by the ledger: of the sixty-nine entries, nineteen cited a file that had changed since the stamp, and that intersection held the answer.

Most of the enumerated list had closed under the intervening commits. What survived was the trace-token relay, and it was wired all along — the dispatch operation declared the single token it captures internally rather than the accumulated list it hands to the close-out path, so the guard reported a dead output that nothing could consume. The declaration now names the list, which closed the finding rather than moving it.

The sweep also found the ledger wrong about itself in ways nothing compared: two entries cited lines their findings no longer sat on, and four of twelve rationales were cited by no entry at all. Both are now checked — a `misplaced-triage` finding in the guard, and the vocabulary in a test.

**W03 is closed without a change, because the defect it was scoped from does not exist.** The item read
the activity's exits and found no route for a second pass. The loop that returns to the activity is the
missing half: it runs while the comprehension flag holds, so the flag is false at every exit a second
pass reaches, and the activity guards its own re-entry. Scoping this from the exits alone, without the
condition governing them, is what produced the item — the exits are only correct relative to the entry.
