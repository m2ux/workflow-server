## Overview

This epic defines what "reliable workflow design" means and measures it. It sets a fixed set of design briefs, three measures and agreed thresholds. The initiative is done when an agent working from the workflow-design skill meets them.

## Problem

Nothing defines the goal this initiative serves. The skill's sufficiency test counts rule violations and nothing else, so:

- it cannot tell a conforming but poorly designed workflow from a good one;
- it cannot tell a well-formed workflow that does the wrong thing from one that does what was asked;
- there is no fixed task set to compare conditions against, and no threshold to meet;
- whether the skill needs a design method, meaning how to get from an objective to activities, checkpoints, routines and fans, is untested.

## Proposal

- **Briefs.**
  A fixed, held-out set of design briefs spanning the constructs: fan, routine, checkpoint, loop and child workflow. Each brief states its outcomes as assertions a walk can check: an activity is reached, a variable is set on every path to the end, an artifact is declared on a path.
- **Measures.** Three:
  - **Conformance:**
    blocking findings after the validator loop, and the number of iterations taken.
  - **Quality:**
    anti-pattern findings per workflow from a named audit instrument, judged without knowing the condition. The instrument is calibrated on workflows with seeded faults before the first run, with its detection rate recorded. It is independent of the skill under evaluation: it neither loads that skill nor shares its routing.
  - **Fitness:**
    whether a walk of the workflow satisfies each outcome assertion its brief states.
- **Thresholds.**
  Agreed before the first run.
- **Conditions.** Five:
  - a baseline with no skill, measured at the pre-migration tags (`main/v0.29.0`, `workflows/v0.33.0`), because the language migration removes the homes it measures;
  - formal files alone;
  - with the reference entries;
  - with the validator;
  - with a design method.
- **Runs.**
  Each condition runs repeatedly, and variance is recorded.
- **Design method.**
  It enters the skill only if it moves the measures.

## Acceptance Criteria

- [ ] **AC1.** A held-out brief set covers fan, routine, checkpoint, loop and child workflow, each brief's outcomes stated as walk-checkable assertions.
- [ ] **AC2.** Conformance, quality and fitness measures, with thresholds, are recorded before the first run.
- [ ] **AC3.** A baseline without the skill is recorded at the pre-migration tags.
- [ ] **AC4.** Each skill condition is run repeatedly, and its measures and variance are recorded.
- [ ] **AC5.** The design-method question carries a verdict backed by the measures.
- [ ] **AC6.** The shipped skill meets every threshold.
- [ ] **AC7.** The quality audit instrument is named, independent of the skill, and calibrated on seeded faults, with its detection rate recorded before the first run.
- [ ] **AC8.** Fitness is measured with the server's draft walker.
- [ ] **AC9.** The skill carries a design method only if the method moved the measures.
