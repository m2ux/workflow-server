## Overview

This epic verifies a draft definition before it merges: checked, walked and model-checked, with findings reported by rule id and the fix each rule states. A designing agent confirms its work against this rather than relying on its interpretation of the spec.

## Problem

Every check that exists today is static, runs against the corpus, and lives in the build:

- The loader and guards accept a draft whose gates can never open, or whose paths never end.
- They accept a fan whose branches never join, and a variable read on a path where nothing writes it.
- A path walker exists, but only as a test utility: `tests/e2e/walker.ts`, driven by `all-workflows-walk` and `option-coverage`.
- Gate liveness exists in `src/utils/gate-liveness.ts`, but nothing runs it on a draft outside the corpus.
- The constraint model from E01 describes how a session behaves, but nothing checks a specific draft against it.

## Proposal

One validation entry point, exposed as an MCP tool and an npm script, takes a draft definition, including one outside the corpus. It runs four stages:

1. **Static:** the loader and every registered check.
2. **Walked:** every path of the draft. Every activity is reachable, every path terminates, every fan joins, every checkpoint option is reachable, and every variable is written before any path reads it.
3. **Cost:** the draft's delivery cost, against the limits from E03.
4. **Model-checked:** the draft is translated into an instance of the runtime model and checked against its temporal properties, within a stated bound.

Each finding names its rule id and that rule's fix. A draft is validated against the `language/vX.Y.Z` tag the server declares ([E00](https://github.com/m2ux/workflow-server/issues/943) W02), and the report names that tag. Corpus CI runs the static, walk and cost stages on each workflow a corpus change touches, before it merges.

## Acceptance Criteria

- [ ] **AC1.** A draft outside the corpus can be validated through an MCP tool and an npm script.
- [ ] **AC2.** Every finding names a registered rule id and that rule's fix.
- [ ] **AC3.** The walk reports any unreachable activity, non-terminating path, unjoined fan, unreachable checkpoint option, or variable read before any path writes it.
- [ ] **AC4.** Delivery cost is reported against the registered limits.
- [ ] **AC5.** A draft is model-checked against the runtime model's temporal properties, and the report states the bound.
- [ ] **AC6.** Every corpus workflow validates clean, or its findings are recorded with a disposition.
- [ ] **AC7.** A corpus change measures its own coverage, walks, and delivery cost before it merges.
- [ ] **AC8.** Static validation of a draft runs the loader and every registered check.
- [ ] **AC9.** A change to the path walker runs the coverage walk.
- [ ] **AC10.** Corpus CI statically validates each workflow a change touches before it merges.
- [ ] **AC11.** An end-to-end test calls the draft-verification MCP tool through the real server on a fixture draft outside the corpus and asserts a result from each of the four stages.
- [ ] **AC12.** An end-to-end test runs draft verification on each conformance fixture and fails when a finding's rule id does not resolve to a reference entry that states its fix.
