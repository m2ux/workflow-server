## Overview

This epic holds every `inspect_session` projection to a result its caller can read. A call asking what a session holds under a name the bag does not hold answers with that absence, so a caller reads the finding rather than a protocol error, and a name held as an empty value stays distinguishable from a name held not at all.

## Problem

- **An absent variable answers with a schema violation.**
  `inspect_session { session_index, view: "variables", variable: "no_such_variable_xyz" }` returns `MCP error -32602: Invalid tools/call result`, whose detail is `expected string, received undefined` at `content.0.text`. The call is well formed and the session is valid.
- **The caller cannot tell absence from failure.**
  The error names a union mismatch across every content kind the protocol admits, and nothing in it says the variable was not in the bag, so a caller reads a transport or server fault where the honest answer is that the name holds nothing.
- **An empty value answers correctly, so the two cases diverge.**
  The same call for a variable the bag holds as an empty array returns `[]`. Only a name the bag does not hold at all produces the malformed result, so the shape of the answer turns on whether the key exists rather than on what it holds.
- **It fires on a name the engine's own definitions read.**
  The meta workflow's `end-workflow` reads `target_workflow_outcomes`, which no step writes, so an orchestrator inspecting that name during close-out meets this error on a healthy session.

## Proposal

- **An absent variable is an answer, not a fault.**
  The projection returns a content item stating that the name holds nothing, so the result validates and the caller reads absence as the finding it is.
- **Absence and emptiness stay distinguishable.**
  A key the bag holds as an empty value keeps answering with that value, so a caller that must tell the two apart can.
- **Every projection path returns a content item that validates.**
  A result the server composes satisfies the schema on every branch, so no input produces a union mismatch in place of an answer.
