## Overview

This epic names the structure a workflow definition compiles to, and has the loader emit that structure for all 18 workflows and 132 activities. The runner is built against that structure.

## Problem

Everything after this epic reads a workflow mechanically — a program walks it, a build compiles it, a checker types it. None of that can start until there is one agreed structure for what a definition is, separate from the file format it is written in today. Nothing outside the loader should depend on how definition files are loaded.

## Proposal

Record the two already-settled decisions — a step's results land when the step finishes, and a step identifier is unique within an activity — and name the resolved tree. Have the loader emit that tree. A walk against it reproduces today's walk. Named runs live on #704 and materialise into ordinary steps, which is the shape the tree already holds.

The resolved tree is the materialised form [Formal Specification](https://github.com/m2ux/workflow-server/issues/937) specifies. It is written on the `language` branch and versioned by its `language/vX.Y.Z` tag.

## Acceptance Criteria

- [ ] **AC1.** A written decision records when a step's declared results reach the session, with its evidence.
- [ ] **AC2.** A written decision records how a position inside an activity is identified, with its evidence.
- [ ] **AC3.** The resolved tree is specified and versioned.
- [ ] **AC4.** Nothing outside the loader depends on how definition files are loaded.
- [ ] **AC5.** The loader emits the named tree for all 18 workflows and 132 activities.
- [ ] **AC6.** A walk against that tree reproduces the existing walk — same transitions, same artifacts, no more delivered characters.
- [ ] **AC7.** The whole guard suite passes over the corpus loaded through the named tree.
- [ ] **AC8.** The delivery baseline is the record taken from the walk, shown by a diff that distinguishes it from a regeneration of the previous baseline.
