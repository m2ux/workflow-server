## Overview

This epic gives the end-to-end walker a mode that drives the runner, and runs the all-workflows walk on the program path. That walk is the instrument for three of the initiative's criteria: every gate decided from session values, every call-out asking for judgement, writing or a question, and no dispatch carrying grading or driving instruction.

## Problem

The all-workflows walk checks that the graph loads, not that a program can walk it.

- **Graph mode only.**
  `tests/e2e/all-workflows-walk.test.ts` walks each workflow with `mode: 'graph'` and `autoAdvance` (line 54). In graph mode the walk executes no steps, so `stepsExecuted` is empty for every workflow (lines 18–23).
- **Gates answered by the walker.**
  `autoAdvance` satisfies forward gate conditions toward unvisited activities by writing the variables itself (`tests/e2e/walker.ts` lines 210–217, `advanceToUnvisited` at line 316). A gate the session cannot answer passes unnoticed.
- **No runner in the walker.**
  The walker's step mode, `robot`, walks steps itself and makes one pass through a loop body, leaving iteration to the runner (`tests/e2e/walker.ts` lines 613–619). Nothing in it calls the runner or records what an agent would be asked for at each step.
- **Dispatches measured, not kept.**
  The walker keeps only the length of each `get_activity` response (`tests/e2e/walker.ts` line 382), so no test can search what a dispatch carried.

## Proposal

- **Walker drives the runner.**
  A walker mode hands each activity to the runner published by [Mechanical Execution](https://github.com/m2ux/workflow-server/issues/532) and answers each call-out with a stub, so a walk runs without an agent.
- **All-workflows walk on the program path.**
  The all-workflows walk runs every workflow the corpus holds in that mode, beside its graph-mode run.
- **Assertions over the walk.**
  The walk fails on a gate left unanswered, on a call-out asking for anything but judgement, writing or a question to a person, and on a recorded dispatch carrying a withheld grading or driving block.
- **Boundary.**
  [Mechanical Execution](https://github.com/m2ux/workflow-server/issues/532) owns the runner, the call-out contract and the list of withheld blocks. This epic owns the walker mode and the assertions that read them.

## Acceptance Criteria

- [ ] **AC1.** The walker has a mode in which the runner walks each activity and a stub answers every call-out.
- [ ] **AC2.** The all-workflows walk drives every workflow the corpus holds on the program path.
- [ ] **AC3.** The all-workflows walk on the program path fails when any gate is left unanswered.
- [ ] **AC4.** The walk logs every call-out with the kind of the step that makes it.
- [ ] **AC5.** The all-workflows walk on the program path fails on any call-out that asks for something other than judgement, writing or a question to a person.
- [ ] **AC6.** The all-workflows walk records every dispatch the server sends it.
- [ ] **AC7.** The all-workflows walk fails when a recorded dispatch carries a block on the list of withheld grading and driving blocks.
