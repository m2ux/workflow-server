## Overview

This epic replaces the agent as the runner. A program walks the steps, decides each test, drives the loops, and resolves what each step consumes. An agent is called for judgement, writing, and putting a question to a person.

## Problem

Today a language model reads the definition and carries it out, guided by prose the server ships alongside it, and the server grades what the model reports back. About 33,000 characters of every dispatch exist only to teach the model that mechanical job. The server cannot yet walk the definition itself.

## Proposal

Publish a runner against the resolved tree. The server derives every transition independently, warns, then refuses once the disagreement rate over real sessions is known. Withhold graders and driving instructions from the new path first. Move surviving rules to where they belong. Keep orchestrator-only rules out of a worker's bundle.

## Acceptance Criteria

- [ ] **AC1.** A program walks an activity's steps, decides each test from the session, and drives iteration.
- [ ] **AC2.** A program calls out per run of steps ending at the first test the session cannot answer.
- [ ] **AC3.** The session carries a durable position with a frame per enclosing loop.
- [ ] **AC4.** A resumed run continues at the next step rather than re-entering the activity.
- [ ] **AC5.** A cycle bounded by a count advances that count mechanically, including a cycle that runs between two activities on an exit predicate.
- [ ] **AC6.** The server derives every transition independently.
- [ ] **AC7.** A stop an agent reports at a test is accepted only when the server recomputes the same verdict from the values returned.
- [ ] **AC8.** The disagreement rate between the server's derivation and the reported outcome is reported over real sessions before any transition is refused.
- [ ] **AC9.** A call-out returns values keyed by declared identifier.
- [ ] **AC10.** A return whose shape disagrees with the declared signature is rejected while its content is trusted absolutely.
- [ ] **AC11.** Resolved input values travel separately from the instruction body.
- [ ] **AC12.** The instruction body stays a pure function of the corpus, and delivery still deduplicates it by content.
- [ ] **AC13.** No grading check is removed while any workflow still runs the current way.
- [ ] **AC14.** No driving instruction is removed while any workflow still runs the current way.
- [ ] **AC15.** Each grading check and driving instruction is withheld from the new path first.
- [ ] **AC16.** At least one workflow completes a production run under each path, against the same server build, accepted by the same check.
- [ ] **AC17.** Every rule body on the two most-delivered surfaces states a constraint, an invariant, or a prohibition.
- [ ] **AC18.** Each procedure removed from those surfaces is present at a named destination.
- [ ] **AC19.** The two named surviving clauses survive the deletion.
- [ ] **AC20.** No orchestrator-only rule appears in a worker's bundle.
- [ ] **AC21.** The per-dispatch saving from dropping orchestrator-only rules is reported.
- [ ] **AC22.** The cost of one agent exchange and of establishing a fresh context is re-measured and recorded where W01 reads it.
- [ ] **AC23.** Every workflow in the corpus runs on the program path, and the agent-driven path's grading checks and driving instructions are removed.
- [ ] **AC24.** An end-to-end fixture walk drives a count-bounded cycle between two activities on an exit predicate and stops at its declared limit.
- [ ] **AC25.** The definitions this epic changes carry no outstanding confirmed finding, as the canon audit's coverage report shows.
