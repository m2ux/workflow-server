## Overview

This epic makes the session a record that is only ever appended to. State is what you get by replaying it.

## Problem

A session's state lives in a file the server rewrites on every call, with a sealed envelope beside it binding those exact bytes to the server's signing key. Resuming a run rebuilds it instead of continuing it. A rotated key reads as tampering. Continuing a run that already exists is hard to get right (R3).

## Proposal

Replace the rewritten snapshot with a chained, appended record. A rotated or lost signing key fails the authorship claim and leaves the content readable. Continuation replaces refusal. A failed key write reports the underlying failure.

## Acceptance Criteria

- [ ] **AC1.** The session is an appended, chained record and state is a fold over it.
- [ ] **AC2.** No entry is rewritten.
- [ ] **AC3.** A rotated or lost signing key is reported as a failure of the authorship claim, with the content still readable.
- [ ] **AC4.** An authorship failure is distinguishable from a record that does not verify.
- [ ] **AC5.** The durable position, with a frame per enclosing loop, lives in the record.
- [ ] **AC6.** A fold reaches a resumable place.
- [ ] **AC7.** No throwaway session is created and then promoted.
- [ ] **AC8.** No process-local registry exists.
- [ ] **AC9.** A second dispatch into a folder holding a running child continues that child, with position, completed activities, and variables intact.
- [ ] **AC10.** A finished child is not resumed.
- [ ] **AC11.** A continued run is visible as such in the response and in the folder's history, distinguishable from a first dispatch.
- [ ] **AC12.** A position naming an activity the resumed workflow does not declare does not strand the run.
- [ ] **AC13.** A run abandoned at an unanswered gate is continued, or refused with the reason stated.
- [ ] **AC14.** The identifier handed back resolves independently of the folder's location.
- [ ] **AC15.** Arguments passed on a continuation are honoured rather than ignored.
- [ ] **AC16.** A failed key write reports the underlying failure whatever its cause.
- [ ] **AC17.** The two hard-to-provoke key-write cases are covered by injection.
- [ ] **AC18.** A continuation starts a new child beside the finished ones, each prior child keeping its place.
- [ ] **AC19.** An end-to-end test replays the session record after a second dispatch into its folder and finds every entry byte-identical.
- [ ] **AC20.** An end-to-end test replays the session record after a rotated signing key and finds every entry byte-identical.
- [ ] **AC21.** An end-to-end test replays the session record after a lost signing key and finds every entry byte-identical.
- [ ] **AC22.** A hard-gate response with no presentation event before it is reported against the session, as a walk that answers a hard gate without presenting it shows.
