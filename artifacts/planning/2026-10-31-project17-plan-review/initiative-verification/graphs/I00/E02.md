## Overview

This epic lands a step's declared outputs when the step finishes, derives the set of names that step may write, and gives the session store an index or a cache so those writes are affordable.

## Problem

A step's results reach the session, in the main, only when its whole activity finishes. More than half of every condition asks about something produced inside the activity it sits in — 274 sites against 194 fed by an earlier activity. The committed baseline records 313 conditions the server could not yet answer across 79 activity deliveries, and not one delivery that answered every condition it carried. The store reads and parses every session file on every call, against roughly 1,085 writes per run.

## Proposal

Index or cache the session store. Fail the load when two steps in different loop bodies of one activity share an identifier. Land a step's declared outputs when the step finishes. Refuse a produced value outside the derived write set. Apply the missing-value rule on the evidence of the recorded number-conversion list.

## Acceptance Criteria

- [ ] **AC1.** A session lookup by identifier does not parse every session file.
- [ ] **AC2.** No per-call path pays the walk-every-file cost.
- [ ] **AC3.** The load fails when two steps in different loop bodies of one activity share an identifier.
- [ ] **AC4.** A step's declared outputs are in the session bag when that step finishes.
- [ ] **AC5.** A produced value falling outside the derived write set is refused, with the reason named.
- [ ] **AC6.** The accepted names, rejected names, and values delta come back on the same call.
- [ ] **AC7.** A missing value fails a positive test, on the evidence of the E00 W04 list.
- [ ] **AC8.** A negative test passes when the asserted value is absent, shown by the fixture walk of the missing-value list.
- [ ] **AC9.** A presence test fails when the asserted value is absent, shown by the fixture walk of the missing-value list.
