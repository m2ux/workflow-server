## Overview

This epic composes every deliverable block ahead of any session and addresses it by a hash of its own bytes, so handing out work is naming addresses and sending only the bytes the recipient does not already hold.

## Problem

When the server hands an agent its next piece of work, it builds that payload on the spot. It annotates each step by re-reading instruction sets from disk, once per inlined step. Then it sends the result, and if the recipient already holds most of it, a separate mechanism tries to notice. The same block appears twice in one response. A repeated request is answered in full. An activity body cannot collapse when everything around it can. Composition is redone on every request.

## Proposal

Compose each instruction set at most once per delivery. Compose the corpus ahead of any session, addressed by content. A delivery names addresses and sends only what is missing. The bodies a call names arrive with the caller. The setup ceremony produces one commit. Path cost is computed by the delivery-cost measure [Execution Model](https://github.com/m2ux/workflow-server/issues/939) registers, applied to the compiled corpus.

## Acceptance Criteria

- [x] **AC1.** A single delivery composes each instruction set at most once.
- [x] **AC2.** The annotation output is byte-for-byte unchanged, with a regression test counting composition runs.
- [ ] **AC3.** Composition happens ahead of any session.
- [ ] **AC4.** Every deliverable block is addressed by a hash of its own bytes.
- [ ] **AC5.** No byte-identical block appears twice in one response, against a worst case of 16,453 characters measured today.
- [ ] **AC6.** A context that asks twice for the same instruction set or resource receives the second answer as an address.
- [ ] **AC7.** A regression test asks twice and measures what came back, against a baseline of 18 repeats and 67,772 characters in one measured run.
- [ ] **AC8.** A resumed delivery returns the activity's identity in full and the remainder as addresses where the bytes are unchanged.
- [ ] **AC9.** The dispatched-activity confirmation still has an identifier to check on every path.
- [ ] **AC10.** A forced full delivery is unaffected, against a measured body share of 38.4% and a range of 17% to 95%.
- [ ] **AC11.** The cost of a path can be computed from the compiled corpus without running it.
- [ ] **AC12.** The bodies a call names arrive with the caller, deduplicated, transitively followed, and tolerant of a walk that returns to a body already reached.
- [x] **AC13.** The setup ceremony produces one commit, shown by a re-measurement by the recorded method.
- [ ] **AC14.** Re-delivered characters are reported against 677,132 characters at gate crossings, plus 1,109,551 on same-identity resumes that re-delivered a byte-identical payload.
- [ ] **AC15.** The definitions this epic changes carry no outstanding confirmed finding, as the canon audit's coverage report shows.
