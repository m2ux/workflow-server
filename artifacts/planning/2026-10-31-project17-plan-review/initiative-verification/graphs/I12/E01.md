## Overview

This epic makes the configured corpus a list. The server takes several labelled roots from its command line and its environment, carries them through the resolved configuration, and resolves every definition lookup through the index of all of them. A readiness probe names each root the instance serves and the commit behind it, so an operator reading the probe can tell which corpora answered a call. A configuration that names several roots without labelling each is refused rather than served.

## Problem

The configuration names one tree, and the instance reports one tree.

- **One path is resolved.**
  [`resolveWorkflowDir`](https://github.com/m2ux/workflow-server/blob/62ee9612c0649c0a99653cdf2ab2ff5469b43be6/src/config.ts#L575-L581) returns a single directory from the flag, the environment or the default, and `workflowDir` is a string throughout the resolved configuration.
- **Every lookup receives that one path.**
  The loaders and tools take `workflowDir` and build an index from it, so a second tree reaches a lookup only by sitting inside the first.
- **The readiness report describes one bind.**
  [`describeCorpus`](https://github.com/m2ux/workflow-server/blob/62ee9612c0649c0a99653cdf2ab2ff5469b43be6/src/transports/http.ts#L105) answers with one directory, one host directory and one [`corpusPin`](https://github.com/m2ux/workflow-server/blob/62ee9612c0649c0a99653cdf2ab2ff5469b43be6/src/config.ts#L81-L85), and two roots stand at two commits.

## Proposal

- **The configuration carries a list.**
  The flag and the environment variable each accept several labelled roots, and the resolved configuration holds them in the order given.
- **An unlabelled root is refused.**
  A configuration naming more than one root without a label for each is refused at load, naming the root it cannot label, so a path qualifier is never guessed.
- **Lookups resolve through the union.**
  Each lookup resolves through the index of every configured root, which is the value those lookups already accept.
- **The probe names each root.**
  The readiness report carries an entry per root: its directory, its host directory where a bind source was given, and the commit behind it.
