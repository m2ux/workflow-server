## Overview

This epic gives the language's checker a rejecting case for every rule it holds: a fixture set the checker must reject, and a harness that fails when it accepts one. It exists so each initiative criterion that a checker rule meets is shown by a rejection, not stated.

## Problem

- **No fixture set targets a checker.**
  The 59 `check-*.ts` guards in `guards/` are tested one at a time: each of the 22 `tests/*-guard.test.ts` files seeds its own fixtures for a single guard. No harness runs a checker over a set of cases it must reject, and none of E00's criteria names one.
- **The disclosure analysis has no suite to replay.**
  `guards/check-stealth-isolation.ts` (`check:stealth`, 282 lines) has no test file of its own. The only test that names it, `tests/guard-registry.test.ts`, checks its registration, so no recorded set of the cases it rejects exists to hold the ceiling against.
- **Effects, presets and alternatives have no rejecting cases.**
  Kinds of effect, presets and alternative sets are E00 constructs, so no fixture exercises a step exceeding its ceiling, a preset leaving an activity unreachable, or a selection violating an alternative set.

## Proposal

**One harness, one fixture per rule.**
A harness compiles each fixture in the rejecting set and fails when the checker accepts it. Each task adds the fixtures for one kind of rule: every kept rule, every kind of effect, both directions of alternative selection, a preset leaving an activity unreachable, and every case `check:stealth` rejects.

**The stealth suite comes first from the guard.**
The cases `check:stealth` rejects are captured as fixtures from the guard itself, so the ceiling is held to the analysis's own record.

**Ownership.**
[E00](https://github.com/m2ux/workflow-server/issues/535) builds the checker, its rules and the whole-corpus compile. This epic owns only the fixtures the checker must reject and the harness that asserts each rejection.

## Acceptance Criteria

- [ ] **AC1.** A harness compiles every fixture in the rejecting set and fails when the checker accepts one.
- [ ] **AC2.** Every kind of effect has a fixture whose step exceeds the workflow's declared ceiling by that kind, and compiling rejects it.
- [ ] **AC3.** Every direction of alternative selection has a fixture that violates it, and the checker rejects it.
- [ ] **AC4.** A fixture preset leaving an activity unreachable is rejected by the checker's per-preset reachability check.
- [ ] **AC5.** Every case `check:stealth` rejects is captured as a fixture.
- [ ] **AC6.** The disclosure ceiling rejects every captured stealth fixture.
- [ ] **AC7.** Every rule whose verdict is kept has a violating fixture that the checker rejects.
