## Overview

This epic gives the GitHub operation library the write surface that board-driven workflows need: replacing a label within a family, where board convention keeps exactly one label per family, and reading and writing project-board fields.

## Problem

- **Labels only append.**
  The library's only label operation appends, so a workflow that must change a label within a family cannot express the replacement.
- **No project fields.**
  Nothing in the library reads or writes a GitHub Projects item field.

## Proposal

- **Label families.**
  Label-family operations follow the library's existing rules: authored prose by file, and paginated list calls. A family transition lists the repository's labels, removes the current one, and replaces it, then re-reads the family to confirm the landed value.
- **Project fields over REST.**
  Board access uses GitHub's Projects REST endpoints: listing a project's fields and items, adding an item, and updating an item's field values, single-select by option id. Every call is REST.
- **Confirmed writes.**
  Every write is validated against a dedicated scratch board and confirmed by post-write re-read.
- **Boundary.**
  The library does not operate on issue types or milestones, and it makes no GraphQL call.
