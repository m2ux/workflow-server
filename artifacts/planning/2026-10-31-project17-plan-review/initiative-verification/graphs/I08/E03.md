## Overview

This epic moves operations that are generic capability out of the workflow families that trap them, and corrects construct grain where content sits in the wrong primitive.

## Problem

Toolchain probes and per-checkout revision steps are still written inside the workflows that use them. The canon names this misplacement: a reusable primitive trapped in a client workflow.

A library's own operations disagree about the state they describe: `git::read-working-state` records `git status --porcelain` output as the tracked paths it names, while `git::pin-revision` refuses the pin wherever that command prints a path. A tree carrying untracked files alone records nothing, so the `accept-discard` checkpoint in `git::ready-checkouts` does not fire and the pin that follows refuses a caller that was given no chance to clear it.

Seven `support/gitnexus` techniques take their answer from an MCP resource while every other reading in that namespace is a tool call, so those seven turn on a client capability the rest do not need. A client holding the library as tools alone runs the flow cycle in `area-comprehension` and lands nothing, and the declared output comes back empty with no statement that the reading could not be made.

## Proposal

A survey enumerates hoist candidates with a proposed destination library and a grain verdict for each — stays, hoists, or re-grains — reviewed before any move. Approved moves land as content-preserving relocations, one family at a time, referring workflows re-bound, each move naming the outcome that must survive and the check confirming it. Approved grain corrections apply the canon's tests: technique-to-routine where protocol iterates or stops for a person, prose-to-resource where content is consulted rather than performed.

workflow-design is deprecated and is not edited. `remove-worktree` and `write-artifact` stay under work-package because that workflow still binds them. `execute-sub-agent` stays in each audit, with its roster, briefs and `collect-results`, because the two copies assemble different outputs.

**Migrations, one family per branch**

1. Output files. `orchestration-patterns::verify-output-files` confirms each filename in `{expected_output_files}` under the planning folder. A missing file is re-dispatched to the worker that owns it. Substrate still passes its filename lists. The CI/CD audit names one file per scanner roster entry, then binds the same operation.
2. Planning README. `create-readme` gains an optional seed switch that omits the Links table, defaulting to a filled table, and `remediate-vuln` binds it.
3. Prism run record. One `accumulate-analysis-run` on `prism`. Both callers use `all_analysis_artifact_paths`. A `partial` or `error` run stays on the list.
4. Probes and revision pin. Midnight's GitNexus and cargo probes bind `support/gitnexus` and `support/cargo`. The midnight-node probe stays. Substrate's revision step binds `git::pin-revision`.

**Grain, on separate branches**

- workflow-authoring intake loops the dimension set and checkpoints each capture. The technique assembles the change brief.
- workflow-authoring yaml is one author pass and one validate pass inside a loop. Style rules move to a resource the technique cites, stating only what the language reference ([I07 E01](https://github.com/m2ux/workflow-server/issues/937)) does not.
- work-packages `prioritize-packages` and `assess-initiative-scope` emit a recommendation. The user choice is an activity checkpoint.
- work-package `review-scope` moves the `per-file-necessity` checklist into the review resource.
- Substrate severity domain floors move into `severity-rubric.md`. The scoring operations stay in each audit.

**One address for every reading in a namespace**

- Each `support/gitnexus` technique that reads a resource composes its answer over a tool the namespace already binds, so the library answers to a client holding its tools alone. A reading that could not be taken records that statement where its value would sit, which is a different answer from a reading that found nothing.

**One condition for a tree that cannot be pinned**

- The survey and the pin read the same condition, so the gate fires on exactly the state the pin refuses. Either the survey records untracked paths beside the tracked ones, or the pin ignores untracked paths; the choice is made once and both operations state it.

## Acceptance Criteria

- [ ] **AC1.** Every hoist candidate the survey names carries a destination library and a grain verdict in the survey record before any move, as that record shows.
- [ ] **AC2.** A missing expected worker file is re-dispatched to the worker that owns it by the one shared check both audits bind, as the corpus guard suite shows.
- [ ] **AC3.** Every site the survey approves that iterates or stops for a person is a routine or an activity checkpoint, as the canon grain guards show.
- [ ] **AC4.** Every site the survey approves that an agent consults rather than performs lives in a resource, as the canon resource guard shows.
- [ ] **AC5.** The links switch determines whether a planning README contains its Links section, as the links specimen shows.
- [ ] **AC6.** Both prism callers record a partial or error run through one shared operation on all_analysis_artifact_paths, as the sidecar walk shows.
- [x] **AC7.** Midnight's GitNexus and cargo probes and Substrate's revision step bind the shared library operations, as the guard sweep resolving each reference shows.
- [ ] **AC8.** The shared-operation guard fails when an operation that more than one workflow binds directly, with the same outputs, sits outside a shared library.
- [ ] **AC9.** A checkout carrying untracked paths and no tracked modification reaches the discard gate or is pinned, as a walk of `git::ready-checkouts` over such a tree shows.
- [ ] **AC10.** `git::read-working-state` and `git::pin-revision` state one condition for a tree that cannot be pinned, as a read of both techniques shows.
- [ ] **AC11.** The audit family’s conduct is one technique addressed by role, which its consumer binds and declares no copy of, as the duplicate-bodies guard reports nothing against the pair.
- [x] **AC12.** No technique in the `support/gitnexus` namespace takes its answer from an MCP resource, as a guard over that namespace's protocols shows.
- [x] **AC13.** A client holding the GitNexus library's tools and no resource reader takes a flow's ordered trace, as a walk of `area-comprehension` under such a client shows.
- [x] **AC14.** A reading that could not be taken answers with that statement in place of its value, as that walk's run trace shows.
