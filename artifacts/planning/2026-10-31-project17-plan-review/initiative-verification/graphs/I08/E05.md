## Overview

This epic walks each library conformance specimen with a real worker through the smoke orchestrator, and asserts what its conformance report claims. The initiative's pin, readiness and reach criteria are each shown by a smoke run, and the smoke infrastructure cannot yet run any of them to a checked result.

## Problem

The specimens exist on `workflows` (`corpus/specimens/git-pin-conformance/`, `corpus/specimens/gitnexus-radius-conformance/`), and `tests/smoke/smoke-orchestrator.ts` drives any workflow a real worker can walk (`--workflow=`, `--full`). No smoke run can land what the criteria claim:

- **One commit, no tag.**
  `setupSandbox()` in `tests/smoke/smoke-orchestrator.ts` creates the target with `git init` and a single `init` commit. The git-pin specimen needs a branch, a tag and more than one commit to land each kind.
- **No session inputs.**
  The orchestrator calls `start_session` with only `workflow_id`, `agent_id` and `planning_folder`. The git-pin specimen needs the repository its checkouts are worktrees of.
- **Workflow server only.**
  `tests/smoke/worker-mcp.template.json` names one server, `workflow-server`, and `runWorker` passes `--strict-mcp-config`, so a worker has no GitNexus server for the radius run.
- **No indexed group.**
  No fixture repository group under `tests/fixtures/` is indexed for the radius specimen to measure reach across.
- **No report assertions.**
  The orchestrator checks the session contract (`guards/check-session-contract.js`) and writes a transcript, but reads nothing from a specimen's conformance report.

The evidence for these criteria is one-off sidecar walks recorded on [#880](https://github.com/m2ux/workflow-server/issues/880) and [#881](https://github.com/m2ux/workflow-server/issues/881).

## Proposal

- **Smoke infrastructure.**
  The target is seeded with a branch, a tag and several commits. The orchestrator passes a specimen's session inputs at `start_session`. A run names the extra MCP servers its worker needs, and the worker config carries them beside the workflow server. A fixture repository group is indexed for smoke runs.
- **Report assertions.**
  Each specimen registers assertions over its conformance report, and the orchestrator fails a run whose report breaks one.
- **Recorded runs.**
  One smoke run per specimen, its assertions passing, is recorded on this epic.
- **Ownership.**
  The library epics own the operations and the specimens. This epic owns the smoke infrastructure, the assertions and the recorded runs.

## Acceptance Criteria

- [ ] **AC1.** The smoke target holds a branch, a tag and more than one commit.
- [ ] **AC2.** The smoke orchestrator passes a specimen's session inputs to `start_session`.
- [ ] **AC3.** A smoke run's worker config carries every extra MCP server the run names, beside the workflow server.
- [ ] **AC4.** A smoke run can measure reach across an indexed group of fixture repositories.
- [ ] **AC5.** The smoke orchestrator fails a run whose specimen conformance report breaks an assertion registered for that specimen.
- [ ] **AC6.** A recorded git-pin-conformance smoke run passes the assertion that a branch, a tag and a commit each land at the commit the name resolves to.
- [ ] **AC7.** A recorded git-pin-conformance smoke run passes the assertion that its checkouts stand at distinct revisions side by side.
- [ ] **AC8.** A recorded git-pin-conformance smoke run passes the assertion that an unresolvable name is refused with the checkout left at the earlier pin's commit.
- [ ] **AC9.** A recorded gitnexus-radius-conformance smoke run passes the assertion that every group member has a row naming its graph and instrument.
- [ ] **AC10.** A recorded gitnexus-radius-conformance smoke run passes the assertion that every reach no graph holds an edge for is settled by a recorded search of the member's tree.
