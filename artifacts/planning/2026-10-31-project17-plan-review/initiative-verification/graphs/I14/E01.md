## Overview

This epic holds the checks to the subject they measure: a guard reports a finding only where the corpus carries the defect, and a walk model reads every step the definitions hold. A check that misreads its subject costs twice — once in the work spent on a defect that is not there, and once in the defect it passes over.

## Problem

- **A guard counts a recorded roster as unrecorded.**
  The declared-values guard reads [the backticked spans of a step's text](https://github.com/m2ux/workflow-server/blob/2469b814/guards/check-declared-values.ts#L29-L30), so a protocol phase that sets an output from its `#### values` records nothing. The contract-not-procedure entry wants that roster on the output alone, so a phase written to one rule fails the other.
- **A walk model tolerates a step it does not model.**
  The activity-loop walk [applies an effects table per body step and lets a miss pass](https://github.com/m2ux/workflow-server/blob/db95c384/tests/batch-loop-walk.test.ts#L289). The commit step returns nothing where `persist-activity` returns `push_landed`, so every walk ends on its first activity with the push read as failed. Twenty tests fail across four files, and a renamed step that lost its row fails nothing at all.

## Proposal

- **A phase that names the roster records it.**
  The guard admits every member when a step names the output and its `#### values`, counts a citation of a different output as nothing, and still fails a phase that settles one sibling and leaves the others unnamed.
- **The walk model reads the body it stands for.**
  A body step with no row, and a row naming no step, each fail and name the step. A step deliberately left unmodelled says so in its row.
- **The suite is green against the corpus the definitions branch serves.**
  Every server test passes against that corpus, so a failure names a defect in what is measured rather than drift in the model doing the measuring.
