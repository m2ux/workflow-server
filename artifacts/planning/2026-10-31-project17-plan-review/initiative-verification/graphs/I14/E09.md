## Overview

A branch carries a verdict of its own only where a check runs on the commit a merge produced and concludes there. Three initiative integration branches carry a failing `Verify` run against their own pairing and have done since their last commits, and the coverage walk never runs on a corpus branch at all. A verdict that is red before any change lands, or absent altogether, tells a reviewer of that change nothing. This epic clears each failing branch at its cause or retires the branch that has nothing left to deliver, and gives the coverage walk the trigger that reaches the branch it grades.

## Problem

- **Every integration branch that exists concludes failure.**
  Measured 2026-10-13 from a `Verify` dispatched on each branch that day, so none of the results is stale:

  | Branch | Head | Run | Failing step |
  | --- | --- | --- | --- |
  | `i08/main` | `15f9a9b4` | [38379312188](https://github.com/m2ux/workflow-server/actions/runs/38379312188) | the test suite |
  | `i09/main` | `621642b5` | [38379315388](https://github.com/m2ux/workflow-server/actions/runs/38379315388) | the definitions-call-the-tools check |
  | `i10/main` | `f8fa1d3f` | [38379318718](https://github.com/m2ux/workflow-server/actions/runs/38379318718) | the test suite |

  `main` at `ec05e7f6` concludes [success](https://github.com/m2ux/workflow-server/actions/runs/38349583935), so the default branch is not the subject.
- **The causes are not one cause.**
  Two branches fail in their own suite against the corpus their initiative pins. The third fails on the pairing between its engine and its corpus, which is drift between two branches rather than a defect in either.
- **The heads are weeks old.**
  `i09/main` last moved on 2026-10-01 and `i10/main` on 2026-10-07. Each failure has stood since, unattributed to any change.
- **Each fix lands on a branch another initiative owns.**
  The correction for a branch is a change to that initiative's engine or corpus, so it carries that initiative's judgment about what the pairing should be.
- **The coverage walk has no trigger for the branch it grades.**
  [`coverage.yml`](https://github.com/m2ux/workflow-server/blob/workflows/.github/workflows/coverage.yml) declares `pull_request` and `workflow_dispatch`, and a merge into a corpus branch reaches neither, so a corpus branch's latest checkpoint-option reading is whatever was dispatched by hand.
- **Two clean pull requests can merge into a tip that is not clean.**
  A pull request walks only the workflows its diff can move, so two diffs that each walk clean can produce a tip whose roster has an unreached option, and no run states that. The guard sweep beside it is triggered by a push to a corpus branch, so its verdict already belongs to the tip a merge produced.

## Proposal

- **Each branch is diagnosed on its own run.**
  The failing suite is read against the corpus that branch pairs with, and the pairing failure against the two branch tips it compares. A cause is a fix on that initiative's branches or an issue that takes it.
- **A branch whose initiative is finished is retired rather than repaired.**
  An integration branch with nothing left to deliver is merged or deleted, and its red run goes with it.
- **A walk on the commit a merge produces.**
  `coverage.yml` is triggered by what reaches a corpus branch, so its latest run reads that branch's tip.

- [ ] **AC2.** The `i09/main` pairing failure is corrected on that initiative's branches or taken by an issue that names it, as a `Verify` run on that branch shows.
- [ ] **AC3.** The `i10/main` suite failure is corrected on that initiative's branches or taken by an issue that names it, as a `Verify` run on that branch shows.
- [ ] **AC4.** Each integration branch the repository holds concludes success on its latest `Verify` run, as those runs and the branch list show.
- [ ] **AC5.** The coverage walk concludes on a corpus branch tip, as the latest run on that branch for the commit at its head shows.
