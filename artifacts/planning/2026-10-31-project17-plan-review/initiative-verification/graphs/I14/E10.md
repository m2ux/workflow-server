## Overview

A guard states the defect class it measures, and a reader takes a clean run as that class being absent from the corpus. Where a guard's reach depends on the shape of the root it was handed, the same corpus answers differently at two of its roots and the clean run overstates what it covered. This epic holds a guard's checked set to the served corpus, so a pass means the same thing wherever the guard was pointed.

## Problem

- **A guard's reach turns on the layout of the handed root.**
  [`check-pinned-corpus-paths`](https://github.com/m2ux/workflow-server/blob/bf3be7b8a3190f02a56d84d89c50a9f63a952fb4/guards/check-pinned-corpus-paths.ts) decides a literal is a corpus pin partly by whether its leading segments name a directory the checkout holds. An overlay mounting the public corpus a level down holds those segments nowhere, so a pin checked at one root is skipped at the other.

- **A skip is indistinguishable from a pass in the count.**
  A skipped literal joins the tally of ids outside the corpus, which the clean run prints as reach. Two runs of one guard over one corpus report different checked counts and nothing names the difference.

- **The fixture exemption reads writes, not assertions.**
  The exemption covers a path handed to a call that writes a file. A path a test compares an assertion against is authored by the test in the same sense, and is not covered, so widening what counts as a pin draws those literals in as findings.

## Proposal

- **A guard's checked set is a property of the served corpus.**
  What a guard measures is decided by the index of the roots served, not by which of them the invocation named. Two runs over one corpus report one checked set.

- **A skip names its reason.**
  A literal outside the corpus and a literal a test authored are different reasons not to check one, and the clean run separates them so a reader can tell reach from exclusion.
