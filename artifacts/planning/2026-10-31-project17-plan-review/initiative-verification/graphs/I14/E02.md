## Overview

Dispatched units share the resources a session reaches for: one experiment sidecar serves every session that walks a specimen, with its corpus bind a single container-wide setting, and one scratchpad directory holds every session's working files. Two sessions running at once take the bind or the file name from each other, so a walk can be served definitions from another unit's worktree and a read-back can return another unit's bytes. This epic makes a taken bind visible in the record and gives each dispatched unit an instance and a scratchpad of its own.

## Problem

- **The pairing is fixed to one name and one port.**
  The [server-in-the-loop](https://github.com/m2ux/workflow-server/blob/d128062e0722f57a51d463694704653bd9efde9f/.claude/skills/server-in-the-loop/SKILL.md) skill fixes the container to `workflow-server-exp` on `32772`, with the MCP client pointed at that URL, and a reload moves the one bind.
- **A concurrent unit takes the bind mid-walk.**
  Delivering I01:E03:W03 against `shieldedtech/midnight-agent-eng`, two walks were served the sibling unit's corpus: the first returned `Activity not found` for an activity the branch declares, and the second returned a workflow `description` from the other branch. Both were detected only by reading the response.
- **Nothing says the instance is taken.**
  A reload prints the corpus it binds and does not say a session is standing on the previous one, and `/ready` reports the bind without reporting who asked for it.
- **A walk that is quietly reparented reads as a pass.**
  A miss is visible where the definition is absent; a walk against a tree whose definitions merely differ returns plausible output against the wrong corpus.
- **One scratchpad holds every session's working files.**
  The directory a session resolves is per-conversation, so every session a delivery run dispatches resolves the same one and nothing in the path distinguishes them. A session naming a file for what it holds picks the name its siblings pick, and one run observed two such files overwritten mid-task.
- **A file collision is silent at the point it matters.**
  The writer succeeds and the reader gets a well-formed file holding another session's content, so a session that does not re-derive the content has nothing to notice. Telling each session to prefix its files holds only while every brief says so.

## Proposal

- **A reload states what it displaces.**
  Where the instance it would rebind is serving another corpus, the reload names that corpus and the sessions standing on it before it moves the bind.
- **A walk records the bind it was served.**
  The corpus pin a walk cites is read back from the response that served it rather than from the reload that preceded it, so a bind taken mid-walk shows up in the record.
- **A unit's walk holds its own instance.**
  The pairing takes the unit's branch as the name and allocates the port, so two dispatched units never share a container.
- **The client reaches the instance the unit holds.**
  Whatever names the instance for the session names it for the MCP client too, so a walk reaches its own container without the skill's HTTP fallback.
- **A unit's working files are its own.**
  The scratchpad a dispatched session resolves is distinct per session, so two siblings writing one name write different files and each reads back what it wrote.
- **A collision that remains is refused rather than silent.**
  Where a shared location stands, a write that would replace another session's file fails at the write instead of at the read.
