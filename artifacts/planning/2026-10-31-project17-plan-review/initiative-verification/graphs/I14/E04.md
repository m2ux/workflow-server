## Overview

This epic turns four defect classes a reader finds into something that finds the next instance: an instruction that reaches a role that cannot act on it, a fallback stated only in a description, a rule that carries more than one constraint under one heading, and a triage verdict whose subject has changed under it.

## Problem

- **An instruction can require a call the role is barred from making.**
  The defect lives in the relationship between files, and every existing check reads one construct at a time. The same shape arises wherever a shared contract describes a call one of the roles is barred from making.
- **A fallback can live only in a description.**
  An input's description says what happens when no value arrives. The declaration carries no default. A caller that binds nothing gets nothing, and the sentence is the only record of what was supposed to happen.
- **The role check reads an orchestrator's refs from a roster that is gone.**
  [`guards/check-role-barred-calls.ts`](https://github.com/m2ux/workflow-server/blob/71459f89/guards/check-role-barred-calls.ts#L60-L67) imports three orchestrator sets `src/loaders/core-ops.ts` does not declare, so `tsc -p tsconfig.tools.json` exits there and the guard's test file fails to load.
- **The delivery-cost gate fails on a rise and passes on any fall.**
  [`run-token-benchmark.ts`](https://github.com/m2ux/workflow-server/blob/86d79e8a/benchmark/run-token-benchmark.ts#L176) compares against its reference in one direction, so a reference that ages downward is never reported. Measured 2026-10-13: the walk delivers 19980 characters against a baseline recording 61144, and the gate passes.
- **A triage verdict names no state of the corpus it was made against.**
  `canonical-home-map-triage.json`, `nested-output-home-triage.json`, `repeated-run-baseline.json`, `resource-statement-home-triage.json`, `section-framing-triage.json`, `unproduced-read-triage.json` and `unserved-operation-ref-triage.json` declare no `corpusSha`; only [`binding-fidelity-triage.json`](https://github.com/m2ux/workflow-server/blob/22434a13ad876292920feecb49565a4e5deebb09/ledgers/binding-fidelity-triage.json#L3) declares one. A definition can change under a suppressing entry that still matches its site, so the guard stays silent on text the judgement never saw. An entry matching nothing is reported as stale; an entry whose subject moved is not.
- **The one-invariant entry is outside the audit's scope.**
  [AP-156](https://github.com/m2ux/workflow-server/blob/6355c392/corpus/canon/resources/anti-patterns.md#L2289) names one invariant per rule. The [rule-hygiene audit](https://github.com/m2ux/workflow-server/blob/6355c392/corpus/workflow-design/techniques/audit-rule-hygiene.md#L33) walks `no-rule-protocol-restatement` through `no-one-step-rules` and does not name it.

## Proposal

- **Register the role check.**
  It reads the bundles each role receives, the unconditional prohibitions each role states, and the registered tool surface, then flags an instruction that turns on a call that role is forbidden to make, including an instruction to take a value from the call. A call named only in a conditional clause is not read as prohibited. It registers under the rule ids the [visibility rules](https://github.com/m2ux/workflow-server/issues/939) publish.
- **Register the fallback check.**
  It flags a description of an absent-value fallback whose declaration carries no default, and registers under a rule id the [formal specification](https://github.com/m2ux/workflow-server/issues/937) publishes.
- **Read an orchestrator's refs where they are declared.**
  Meta's `techniques.activity` and the role activity's step bindings are the two homes that declare them, so the orchestrator half of `ROLE_BUNDLES` names what an orchestrator is delivered and the typecheck completes.
- **Report a drift in either direction.**
  The gate names a difference beyond its threshold whichever way it falls, so a reference that has aged is reported rather than passed over, and the reference is re-recorded from what the walk delivers today.
- **Each ledger declares the commit its verdicts were made on.**
  A `corpusSha` field at the head of every triage ledger, in the shape `binding-fidelity-triage.json` already uses. A check reads each stamp, resolves each entry's cited site to a file, and exits non-zero where that file changed after the stamp; a site it cannot resolve and a ledger with no stamp are named the same way. Continuous integration runs it, so a stale verdict is reported by the run that makes it stale.
- **Walk the catalogue entry.**
  The rule-hygiene audit walks AP-156. The entry stays silent on a single constraint stated with the failure mode that makes it matter, and on successive paragraphs elaborating one constraint across two cases.
