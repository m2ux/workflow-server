## Overview

This epic makes one workspace command policy reach every harness an agent works in, and proves it reaches them. A common permission file and a shared evaluator replace policy expressed in one harness's configuration, each harness translates its own events through an adapter, and a session in each harness shows the decision taking effect on a tool call it issues.

## Problem

- **The policy is expressed in one harness's configuration.**
  146 of the command grants live in [.claude/settings.template.json](https://github.com/m2ux/workflow-server/blob/7485622d0102c583f11575c9846b523e408a74ff/.claude/settings.template.json), and [load_allow_rules](https://github.com/m2ux/workflow-server/blob/7485622d0102c583f11575c9846b523e408a74ff/hooks/compound-bash-allow.py#L205-L227) reads Claude's user, project and local settings to find them.
- **Shared locations hold harness-specific behaviour.**
  The seven scripts that settings template registers each weld command classification to Claude event decoding and Claude-shaped approval responses, so no other harness can reach the classifiers.
- **Codex receives rule text with no enforcement behind it.**
  [deploy-workspace.sh](https://github.com/m2ux/workflow-server/blob/7485622d0102c583f11575c9846b523e408a74ff/scripts/deploy-workspace.sh) renders Codex instructions and server connections and registers no hook, so no command check runs for a Codex session.
- **A registration is not evidence that a harness runs it.**
  A contract test shows an adapter decides correctly when it is called. Nothing shows a harness calls it, and a Codex hook stays inert until a person reviews it.
- **A change to the policy is a change in three places.**
  The grant list, the classifier that reads it, and each harness's configuration are edited separately, and nothing measures them against each other.

## Proposal

- **One permission file, one evaluator.**
  Command patterns, file grants, web domains, MCP servers, skills and tools live in a common file. The evaluator checks blocking rules, then confirmation requirements, then approval grants, and abstains on anything it does not recognise.
- **An adapter per harness.**
  Each harness owns the translation of its events into a neutral request and of a decision back into its own response format, and links to the shared classifiers rather than copying them.
- **Generated configuration, checked for drift.**
  One renderer discovers each harness's configuration adapter, writes that harness's machine-local files, and reports any that differ from what it would write.
- **Discovery is proved separately from dispatch.**
  A runtime diagnostic shows the registrations reach a harness. Only a session shows the harness acting on them, so each harness is validated in a session of its own, independently of the others.
- **A task whose subject is one harness is delivered only by that harness.**
  Each session record carries the runtime identity its harness reports, and a record whose identity does not match the task's harness fails the check that reads it. A session in the wrong harness cannot discharge the row by describing what another harness would do. The policy, the adapters, the generated configuration and the identity check are ordinary work that any harness delivers, because a suite any harness can run is what observes them.
- **The classifiers keep their implementation.**
  The quote-aware shell splitter, the URL checks and the bubblewrap launcher are the foundation, so what a command means does not change with where it is evaluated.

## Acceptance Criteria

- [ ] **AC1.** A request reaches the same decision through each generated harness registration as through the preceding Claude hook pipeline, as the differential suite measures it.
- [ ] **AC2.** Generated harness configuration is reproducible from the common permission file, and each generated file that differs from it is named, as the renderer's drift check reports.
- [ ] **AC3.** The Codex runtime lists both workspace hook registrations in its discovered inventory, enabled and free of warnings and errors, as the runtime diagnostic's exit status reports.
- [ ] **AC4.** A session record whose declared harness differs from the runtime identity it carries fails, as the harness identity check reports.
- [ ] **AC5.** A Codex session applies a workspace hook decision to a tool call it issues, as that session's record shows.
- [ ] **AC6.** A Cursor session applies a workspace hook decision to a tool call it issues, as that session's record shows.
- [ ] **AC7.** A Claude Code session applies a workspace hook decision to a tool call it issues, as that session's record shows.
