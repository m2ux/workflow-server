## Overview

This epic settles what an author writes in a description against what reads it. An input's description is read by the anti-pattern catalogue, by a reviewer and by the engine's own derivation, and where those readers disagree the author has no wording that satisfies them all. Each description has a form every reader accepts.

## Problem

- **Two catalogue entries reject each other on one construct.**
  A reporter declares one input per site, and the site that binds nothing has to say what makes it different. [`io-agnostic-contract`](https://github.com/m2ux/workflow-server/blob/6fcee6ab/corpus/canon/resources/anti-patterns.md) rejects naming the producer, and `no-bind-mechanics-as-prose` rejects naming the resolution.
- **The reads prose and the derivation disagree.**
  The `reads` field is described as the bound techniques' inputs an activity does not supply itself. The engine excludes an input marked `*(optional)*` from reads and counts it consumed, so an author following the prose declares a name `check-activity-variables` then reports.

## Proposal

- **An unbound input has a describable form.**
  The catalogue states the wording that distinguishes a site binding nothing, and the entries that reach it accept that wording.
- **The prose carries the carve-out the derivation applies.**
  The `reads` description states that an optional input is consumed rather than read, so the declaration an author writes is the one the derivation expects.
