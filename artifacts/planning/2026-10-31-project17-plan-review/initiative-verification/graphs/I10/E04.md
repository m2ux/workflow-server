## Overview

This epic checks each implementation task against contract tests written from the plan by an agent that sees only the contract, before the code exists.

## Problem

- **Tests restate the code.**
  The agent that implements a task writes its tests, so a test tends to confirm what the code does rather than what the plan asked for.
- **No contract to test against.**
  The plan's test plan names cases, and no section states each task's public signatures, behaviours, error cases and acceptance criteria.

## Proposal

- **A contract per task.**
  Plan-prepare writes each task's contract into the plan.
- **Contract tests beside implement.**
  A contract-tests activity, fanned beside implement in a checkout of its own, writes the tests from the contract alone into test files of their own, and each fails against the base tree.
- **The join runs them.**
  The join runs the contract tests against the implementation; a failure returns the task to its implementer, and a disputed test reaches the user as a contract ambiguity.

## Acceptance Criteria

- [x] **AC1.** The plan states each task's contract: its public signatures, behaviours, error cases and acceptance criteria, as a contract-first specimen walk shows.
- [x] **AC2.** Each task's contract tests are written by an agent given the contract alone, as a contract-first specimen walk shows.
- [x] **AC3.** Each contract test fails against the base tree before the implementation lands, as a contract-first specimen walk shows.
- [x] **AC4.** The join runs the contract tests against the implementation, as a contract-first specimen walk shows.
- [x] **AC5.** A failing contract test returns the task to its implementer, as a contract-first specimen walk shows.
- [x] **AC6.** A test the implementer disputes reaches the user as a contract ambiguity, as a contract-first specimen walk shows.
