## Overview

This epic makes implement, review, and remediate each a workflow of the work-package library, and keeps the combined workflow startable as legacy. A worker on one mode is sent no step of another.

## Problem

- **One workflow holds three modes.**
  [`is_review_mode`](https://github.com/m2ux/workflow-server/blob/bb38d574eae1d8bf8af0bd40128fd9b872428543/corpus/work-package/workflow.yaml#L19) and [`stealth_mode`](https://github.com/m2ux/workflow-server/blob/bb38d574eae1d8bf8af0bd40128fd9b872428543/corpus/work-package/workflow.yaml#L106) select review and remediate inside the workflow a worker is sent.
- **Start carries the other modes.**
  The [start activity](https://github.com/m2ux/workflow-server/blob/bb38d574eae1d8bf8af0bd40128fd9b872428543/corpus/work-package/activities/01-start-work-package.yaml#L347-L410) binds 37 technique steps, including review-only steps.
- **Submit carries a review and a push.**
  [Submit](https://github.com/m2ux/workflow-server/blob/bb38d574eae1d8bf8af0bd40128fd9b872428543/corpus/work-package/activities/13-submit-for-review.yaml#L129) posts a review or [pushes](https://github.com/m2ux/workflow-server/blob/bb38d574eae1d8bf8af0bd40128fd9b872428543/corpus/work-package/activities/13-submit-for-review.yaml#L253-L266), according to the mode flags.

## Proposal

- **Modes under workflows/.**
  `corpus/work-package` is the library. `workflows/legacy`, `workflows/implement`, `workflows/review`, and `workflows/remediate` each hold a workflow and its activities.
- **The modes are re-authored.**
  Implement, review, and remediate are written for the grain of each mode. Design may use an existing artifact when it meets the need, and may re-interpret and refactor it into a new artifact when it does not. Legacy stays the unchanged combined workflow.
- **Components before activities.**
  Routines, techniques, and resources are specced, created, and tested before an activity binds them. The tests are the checks that work calls for.
- **Integration reformulates the component.**
  Wiring derives behaviour from the activities and compares it with the expected behaviour. When they differ, that task changes the routine, technique, or resource, and the tests that cover the change, until fit, form, and function hold. The same task changes the expected behaviour or the function when the structure shows that earlier statement was wrong.
- **Library routines and techniques.**
  A series, a loop, a branch, or a gate is a routine in the library. A phase of one judgment is a technique in the library. A mode binds one only when that mode runs it.
- **One value, one routine.**
  Two modes share a routine when the steps match and a value changes one step. They bind different routines when one mode would carry a technique it does not run.
- **The workflow is the mode.**
  Implement, review, and remediate declare neither `is_review_mode` nor `stealth_mode`. Review is the review workflow, and remediate is the remediate workflow. Legacy declares both.
- **READMEs.**
  The library README names each mode. Each mode README orients that mode and does not name another mode's activities.
- **Tests travel with the work.**
  The unit tests, integration tests, and walk of a task are part of that task. A failure in any of them keeps the task open.
