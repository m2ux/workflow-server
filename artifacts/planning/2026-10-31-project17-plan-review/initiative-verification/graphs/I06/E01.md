## Overview

This epic runs the role skills on every supported host: a smoke run that installs them through the workspace deploy, briefs a real agent from them, and shows a refresh bringing a lagging skill through the bootstrap handshake. It exists because the initiative's host criteria are shown only by a run on each host.

## Problem

- **The smoke run knows one host.**
  `tests/smoke/smoke-orchestrator.ts` launches only a headless Claude CLI worker, from the fixed binary path `CLAUDE_BIN`. No driver launches another host's agent.
- **The worker is briefed by a file, not a skill.**
  The smoke worker reads `tests/smoke/worker-brief.md`, which the orchestrator loads and hands to each dispatch. No smoke run reads an installed role skill.
- **Nothing drives a deploy or a refresh.**
  The smoke sandbox is set up by the orchestrator itself. No run installs skills through the workspace deploy, refreshes them, or bootstraps against a skill older than the server requires.

## Proposal

**Install, then run.**
The smoke sandbox installs the role skills through the workspace deploy, and the worker takes its standing instruction from the installed worker skill.

**One driver per host.**
The driver launches the headless agent of every host on the supported-hosts list. A listed host with no headless agent has no automated run, and the supported-hosts list records it as confirmed by the user from a production run.

**Refresh closes the version gap.**
A smoke run installs a role skill older than the server requires, runs the deploy's refresh, and passes the bootstrap handshake.

**Ownership.**
[E00](https://github.com/m2ux/workflow-server/issues/868) builds the role skills, their install path, the supported-hosts list and the handshake. This epic owns only the smoke runs that exercise them on each host.
