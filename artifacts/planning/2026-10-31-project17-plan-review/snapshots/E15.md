## Overview

Delivery keeps the board and the review pull request in step with what has landed. A task's criteria are readable from the evidence its open pull request carries, a row a session holds reads as work in progress, a completed epic's review pull request stands for review, and every board write a delivery run makes is one that run owns.

## Problem

- **A task's criteria are unreadable until its work has merged.**
  They are reported ready to verify only once the delivering pull request has merged, though the evidence they rest on is what that pull request and its planning record already carry.
- **A held row reads as Ready.**
  A row a session holds derives no status from its reservation, so a sync returns its issue to Ready after a dispatch set it In Progress.
- **A complete epic waits on a click.**
  Its review pull request stays a draft until the user marks it ready, though every condition for that mark is one the delivery scripts already establish, and the merge still belongs to the reviewer where the target requires a review.
- **A delivery run writes the board unchecked.**
  Board writes go through one component that refuses a status the calling mode does not own, and a delivery run's writes are the only ones that bypass it.

## Proposal

- **A task's evidence is its pull request, not its merge.**
  Its criteria are reported ready to verify once a pull request names the task, open or merged. Delivery and closure still wait on the merge.
- **A held row reads as In Progress.**
  A row whose id links its planning record derives that status, so a sync agrees with the dispatch that set it.
- **The signal that completes an epic readies its draft.**
  The sync reports a base unmerged once every task is delivered and every criterion ticked, naming the pull request that merges it. A draft named there is taken out of draft, and the epic moves to In Review. The mark states completion, not permission: the epic merge conditions decide the merge.
- **A delivery run's board writes are held to a jurisdiction.**
  It owns the In Progress a held row and its epic take and the In Review a completed epic takes. Any other status, a task set In Review, and a removal are refused.
