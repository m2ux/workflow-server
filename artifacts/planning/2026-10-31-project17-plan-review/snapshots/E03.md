## Overview

Each theme has one project board, and every initiative of that theme stands on it with its epics and its task issues. An item's status follows from the state of its issue rather than from a judgement, an epic tracked in another repository still appears, and a board is brought current without a hand edit.

## Problem

- **One board for everything.**
  A single board held every initiative, so a view of one conversation's work meant filtering by hand and an initiative with no board was invisible.
- **Status set by hand.**
  Nothing derived an item's column from its issue, so a board drifted from the tracker as soon as anything moved.
- **Items missing from the board.**
  Epics and task issues existed that the board had never been told about, so a count taken from the board was wrong.
- **One repository assumed.**
  An epic tracked in another repository could not be held, so work spanning repositories had no board at all.
- **In Review assumed.**
  Every board was taken to have an In Review column, so a board without one could not be synchronised.

## Proposal

- **A board per theme.**
  Its title is the theme's name, a colon and its description. It is linked to the repository and holds that theme's initiatives, epics and task issues. A new theme needs its label and its board before an initiative takes it.
- **A derived status.**
  The column follows from facts already read: whether the issue is closed, whether its tasks are delivered, whether a pull request is open and whether it is a draft. A draft pull request leaves the item In Progress.
- **Missing items added.**
  An issue of the theme that the board does not hold is added to it.
- **Any repository.**
  An epic is tracked wherever its issue lives, and the board holds it.
- **In Review optional.**
  A board without an In Review column is synchronised to the columns it has.
