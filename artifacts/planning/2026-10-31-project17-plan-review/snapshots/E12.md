## Overview

Work Planner states 79 command specifications in one catalog, and every mode opens that catalog to reach the few operations its procedure runs. This epic puts each specification in the file whose procedure runs it, leaves the catalog holding only what several procedures share, fixes the set of top-level sections a mode file may carry across both skills, moves Workflow Canon's specifications the same way, and reaches both rules through the shared skill-file check so the layout holds without anyone remembering it.

## Problem

- **One catalog answers every mode.**
  [`references/commands.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/commands.md) holds 79 specifications across 870 lines, 30 percent of the skill's markdown, and all ten mode files link into it. 36 of the 79 are cited from one file.
- **The conventions ride on the catalog.**
  The execution conventions every specification assumes sit at the head of that file, so a procedure reaching them opens the file holding all 79.
- **A mode file may invent a top-level section.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/guidelines.md#L51) states that a section the procedure draws on sits beside it under a heading of its own, so nothing fixes what a mode file carries. Eight such sections stand: Brief and Placements in Work Planner, and Canon Question, Attribution, Coverage, Branch Coverage, Findings and Verdicts in Workflow Canon. What a mode states, and where, is not predictable from the file before it.
- **The specification rule reports three results it should not.**
  [`check_skill_files.py`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/scripts/check_skill_files.py#L148) counts a specification's callers without the file that holds it, so one its own procedure cites alongside a single other file is reported. [Inside a catalog](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/scripts/check_skill_files.py#L110) every third-level heading counts as a specification, so `### Execution` under `## Conventions` is one. A [caller under another root](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/scripts/check_skill_files.py#L150) raises `ValueError` rather than drawing a finding.
- **Any citation from the holding file excludes a specification.**
  [`check_skill_files.py`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/scripts/check_skill_files.py#L162) counts the file holding a specification among its callers whatever cites it there, and a catalog holds no procedure, so eleven specifications in [`commands.md`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/work-planner/references/commands.md) are excluded by a sibling specification's cross-reference rather than by the procedure that runs them.
- **The section rule reads only the headings present.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/guidelines.md#L50) makes Procedure and Rules mandatory, and the check measures membership and order alone, so a mode file carrying neither passes.
- **Five links resolve by file order.**
  [`review-criteria.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/review-criteria.md) titles a heading `Proposal` four times and `Acceptance Criteria` three times, once per issue kind. Five of those repeats are cited, and each citation reaches the first heading of that title rather than the kind it names.
- **Two layout faults stand against the shared check.**
  [`hoist-mode.md:81`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/hoist-mode.md#L81) carries a 113-character inline bold lead against a 100-character limit, and [`standup-mode.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/standup-mode.md#L57) ends on a blank line.

## Proposal

- **A specification stands in the file whose procedure runs it.**
  Each mode file gains a Commands section holding the operations only that mode runs, with the conventions governing them stated in the entry point every mode opens. The reader meets the operation at the point of use rather than through a link out.
- **The catalog keeps what several procedures share.**
  Specifications cited from more than one file stay in one place, so an operation two modes run is still stated once and changed once.
- **The conventions stand in the entry point.**
  Work Planner's execution conventions are a section of `SKILL.md`, which every mode opens to select itself, so a procedure reaching them opens no further file and the statement stands once.
- **A mode file carries five top-level sections.**
  Prerequisites, Procedure, Reference, Rules and Commands, in that order, each optional but for Procedure and Rules. Anything else a mode needs is a sub-section under one of them, so a diverse title names a part of a known whole rather than a section a reader must discover.
- **What the reader does with a heading places it.**
  Reference holds what a step consults or produces — a table, an output shape, a vocabulary. Rules holds what binds the mode whatever step it is on. An alternative way into the mode is a step of the Procedure. The test is stated once in the shared guidelines, so the next author places a heading without a precedent to copy.
- **One check decides both rules.**
  `skills/scripts/check_skill_files.py` gains a rule for a specification cited from one file other than its own, and a rule for a top-level section outside the named set or out of its order. Both bind every skill in the repository, so the layout is measured rather than remembered.
- **A specification's callers include the file that holds it.**
  The count reads every citation, so a specification already standing in the procedure that runs it draws no finding whatever else cites it, and a caller under another root is reported rather than raised.
- **A step is what calls a command.**
  A passage runs the commands it names where its author has written them as steps, and a sentence naming commands names them. Mood, count, order and condition each divide one pair of passages and join another, so enumeration is the only mark an author, a reader and the check all read alike.
- **A procedure's citation is what makes a file a caller.**
  One reading settles every file: a file is a caller where one of its procedures runs the command, whether or not it holds the specification, so a cross-reference between two specifications counts for neither and a procedure stated under its own heading counts wherever it stands.
- **Each rule reads the whole of what the guidelines state.**
  A command specification is a heading the Commands listing carries, not every third-level heading in the file, and a mandatory section is reported by its absence as well as by its place.
- **The reduction is measured.**
  Each mode's retrieval is recorded under the skill's representative scenarios against the layout before the change and the layout after it, so the claim rests on a walk rather than on arithmetic.
