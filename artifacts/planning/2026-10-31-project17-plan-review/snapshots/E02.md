## Overview

An acceptance criterion states one invariant that something can fail. An initiative criterion ends by naming the instrument that keeps it; an epic criterion is a fact inspection, analysis, demonstration or test can check. Every row of a Work Breakdown names the criteria it delivers, every criterion is delivered by at least one row, and the criteria of an initiative agree with the sources it marks.

## Problem

- **Criteria nothing could fail.**
  A criterion worded as a judgement about meaning had no pass and no fail, so it was ticked on opinion.
- **Criteria with no instrument.**
  Nothing said how a criterion would be checked, so an initiative closed on a reading of its own text.
- **Detail hidden in table cells.**
  A row's Description carried the detail that should have been a criterion, so the work was specified in a place no review read as a specification.
- **Rows claiming no criterion.**
  A task could exist that delivered nothing the epic had stated, and a criterion could exist that no row delivered.
- **Sources that bound nothing.**
  An initiative could cite a requirements document in References while its criteria contradicted it, and no check compared the two.
- **No stated characteristics.**
  The qualities a requirement must have were applied from memory, so two reviews of one plan disagreed.

## Proposal

- **One invariant.**
  A criterion states a single condition that holds or does not. One joining several is split.
- **The instrument in the sentence.**
  An initiative criterion ends by naming what keeps it: an end-to-end walk, a smoke run, a live check, or a guard or fixture suite continuous integration runs. A named test that does not exist is work the plan holds.
- **Coverage.**
  Every row of a Work Breakdown names in Coverage the criteria it delivers, and a criterion no row delivers is a gap.
- **At least one.**
  A task covers at least one criterion, and a criterion more than one row cites is split into the invariant each row makes true.
- **Marked sources.**
  A reference the criteria answer to carries a mark. The criteria are then aligned with it in both directions: a criterion contradicting it is a fault, and a requirement it states that no criterion makes true and no Non-Goal excludes is a gap.
- **Stated characteristics.**
  The characteristics plan and review apply to a requirement are written down, and both modes read them.

## Acceptance Criteria

- [x] **AC1.** A criterion is kept only where inspection, analysis, demonstration or test can fail it.
- [x] **AC2.** An initiative criterion ends by naming the instrument that keeps it.
- [x] **AC3.** Each Work Breakdown row names in Coverage the acceptance criteria it delivers.
- [x] **AC4.** A task covers at least one acceptance criterion, and a criterion is cited by one row.
- [x] **AC5.** The characteristics a requirement must have are stated in a file both plan and review read.
- [x] **AC6.** A reference an initiative's criteria answer to is marked, and alignment with it is reported in both directions.
