## Overview

Work Planner and Workflow Canon carry 680 internal citations, and the form that says when one is loaded is stated nowhere. The entry point of each skill states that the selected mode's file is read in full before its links are followed, and each mode file states that the command conventions are read before its first specification, so the form the skills use is text preceding a set of citations. This epic states the targets those rules serve and the form itself in the shared guidelines, with the defaults that hold where no preceding text speaks; requires a whole-file citation to open with the case that calls for it; keeps a link for what the reader opens and plain text for what prose merely names; moves a prerequisite to the step that uses it; brings both skills' files to the form; and generates each skill's read set from its citations so the payload a run injects is derived and reviewed rather than inferred.

## Problem

- **The targets the reading rules serve are unstated.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/guidelines.md#L134-L153) states placement, boundary and batching rules without naming what they are for, so an author weighing two layouts has no stated measure to weigh them against, and a rule that costs context without buying determinism reads as conformant.
- **The form binds nothing.**
  Each skill's entry point states when a mode file is loaded in full, [in Work Planner](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/SKILL.md#L21) and [in Workflow Canon](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/workflow-canon/SKILL.md#L24), and each mode file's Prerequisites states when the command conventions are loaded. Nothing states that form as a rule, so a procedure whose steps carry citations and whose preceding text says nothing about them is as conformant as one that speaks.
- **A citation with no stated timing carries no obligation.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/guidelines.md#L96-L108) types a selection link, which the reader chooses from, and a prerequisite citation in the form `Read [Name](target) first.` A citation standing mid-sentence inside a step, naming the guide whose rule that step must satisfy, is neither, and nothing says what the reader owes it. None of Work Planner's 550 internal citations takes the prerequisite form.
- **A link is required where nothing is to be opened.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/guidelines.md#L98-L99) makes every reference to another skill file a relative link, so prose attributing a behaviour to another mode links that mode's whole file. [`work-breakdown.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/references/work-breakdown.md#L104) states that Sync Mode finds an epic's pull requests by their prefix, and [`align-mode.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/references/align-mode.md#L60) states that verifying and ticking a criterion is Sync Mode. Neither sends the reader anywhere, and both would become whole-file reads under a stated obligation.
- **A whole-file citation states no case.**
  The entry point's [template listing](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/SKILL.md#L89) names six whole template files on one line, where the reader loads the one template its issue kind takes. The case that selects among them is the reader's inference, so the citation claims six files for a reader who needs one.
- **A prerequisite stands far from the step that uses it.**
  [`plan-mode.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/references/plan-mode.md#L9) loads Delivery State in its Prerequisites, and the step that matches pull requests is its ninth; [`work-breakdown.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/references/work-breakdown.md#L9) and [`understand-mode.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/work-planner/references/understand-mode.md#L9) place one the same way. The rule forbidding a citation that points further down its own file has no counterpart for one stated long before its use, and the rule reusing content already read at the same revision tells the reader not to load it again at the point it is needed.
- **150 citations name a whole file.**
  Work Planner carries 119 and Workflow Canon 31. Forty-two of Work Planner's stand inside a procedure step and name a mode file of 100 lines or more: 13 Sync, 9 Plan, 6 Advance, 4 Align, 3 Understand, 3 Hoist, 2 Propose and 2 Deliver. An obligation on those charges the reader for a file where one section was meant.
- **The payload a run injects is inferred.**
  Nothing states the set of sections a mode's run loads. Two runs of one mode can inject different sets and both follow every rule the skill states, so a change to the prose moves the payload with no record of what moved.
- **The check reads resolution alone.**
  [`check_skill_files.py`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/scripts/check_skill_files.py#L51) recognises the prerequisite form and otherwise confirms that a link resolves to a file and a heading that exist. A citation naming no heading resolves, and a whole-file citation carrying no case is indistinguishable from one read in every case, so nothing reports the scope either claims.
- **A check is named by its path and defined nowhere.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/guidelines.md#L176) names `skills/scripts/check_skill_files.py` as a code span, and its [Files rule](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/guidelines.md#L27) states where shared and per-skill checks sit without saying what any of them decides, which skills it binds, how it is run, or where its tests live. Workflow Canon carries ten scripts and no test folder.
- **A retrieval walk cannot show a citation working.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/3c0f1ff5/skills/guidelines.md#L166-L167) states that retrieval order measures file layout wherever the reader loads the file whole, so a walk shows a citation failing and never shows one working. No scenario in the skill's evidence puts its answer where a broad read does not reach.

## Proposal

- **The guide states what its reading rules are for.**
  A reading rule serves three targets: the payload a run injects is as small as the work allows, the set it injects is the same on every run, and a maintainer can read the rule and the prose it governs without running either. A rule that costs one target buys another, and the guide says which.
- **Preceding text states when a citation loads.**
  The shared guidelines state the form both skills already use: the prose ahead of a set of citations says when they are read, as the entry point does for a mode file and a mode file's Prerequisites does for the conventions.
- **A step's citation is read before the step runs.**
  Where no preceding text states the timing, the citation binds the step that carries it, so a reader classifies nothing and an author who wants one left optional marks that citation in its own prose.
- **A citation outside a procedure is read when its rule applies.**
  A Rules or Reference citation is read when the reader reaches a case the rule carrying it governs, stated as any condition is stated. Where its prose states no case, it is read in every case.
- **A whole-file citation opens with its case.**
  The sentence carrying a conditional whole-file citation opens with that case — When, Where, Before, Once or For — so the reader meets the condition before the claim and a script reads the same thing the reader does. A sentence that opens with none claims every case. A citation names a heading wherever the file it points to carries one; a file with no heading of its own, as a body template is, is cited whole.
- **A link is what the reader opens.**
  Prose attributing a behaviour to another mode names that mode in plain text. Nothing is to be followed, so nothing needs an exception, and the link rule narrows to references the reader is sent to open.
- **A prerequisite stands where its step uses it.**
  A Prerequisites section carries what every step needs, or what its first step needs. A prerequisite one later step needs is cited in that step, in the form `Read [Name](target) first.`, so the reader meets the obligation where the work is and the reuse rule never stands between a reader and content read eight steps ago.
- **Each skill's read set is generated from its citations.**
  The shared script derives, per mode, the sections a run loads unconditionally and the sections each stated case adds, and writes them as a manifest beside the skill. The prose stays the single home of every citation, the manifest is what a maintainer reads to see the payload, and the check reports a manifest that disagrees with the prose it was derived from.
- **One check decides scope and names the unconditional set.**
  `skills/scripts/check_skill_files.py` reports an internal citation that names no heading where its target carries one, draws no finding for one naming a file's title heading, and lists every whole-file citation whose sentence opens with no case.
- **A check is cited by link to its definition.**
  The shared guide defines each check the workspace runs: what it decides, which skills it binds, how it is run, and where its tests live. Prose names a check by linking to that entry, so a reader meets a check as a thing with a purpose rather than a path to a file.
- **The gate lands once both skills comply.**
  The rule is stated, both skills are brought to it, and the check follows, so no branch carries a failing gate.
- **Efficacy is walked against a target broad reading does not reach.**
  Each scenario puts the content that decides its outcome outside the files a broad read loads, and passes at the bar the record fixes before the walks run. A scenario still failing after one revision is recorded as a finding and raised as technical debt. The retrieval record measures what each mode costs under the layout that served it.

- **Final evidence follows the final citation edits.**
  Generate and check the final manifests after all citation and check-definition changes land. Run the final efficacy and retrieval walks after manifest generation, against the settled corpus revision; record that revision and regenerate affected evidence after any later input change.

- **The final comparison has one baseline and threshold.**
  Compare the settled corpus against 04de875a8517dcf229462e3b939099e16ffe3e63 using the same pinned traversal instrument and frozen scenario inputs. Count every distinct instruction file required by each scenario, following required citations transitively, including command-specification links; no scenario may increase. Missing or incomparable cases block a pass.
