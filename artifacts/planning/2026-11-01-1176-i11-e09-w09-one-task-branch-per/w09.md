**Component:** skills/work-planner/scripts/deliver.py

## Overview

A unit that changes more than one long-lived branch takes one task branch and one worktree per epic base, each cut from that base and named for its long-lived branch. The delivery survey's `unit` line names each branch with its base and worktree, and Task Branches states the rule, so a dispatch creates every branch the unit delivers through without inventing names.

## Problem

Task Branches cuts a unit's single branch from "the epic base for the long-lived branch the unit changes", and every delivering pull request opens from it. The bases of different long-lived branches share no history in workflow-server, so one branch cannot be cut from, or open a pull request against, more than one of them. The survey prints one branch and one worktree beside a list of several bases. W08 changed `main`, `workflows` and `docker`, and its brief named three suffixed branches by hand with no rule to follow.

## Proposal

- **Scene.**
  A delivery survey offers a unit of an epic with bases `i07/e00/main` and `i07/e00/workflows`, and the dispatch creates the unit's worktrees from that line.
- **One branch per epic base.**
  With more than one base, the unit takes one task branch per base, cut from it. Each branch is the unit's branch with the base's long-lived branch as its last slug word: `i07/e00/w01-queue-plan-main` and `i07/e00/w01-queue-plan-workflows`. A unit with one base, or none named, keeps the unsuffixed branch.
- **One worktree per branch.**
  Each worktree is named by its branch under the worktree directory.
- **One pull request per branch.**
  Each branch opens its own pull request into its own base, matching the one delivery per long-lived branch Task Delivery records on the row.
- **The unit line names each.**
  `deliver.py` prints, for each base, `branch <branch>, base <base>, worktree <worktree>`, separated by semicolons, after the unit's coverage and record folder. The record folder stays one per unit.
- **Prose follows the line.**
  Task Branches, Create Task Worktree, the delivery plan's Work Units and Report Lines, the delivery brief and Deliver Mode's dispatch and session steps state a branch, base and worktree per long-lived branch the unit changes.
