**Component:** skills/work-planner/scripts/sync.py

## Overview

Epic sync links every pull request `--link` names for a task id, so a unit delivering through one pull request per long-lived branch has each of them on its row. A repeated run leaves the row as it is.

## Problem

- **One pull request per id.**
  `--link W08=1494,W08=1495,W08=1496` is read into a map keyed by task id, so only the last pair survives and the row links one pull request.
- **Task Delivery asks for every one.**
  A unit changing several long-lived branches links the pull request on each: `[W01](…/pull/950), [W01](…/pull/951)`. E09's W08 row, linking #1494, #1495 and #1496, was written by hand.

## Proposal

A delivery session records a unit that opened a pull request into each of its epic bases by naming the id once for each: `--link W08=1494,W08=1495,W08=1496`.

- **Repeated ids accumulate.**
  `--link` collects every pull request named for an id, in the order given; a number named twice is one link.
- **The row keeps its deliveries in place.**
  The Task cell keeps the pull request and commit links it holds, in their order, and gains each named pull request it lacks after them. A run naming only pull requests the row already links leaves the cell unchanged.
- **One delivery per long-lived branch.**
  Two named pull requests on one long-lived branch, or a named pull request on a branch the row already delivers to, are refused: further work needs another task.
- **Wording.**
  The `--link` description in `epic-issue-body.md` and in `sync.py` states that an id repeats once for each pull request.
