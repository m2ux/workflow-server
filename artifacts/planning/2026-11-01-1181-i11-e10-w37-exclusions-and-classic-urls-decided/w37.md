## Problem

- **B1.** `held_aside` rebuilt each finding's path from the excluded skill's parent, which resolves only when the skill is itself a root. Verify Skills passes `skills/*/` as roots, so excluding `gitnexus/gitnexus-cli` reported its findings and also reported the exclusion as lapsed.
- **B2.** The classic pattern's lookbehinds, meant for board web links and local folders, also excluded routes after `api.github.com/`, so `gh api https://api.github.com/repos/o/r/projects` and `curl https://api.github.com/projects/1` passed. Classic mutations naming no card or column (`createProject`, `cloneProject`, `linkRepositoryToProject`) and `convertProjectCardNoteToIssue` passed too.
- **N1.** Four mutants survived the shared suite: a REST gap accepted anywhere on a line, an exclusion matched by name prefix, the mutation prefix cut to `add|move`, and the held-aside counts emptied. The lapse test asserted only that `alpha` appeared in the output.
- **N8.** No workflow ran `skills/test`, so the checker's own tests were shown only by local runs. A tree holding no skill called the checker with no roots, which argparse refused with exit 2.

## Proposal

A finding names its file relative to the folder holding its root.

- **Exclusions.** Each excluded skill is named the same way, from the root that holds it, and a finding is held aside when its path lies within that name; a skill no root holds keeps the name given and holds nothing. The lapse finding and the held-aside line print that name.
- **Roots.** The check accepts no roots and reports `0 files checked, 0 findings`.
- **Classic routes.** A route rooted at `projects/` or `user/projects`, or under a repository, organization or user, matches when it follows `api.github.com/` or `/api/v3/`, as well as where it stands alone. A board's web link on `github.com` still names no route.
- **Classic names.** The pattern lists every classic mutation and the argumentless `projects` field; the `V2` suffix keeps the Projects V2 names out.
- **CI.** A `check-suite` job in `verify-skills.yml` installs pytest and PyYAML and runs `pytest skills/test`. The job-step tests run the `skill-files` job alone, since the suite job reads a tree the seeded specimen does not hold.
