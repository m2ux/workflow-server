## Overview

`engineering` takes direct pushes and is never reviewed. This hot-fix states that once, at configuration.md's Planning Records, and makes delivery treat the branch that way: no epic base, task pull request or review pull request for it.

## Problem

Deliver treats every long-lived branch alike, so a row declaring `engineering:` files gets an epic base, a task pull request and a review pull request that wait on a review nobody gives, while Publish Planning Record pushes records to the same branch directly.

## Proposal

A session whose unit declares a file on `engineering` writes it in the engineering worktree and publishes it as a planning record is published; a unit changing it alone opens no pull request, links its pushed commit and follows Task Merge with it.

- **deliver.py.** A base named for `engineering` is ignored, a task pull request into one is no merge, and a unit line ends with `push engineering` when its rows change the branch, naming no branch when that is all they change.
- **Prose.** Planning Records holds the rule; Publish Planning Record, Prepare Delivery Bases, Epic Bases, Task Branches, Delivery Plan, Task Delivery, Task Merge and Deliver link it.
