**Component:** skills/work-planner/scripts/development-link.py

## Overview

Development links written and removed by command. A script runs GitHub's add and remove mutations from a query file and reads the relation back from both ends, so a session with authenticated `gh` writes the field itself and a failed write names its operation and error.

## Problem

Set Development Link and Remove Development Link describe GitHub's sidebar selector. A session without a browser reads that as an unavailable field and hands the link to the user, although `addCloseIssueReferences` and `removeCloseIssueReferences` accept the write from `gh api graphql`. Nothing checks that a repeated add leaves one relation, that a removal spares the issue's other links, or that a failed write says what failed.

## Proposal

A delivery session links its pull request to the issue it delivers, or removes an authorized abandoned link, from a shell where `gh` is logged in.

- **One script, two operations.**
  `development-link.py add|remove --issue <owner/repo#n> --pull <owner/repo#n>` resolves both node ids through REST, writes the mutation into a query file and sends it with `gh api graphql -F query=@file`, so no command carries the dollar sign the workspace shell denies.
- **Readback from both ends.**
  The script reads the issue's relation before the write and both ends after it through `development.read`, the batched paginated read Capture Pull Request Links and Capture Issue Links run. An add holds when the issue lists the pull request exactly once, the pull request lists the issue, and every other link on the issue stands. A removal holds when the pull request is gone from both ends and every other link on the issue stands.
- **A failure names its operation.**
  A failed node-id lookup, mutation or readback prints the operation, the pull request and issue, and the tracker's error text, then exits 1. An unreadable relation is a failed readback, never an empty one.
- **The commands sit at the point of use.**
  Set Development Link and Remove Development Link carry the runnable command, and Access Development Links takes the verified relation the command returns.
