**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check reports every heading whose anchor another heading in the same file already holds, whether or not a link cites it. A link's destination is then unambiguous by construction, rather than by nobody having cited the repeat yet.

## Problem

- **The rule waits for a victim.**
  [`check`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/scripts/check_skill_files.py#L259-L264) reports a duplicate anchor only when a link already cites it, so an ambiguity is measured by whether anyone has fallen into it rather than by whether it is there.
- **The fault is known to recur.**
  Five citations into the review criteria resolved by file order until [#1324](https://github.com/m2ux/workflow-server/pull/1324) corrected the headings behind them, and eleven further repeats of `Problem`, `Title`, `References` and their like stood uncited in that file until it was restructured. Nothing stops the next repeat arriving the same way.
- **The command states the gap as a rule.**
  [Check Skill Files](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/workflow-canon/references/revise-mode.md#check-skill-files) says an uncited repeat resolves nothing ambiguously, which holds only until the first citation lands on the first of two headings.

## Proposal

An author adds a second `## Problem` to a reference file, one per issue kind. Nothing cites either yet, so the check passes, and the next author who links `#problem` reaches the first one whatever they meant.

- **A repeated heading is reported wherever it stands.**
  The check reports each heading whose anchor an earlier heading of the same file holds, naming the anchor and the earlier heading's line. Two titles that differ only in what the anchor drops, such as case or punctuation, are one anchor and are reported alike.
- **The rule is stated where the check is documented.**
  The guidelines' Resolution rule says every anchor resolves to one heading, and Check Skill Files states that a repeated heading is reported whether or not a link cites it.
- **The repository stays clean under the rule.**
  A run over every repository skill carries no repeated heading; any it finds takes its distinguishing kind into its title.
