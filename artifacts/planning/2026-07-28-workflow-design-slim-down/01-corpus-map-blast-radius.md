## 6. `artifactPrefix` renumbering vs. find-or-update discipline

`artifactPrefix` is **not authored** — `src/loaders/workflow-loader.ts:83` and `:168` set `activity.artifactPrefix = parsed.index` from the filename, and `:91-93` sorts activities by it. `get_activity` surfaces it in the response header and `_meta` (`src/tools/workflow-tools.ts:850-856, 943`).

**Artifact writes survive renumbering.** `work-package/techniques/manage-artifacts/write-artifact.md:37-44` is find-or-update keyed on the **bare filename, prefix-agnostic**: step 1 looks for "a file matching `<NN>-{bare_filename}` (**any** two-digit prefix)"; step 2 "**UPDATE that file in place** … Keep its existing numeric prefix; do NOT create a second copy under a different number"; step 3 only mints `{artifact_prefix}-{bare_filename}` when nothing matches; step 4 is a re-scan mint guard. `planning-readme.md:77` restates it: "write-artifact keeps the first prefix sticky on later artifact updates."

So for the QDDWIT folder — which holds 16 artifacts under prefixes `01/03/05/06/08/10` — collapsing 01/03/04/05 into one prefix **does not orphan or duplicate a single file**. `03-design-specification.md` keeps its name and is updated in place.

Two things do break:

1. **The `@` column desyncs from disk** (see §4). Rows carry `01/03/04/05/06/08/09/10/11` (`README.md:29-47` of the live folder) but `{artifact_prefix}` now resolves to the new index. Silent no-op.
2. **Artifact *consolidation* (17→5), not renumbering, is the real orphan risk.** If two artifacts merge into one bare filename, the old files (`01-structural-inventory.md`, `01-format-conventions.md`, `08-verified-findings.md` …) are left on disk, still hyperlinked from Progress rows, with no guard to notice — `check-resource-anchors.ts` only walks the corpus, never planning folders, and no "unused resource/technique" guard exists anywhere in `scripts/`.
