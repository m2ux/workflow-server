**Component:** skills/work-planner/artifacts/issue.md

## Overview

Audit every script the skill holds against the command block that runs it, the artifact operation that cites that block, the procedure that calls that operation, and the test that exercises the script. Repair each break in the path, and guard the first hop with a test so a script no cited command runs fails the suite.

## Problem

E16 added six scripts across four artifacts, each delivered by its own task. No check spans them: the shared skill-file check reads markdown only, so a script with no command block, or a command no operation reaches, passes it.

- **Removal is specified and never requested.** Remove Development Link runs `development-link.py remove` from the removal branch of Access Development Links. Close Tracker Issue asks for the user's decision before an abandoned or incorrect link is removed, then runs nothing, so no procedure reaches the removal command.

## Proposal

- **The audit.**
  Each script under `scripts/` is traced script → command block → citing operation → calling procedure → test. A module other scripts import, such as `development.py` or `statuses.py`, is reached through its importers.
- **The repair.**
  Close Tracker Issue returns an abandoned or incorrect link to its caller. The Issue Closure protocol, which already reads both the issue and pull-request artifacts, obtains the user's decision, runs Access Development Links with the removal request, and repeats from its issue step.
- **The guard.**
  A test in `test_documents.py` requires each script to be named in a command specification some procedure cites, or imported by a script that is. The shared skill-file check stays a markdown check; the scripts directory and its command convention are this skill's own.
- **Structure declaration.**
  `structure.json` declares no scripts, so no declaration is added.

### File-change declaration
