**Component:** workspace:skills/work-planner/artifacts/board-status.md

## Overview

Board Status owns the proposed board-change contract and its derivation and validation.

## Problem

Board Delivery's Status Changes guidance combines board-state derivation and write jurisdiction with subject-specific lifecycle policy, leaving that derived subject without its own artifact home.

## Proposal

Create the Board Status artifact from the completed ownership audit. Consume supplied state and subject-owned lifecycle decisions through explicit data contracts, and provide proposed changes or blockers. Reuse existing computation/rendering capabilities where adequate. Board Delivery owns evidence gathering, application and readback; the shared artifact contains no issue-kind switch or lifecycle coordination sequence.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | Current Status Changes guidance, its pinned historical source, all consumers, existing script capabilities and the audit's clause-to-owner map. |
| Plan | Define issue/item identity, current/desired status or membership action, write jurisdiction, reason and blockers; identify substantive shared derivation/validation capabilities. |
| Implementation | Create board-status.md with operations, command specifications before Fields, concrete data shapes and context linked at use. |
| Review | Each rule has one owning subject; capabilities have real callers, and only shared ordered changes across artifacts qualify for a separately justified protocol. |
| Test | Within the joined extraction, verify actual decisions/calls and blocked writes for closure, membership, review, reservation and dependency cases; run document/checkout/role checks and the full status/board/delivery matrix. |
