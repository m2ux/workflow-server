# Split Decisions

- **Numbering.**  Every new row adds tests, and the test README catalogue carries each module's test count, so every new row depends on W13, which changes that catalogue. Rows numbered before W13 would depend on a later row, so the new rows take W14 onward in start order. The former W06–W10 have no pull request and move to W47–W52 after their new producers; their work items are copied unchanged to this folder. W03–W10 are left unused.
- **Test catalogue.**  Parallel rows each add a test count to the shared test README catalogue. That is an append-only catalogue the readme check reconciles, not a component; rows rebase on each other there.
- **Delivered producers.**  The Deliver Mode and Pull Request rows consume E04 W01 and W02, which are delivered and merged into the epic base. An edge to a later epic is refused by the dependency check, so no edge is written.
- **Criteria.**  A criterion more than one row cites is split into one invariant per row, so AC3, AC4 and AC5 leave the body for AC21–AC59 and AC61. AC60, Board Delivery naming no kind, joins the Board Status extraction unit, since the only kind mention there is in the guidance that unit extracts. AC11 joins the checker row: the audit found no current before-use cycle to fix, and the checker's cycle check over the installed model is its instrument. AC12 is the reading-trial row's own.
- **Upstream capability.**  `scripts/priority.py` is not on the epic base; the queue and progress rows depend on #1631 rather than reimplementing it.
- **Kind interface.**  The entry point is the kind registration the guidelines name, and `scripts/kinds.py` the one script registry; no second registry is created. Hot-fix names a general script still imports remain until that script's row moves it to the registry; the hot-fix retirement row removes the rest.
