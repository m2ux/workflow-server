**Component:** `workspace:skills/scripts/check_skill_files.py`

## Overview

W39 is a further task on W37: the shared skill-file check holds a finding aside only when its file lies within an excluded skill, matched by resolved path, so roots under different parents cannot cross-match.

## Problem

A finding names its file relative to the folder holding its root, and `held_aside` matched an excluded skill against that name. With roots `one/x` and `two/x` and `one/x` excluded, both files are named `x/SKILL.md`, so the finding in `two/x` was held aside under `one/x` and the run passed.

## Proposal

A finding's name stays as printed and carries the file it names.

- **Where.** `finding()` returns a `Where`, a string naming the file as before that also holds its resolved path; every producer already builds findings through `finding()`, and every reader that treats the name as a string is unchanged.
- **Held aside.** `held_aside` matches each finding's resolved path against each excluded skill's resolved folder. The skill's printed name, relative to the folder holding the root that holds it, is for the held-aside and lapse lines alone.
