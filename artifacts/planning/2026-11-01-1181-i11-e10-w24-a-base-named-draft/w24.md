**Component:** workspace:skills/work-planner/scripts/sync.py

## Overview

Sync Epic reports an epic base as draft so the caller opens a review pull request for it. This task makes that report turn on what the base carries: a base is draft only where it holds a commit its long-lived branch lacks, so the line always names a pull request GitHub will accept.

## Problem

- **The condition reads the pull request, not the branch.**
  [`draft_bases`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/work-planner/scripts/sync.py#L353-L373) reports a base when a merged task targets it and no pull request, open or merged, merges it. Whether the base carries anything the long-lived branch lacks is never asked.
- **A mid-delivery merge makes the report permanent.**
  `i11/e09/workspace` stood 0 commits ahead of `workspace` and 130 behind once its content landed through its first review pull request. Every sync of that epic reported a draft until another task merged into the base.
- **The action it names cannot be taken.**
  GitHub refuses a pull request with no commits between head and base. A reader following the report learns that only by trying it.
- **A report nobody can act on trains the reader past it.**
  The draft line sits among lines that do require action, and an epic that merges mid-delivery is the ordinary case for a long epic.

## Proposal

An epic sync already runs against a project checkout and names each fetched epic base as a `--revision`, such as `origin/i07/e00/main`. The long-lived branch sits beside it on the same remote, as `origin/main`.

- **The draft line asks what the base carries.**
  A base is reported draft only where its revision holds a commit the long-lived branch at the same remote lacks, read with `git rev-list`. A base level with or behind its branch has nothing to review and draws no line.
- **The merged review pull request is not what the report turns on.**
  Only an open pull request merging the base withholds the line. A base whose earlier review pull request merged, and which has since gained a task, is draft again, since a new review pull request is the action it needs.
- **What the run cannot compare is unevaluable, not draft.**
  A base no `--revision` names, a base in another repository than the checkout, and a long-lived branch absent beside the base revision are each reported `unevaluable` with the reason, and draw no draft line.
