## Overview

The shared skill-file check counts the file holding a command specification among that specification's callers only where a Procedure section of the file carries the citation. A procedure that runs a command stands with it, so the specification is already home; a sibling specification or a passage of reference prose names the command without running it, so the file holding it is not a caller and the one procedure elsewhere that does run it is the specification's home. The rule settles what W08 moves.

## Problem

- **The exclusion reads any citation from the holding file.**
  [`check_skill_files.py`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/scripts/check_skill_files.py#L162) counts the holding file as a caller wherever that file cites the specification, whatever the citation is doing. The citation that justified the exclusion is a Procedure step: [`revise-mode.md`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/workflow-canon/references/revise-mode.md#L23) runs Check Skill Summaries from step 5 of the mode that holds it. A citation from anywhere else in the file carries the same weight.
- **A catalog holds no procedure, so every citation in it is a cross-reference.**
  [`commands.md`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/work-planner/references/commands.md#L1) has h1 `Commands` and nothing but command specifications. Eleven of its entries are cited by a sibling specification and by exactly one procedure elsewhere, so the exclusion counts two callers and reports none. [Fetch All Issues](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/work-planner/references/commands.md#L48) is named by List Orphans and run by [`hoist-mode.md`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/work-planner/references/hoist-mode.md#L16) alone.
- **A reference file holds no procedure either.**
  [`canon-context.md`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/workflow-canon/references/canon-context.md#L1) and [`change-surface.md`](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/workflow-canon/references/change-surface.md#L1) state terms, scope, checks and artifacts, and close with a Commands section. Nine of their specifications are named from that reference prose, or from a sibling specification, and run by exactly one mode elsewhere. The exclusion drops all nine the same way.
- **The dropped findings are the scope of the move.**
  The check reports 31 findings over the four skills at the base, and the twenty suppressions are specifications standing in a catalog or a reference file although one procedure runs them, which is the state the epic's placement rule forbids.

## Proposal

The exclusion already asks the right question of the citation index — whether the file that would receive the specification already holds it — and reads the answer from the wrong evidence. A file holds a specification's procedure only where it carries a Procedure section that cites it, so that is what the count reads.

- **A Procedure of the holding file is a caller.**
  A specification an h2 `Procedure` section of its own file cites stands with the steps that run it, and the file counts among its callers. The section runs to the next heading of its level or above, so a step under a sub-heading of the procedure counts with the rest.
- **Nothing else in the holding file is.**
  A sibling specification, a Rules section and a passage of reference prose name a command without running it, so the holding file is dropped from the caller set and the procedures elsewhere decide. A specification only its own prose names has no caller at all and stands where it is.
- **The guidelines state what a caller is.**
  The placement rule in the shared [skill guidelines](https://github.com/m2ux/workflow-server/blob/67fe12ad/skills/guidelines.md#L105) says a catalog block with one caller belongs to that caller. It gains the sentence that a caller is a procedure that runs the command, so the rule the check measures is readable where the rule lives.
- **The specimens carry each side of the distinction.**
  The check's own suite seeds a specimen catalog whose sibling specification carries the citation and one procedure elsewhere runs it, which is reported; a specimen file whose Procedure carries the citation, which stands; and the reference-prose and Rules variants of the first, which are reported with it.
- **The twenty suppressions are classified before the rule is written.**
  Each is read for the section of its own file that cites it, and the rule is checked against all twenty rather than against the eleven already measured. The classification is in [the suppression table](suppressions.md).
