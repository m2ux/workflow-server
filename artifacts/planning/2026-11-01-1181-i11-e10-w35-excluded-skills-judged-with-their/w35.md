**Component:** `workspace:.github/workflows/verify-skills.yml`

## Overview

W35 fixes finding 6 of the [agent review of #1555](https://github.com/m2ux/workflow-server/blob/engineering/artifacts/planning/2026-11-01-1181-i11-e10-epic-review/review-1555.json): the skill-check workflow judges an excluded skill in a run that also reads the skills citing it, and completes when every skill is excluded.

## Problem

The workflow's exclusions job ran each excluded skill alone, so the citations other skills make into it were absent. A finding such as `command specification nothing cites` could come from the isolation alone and keep an exclusion alive after its real findings were fixed. With every skill excluded, the in-scope job passed the checker an empty roots list, which argparse rejects with exit 2, so the job failed.

## Proposal

A skill held out of scope is read with every other skill, and only its findings are set aside.

- The checker takes `--exclude <skill>`, repeatable. It reads every root as before, holds aside the findings in an excluded skill's files, prints a count of them per skill, and reports an excluded skill holding none as `excluded skill without a finding`.
- The workflow runs the checker once over every skill folder holding a `SKILL.md`, with an `--exclude` for each name in `EXCLUDED`. One run answers both questions, so the separate exclusions job goes, and the roots list is never empty.
- An `EXCLUDED` name naming no skill holds no finding, so it is reported the same way.
