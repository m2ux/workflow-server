**Component:** skills/work-planner/scripts/sync.py

## Overview

Sync checks the epic prefix of every pull request the Work Breakdown links after it applies `--link`, so a pull request linked in a run is checked in that run.

## Problem

An epic sync reads the linked deliveries for title repairs from the rows as fetched, then applies `--link` to them. A pull request the run links is absent from the rows the title check reads, so its prefix is checked only on the run after.

## Proposal

A delivery session records its pull request on the epic with `sync.py --link W01=<n>`. The run both writes that link and reports the deliveries whose titles lack the epic prefix.

- `--link` accepts only a pull request whose title names this epic, and refuses one that does not, exiting before the body is written.
- Title repairs read the rows after `epic_delivery` has applied `--link`, so the rows they check are the rows the run writes.
- A sync test links a merged pull request through `--link` and shows the run reports it linked with no retitle, and that a `--link` to a pull request lacking the epic prefix is refused in that run.
