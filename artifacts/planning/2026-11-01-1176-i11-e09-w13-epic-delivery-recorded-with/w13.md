**Component:** skills/work-planner/artifacts/epic-issue-body.md

## Overview

Every call to Record Epic Delivery passes the epic's fetched bases, so Sync Epic reads the long-lived branch names at those bases and can report an epic closable. A test walks the skill's instruction files and fails on a call that omits them.

## Problem

- **Callers omit the bases.**
  Record Epic Delivery takes the fetched epic bases as an input and maps each to a `--revision`. The calls in Deliver Mode, Review Pull Request, Plan Gap Task, Align Mode's unplaced and review-pull-request steps, and Sync Mode's repeats and close step name other inputs and leave the bases out.
- **A call without bases never closes an epic.**
  Without `--revision`, Sync Epic reads no long-lived branch names, reports them `unevaluable`, names each check it did not make, and reports no epic closable. The failure is safe but leaves delivery unrecorded against its bases.
- **Nothing checks the callers.**
  No test reads the call sites, so a new or edited call can drop the bases unnoticed.

## Proposal

A caller of Record Epic Delivery reads its prose call; the operation reads its Inputs line. Every call names the fetched epic bases among its inputs, and a repeated call names the same epic bases it was first given.

- **Calls.**
  Each `Run` or `Repeat` of Record Epic Delivery in a mode, protocol or artifact names the fetched epic bases, or the same epic bases for a repeat within one step.
- **Plan Gap Task.**
  Its Inputs carry the project checkout and the fetched epic bases, which it passes to Record Epic Delivery. Align Mode and Sync Mode supply them where they follow it.
- **Test.**
  `test_documents.py` collects every line in the skill's mode, protocol and artifact files that runs or repeats Record Epic Delivery, and asserts each names the epic bases. A line that only reads a result the operation reported is not a call.

### File-change declaration

The delivery change is bounded by these paths:

- `skills/work-planner/artifacts/epic-issue-body.md` (Plan Gap Task only)
- `skills/work-planner/modes/deliver-mode.md` (the Record Epic Delivery call only)
- `skills/work-planner/modes/align-mode.md`
- `skills/work-planner/modes/sync-mode.md`
- `skills/work-planner/protocols/review-pull-request.md`
- `skills/work-planner/protocols/task-merge.md` (the Review Pull Request call only)
- `skills/work-planner/protocols/epic-integration.md` (the Review Pull Request call only)
- `skills/work-planner/test/test_documents.py`

Review Pull Request receives the checkout and bases from each caller, so its Record Epic Delivery call has them to pass.

`deliver.py`, held by W12, is not changed.
