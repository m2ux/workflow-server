## Overview

The specification rule reads every citation of a command specification, so a specification the procedure holding it already cites draws no finding, a catalog's conventions section lists no command, and a caller under another of the given roots is reported rather than raised. The rule decides where W02 moves 36 specifications, so it settles what it reports before anything moves on its word.

## Problem

- **The caller count drops the file holding the specification.**
  [`check_skill_files.py`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/scripts/check_skill_files.py#L148) filters the holding file out of the caller set, so a specification its own procedure cites alongside one other file counts one caller and is reported. [`revise-mode.md`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/workflow-canon/references/revise-mode.md#L119) states Check Skill Summaries, cites it at line 23, and is reported for a specification standing exactly where the rule wants it.
- **A catalog counts every third-level heading as a specification.**
  [`specifications`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/scripts/check_skill_files.py#L106-L115) opens a catalog inside the listing and never leaves it, so `### Execution` under `## Conventions` in [`commands.md`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/work-planner/references/commands.md#L7) reads as a command specification. The guidelines state conventions as what governs the commands, not as one of them, and the first citation of that anchor turns the mismatch into a finding.
- **A cross-root caller raises instead of reporting.**
  [`relative_to`](https://github.com/m2ux/workflow-server/blob/9ed47b0d/skills/scripts/check_skill_files.py#L150) names the caller against the root of the file holding the specification, which raises `ValueError` when the roots named on the command line have different parents and a citation crosses between them. The check runs over several roots at once, so a layout the rule is meant to measure ends the run instead.

## Proposal

The rule already judges placement by use, reading the citation index the check builds over every file it is given. Each fault is in what that index is asked, not in the index, so each correction is a change to the question the rule puts to it.

- **The count reads every citation.**
  A specification is reported when exactly one file cites it and that file is not the one holding it. A specification its own procedure cites stands whatever else cites it, since the file that would receive it already holds it.
- **A catalog's conventions list no command.**
  Inside a catalog each second-level heading opens a command listing, and Conventions does not, so a third-level heading under it is prose the commands assume rather than a specification.
- **A caller outside the root is named whole.**
  A caller is named relative to the root holding it and by its full path otherwise, so a citation crossing two roots draws the finding it describes.
- **The specimens carry each fault.**
  A specimen catalog whose specification its own file and one other cite, a specimen catalog citing a heading of its conventions section, and two specimen skills under different parents with a citation between them, each shown against the rule as the suite already shows every other.

## Work Breakdown

| Part | Description |
| --- | --- |
| Caller count | The rule reports a specification exactly one file cites where that file is not the one holding it |
| Catalog listing | A catalog's Conventions section carries no command specification, and its other second-level sections each open one |
| Cross-root report | A caller is named relative to its root where it lies under it, and by its whole path otherwise |
| Test | The check's suite seeds a specimen per fault — a specification its own file and one other cite, a catalog citing a heading of its conventions, and two skills under different parents — and the whole suite and the check over work-planner and workflow-canon both run |
