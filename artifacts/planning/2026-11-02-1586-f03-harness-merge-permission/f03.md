## Overview

The pull-request artifact states the merge permission a delivery session needs from its agent harness, Deliver checks for it before dispatch, and Merge Delivery Pull Request returns a permission-layer refusal to a later Deliver run.

## Problem

- **A harness refusal reads as a GitHub refusal.**
  Merge Task Pull Requests updates the task branch and retries once on any refusal, so a permission-layer refusal fails twice and leaves the pull request blocked.
- **The permission is unstated and unchecked.**
  Nothing names the harness setting Deliver relies on, so every refused merge reaches the user as a request for approval.

## Proposal

A delivery session merges its task pull request into an epic base under an agent harness with its own permission layer.

- **One home for the permission.**
  A Merge Permission field of the pull-request artifact states it, with the Claude Code `autoMode` form; SKILL.md Dependencies and Deliver link it.
- **Checked before dispatch.**
  Deliver's dispatch step confirms the permission and stops, naming the absent setting, before any unit begins.
- **A refusal of its own.**
  Merge Delivery Pull Request tells a permission-layer refusal from a GitHub one and returns the pull request ready and verified, for a later Deliver run to merge.
