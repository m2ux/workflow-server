**Component:** workspace:skills/work-planner/scripts/deliver.py

## Overview

A unit's planning record names its work item twice: once in the README a dispatching session writes, and once in the row link the release operation composes. The two names are composed by different parties and can disagree, which leaves the epic row pointing at a file that is not there. This task gives the file one composition and refuses a row link the record cannot satisfy.

## Problem

- **The row's link is composed, not read.**
  `deliver.py --release` writes `<record>/<task id in lower case>.md` from the task id alone. It never looks for the file, so a record whose work item carries another name is linked to a path that does not resolve.
- **The README names the file independently.**
  The record's Artifacts table is written by the session that populates the record. One delivery found a README whose row named `work-item.md` while the row link addressed the task id's file.
- **Nothing measures the disagreement.**
  The link lands in the epic body and the README lands in the engineering branch, and no check reads one against the other.

## Proposal

The release operation is the one place a row's link to its work-item file is composed. It runs while the record is in reach, in the engineering worktree.

- **One name for the file.**
  Work Item's Identity names the file for its task id in lower case, the name the row's link carries, and the record's README links it by that name.
- **The release reads the record before writing the link.**
  `--release` takes the engineering checkout as `--engineering`, resolves the held folder there, and refuses a row whose folder holds no `<task id>.md` or whose README does not link it. A mismatch is caught at the row, not by the reader who follows the link.
