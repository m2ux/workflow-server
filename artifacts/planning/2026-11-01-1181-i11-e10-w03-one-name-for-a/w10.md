**Component:** workspace:skills/work-planner/scripts/deliver.py

## Overview

A unit of work is one task row, or the rows that name each other in Joins, and one unit is one pull request. The available-work report names one record folder for the unit, and Deliver Mode holds that a unit's record exists and its rows carry that record's link. The reserve operation derived a folder from each row separately, so a joined pair was held with two folders and its planning split across them. This task makes the reserve operation hold a unit with the folder the report named for it.

## Problem

- **The folder is derived per row, not per unit.**
  [The reserve loop](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/scripts/deliver.py#L325-L329) calls `names()` once for each task it is given, with that task's own id and Description, and writes the result as that row's link.
- **The function it calls is written for a unit.**
  [`names()`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/scripts/deliver.py#L95-L100) documents its result as what one unit's **first** task id and Description give it, which is the folder the available-work report prints. Only the first row's call agrees with that report.
- **Two joined pairs were held wrongly.**
  Reserving a joined pair on an epic of this initiative produced one folder named for each row rather than one for the pair, and a second joined pair on the same epic was held the same way. Each pair is one pull request, so each needed one record.
- **Nothing refuses the split.**
  A call naming one row of a joined pair holds it alone, so its partner is later held with a folder of its own.

## Proposal

The reserve and release operations group the rows they are given into units by the same Joins reading the available-work report uses.

- **One reserve call holds one unit.**
  The folder is derived once, from the unit's first row, as the available-work report derives it, and written as the link of every row in the unit.
- **A unit is held and released whole.**
  A call naming some rows of a unit and not others is refused, naming the rows it leaves out, so a joined pair cannot be held with two folders.
- **A row that joins nothing is unchanged.**
  Its unit is itself, so its folder is the one its own id and Description give it.
- **Release follows the same reading.**
  Each row of a released unit points to its own work-item file inside the one record, which is where the record's README links them.
