# Protocol Layer Stack: A Call Goes Down, Never Up — October 2026

> Delivery · Created 2026-10-19

## Executive Summary

Work Planner is a layer stack. A mode aggregates protocol calls the way an application calls services, a protocol runs artifact operations and other protocols, and an artifact runs neither. One call inverted that: Epic Integration ran Understand Mode to obtain the review pull request's architecture overview, which put a user-goal lifecycle — its interview step included — inside an automated merge path. The shared guidelines licensed the inversion, permitting a protocol to run a mode where that mode is the unit of work.

Reading the shared guidelines for that rule exposed a second fault. The file binding every skill carried the section sets for `modes/`, `protocols/` and `artifacts/`, which only Work Planner has, and a mode-file shape that is Workflow Canon's, the two disagreeing over whether a mode carries Rules. The shared check held the same knowledge, keyed on directory names.

Two sessions changed the same two files while this work was open. Epic Integration carries their Review Pull Request inputs, their interview over the review's ready mark and their named Update Epic Base inputs; the worktree call loses its path argument where it now sits, in Change Overview.

Three changes answer this. Each skill declares its own directories in a `structure.json` the shared check reads, and the prose moves to the skill that owns it. Work Planner's entry point states the layer stack, where every mode reads it, binding this skill alone. Change Overview becomes the protocol that produces and publishes one pull request's overview, run by Epic Integration and by Understand Mode, which keeps its Outcomes and becomes the selector. A fourth commit answers this branch's own review: the contract now comes from the nearest declaration above each file rather than from the root named on the command line.
