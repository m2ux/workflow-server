**Component:** `workspace:skills/scripts/check_skill_files.py`

## Overview

W42 has the shared skill check run by hand over the skills a person names: the epic base holds no GitHub workflow for skills, and the check takes no exclusion option.

## Problem

The epic base carried a Verify Skills workflow that ran the shared check over every skill under `skills/`, holding the out-of-scope skills aside through an `EXCLUDED` list and the check's `--exclude` option. The user wants no GitHub workflow that verifies skills, so the workflow, the option and everything serving only the two have no caller.

## Proposal

A person runs `skills/scripts/check_skill_files.py` over the skills in scope, naming each; a skill out of scope is not passed.

- **No workflow.** `.github/workflows/verify-skills.yml` goes, so the epic base holds no `.github` directory, as `workspace` holds none.
- **No exclusion.** The check's `--exclude` option goes with what serves only it: `held_aside`, the held-aside and lapse output, the `excluded skill without a finding` kind, and the `Where` path carrier, whose resolved path only exclusion read. A finding names its file as a plain string.
- **Tests.** The tests running the workflow's steps or exercising exclusion go. The cases they carried for surviving checks — a citation crossing skills judged together, a REST gap named mid-line — run the check directly over the seeded tree.
