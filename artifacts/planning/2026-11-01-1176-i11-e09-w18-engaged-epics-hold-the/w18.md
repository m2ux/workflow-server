**Component:** workspace:skills/work-planner/scripts/board-queue.py

## Overview

An initiative In Progress waits, in every priority set and when unplanned, while an epic it lists is active or In Review. The queue then readies none of its epics, and Board Delivery and the queue agree on its Status.

## Problem

`board-queue.py` waits an initiative only on open delivery pull requests, and excludes the integration pull request. `board.py` holds an initiative In Progress while a listed epic is In Review or In Progress. For an initiative in the next priority set whose only engagement is an epic In Review (its integration pull request open) or a reserved row, the queue moves it In Progress → Ready and readies its unstarted epics; Board Delivery raises it back. The two scripts undo each other every run. At workspace `67eb0235` the In Review case waited, so the In Review half is a regression from this epic.

## Proposal

- **Scene.**
  I01 (priority 3) is In Progress; its E00 is In Review with only the integration pull request open. I02 (priority 5) is in Backlog.
- **What holds the initiative is what Board Delivery reads.**
  `Queue.holding` names the open delivery pull requests of the listed epics, each listed open epic In Review, and each one active through a session's row with no such pull request. `Queue.wait` waits an In Progress initiative on any of them and prints a `wait` line naming them.
- **One wait rule.**
  The next set, the lower sets and an unplanned initiative all use `Queue.wait`. A waiting initiative readies none of its epics, as AC4 states.
- **An unplanned initiative with a reserved row waits.**
  It waits, as it does for an open pull request, rather than printing `reconcile`: the reserved row is task work under way, which Epic Activity treats as an open pull request.
