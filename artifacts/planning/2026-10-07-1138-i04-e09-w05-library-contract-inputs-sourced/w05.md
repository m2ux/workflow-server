## Overview

The github, atlassian and git library contracts leave a required inherited input only where the bound operation reads it. `cloudId` and `planning_folder_path` are optional; GitHub's repository inputs already are.

## Problem

- **8 steps owe a cloud id nothing supplies.**
  [`cloudId`](https://github.com/m2ux/workflow-server/blob/c6774bff79af0e118b3de3532307c7ad40cd5d66/corpus/support/atlassian/techniques/TECHNIQUE.md#L12-L14) is required on the atlassian contract. `comment-jira-issue`, `edit-jira-issue`, `get-jira-issue`, `transition-jira-issue` and `user-info`, bound from work-package, remediate-vuln and the assumptions-review specimen, never read it, and the run holds no variable or earlier output of that name.
- **Git requires a planning folder not every operation reads.**
  [`planning_folder_path`](https://github.com/m2ux/workflow-server/blob/c6774bff79af0e118b3de3532307c7ad40cd5d66/corpus/support/git/techniques/TECHNIQUE.md#L12-L14) is required while the same contract says not every technique needs one. The server seeds the name, so the guard reports no step.

## Proposal

- **The scene.**
  A library contract is bound from many workflows, each holding a different set of variables.
- **The source.**
  `cloudId` is optional until resolve-cloud-id caches it. A site-scoped call passes that id; a call without it resolves the id and retries. user-info takes no cloud id. `planning_folder_path` is optional. GitHub's `target_repo` and `repo_path` stay optional.
