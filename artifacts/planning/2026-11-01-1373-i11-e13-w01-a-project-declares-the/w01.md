## Overview

A project declares the criteria its epics carry. The guide names one declaration, `config/required-criteria.json` at the project root, and its schema, so the format check and this project's own declaration build on one stated contract.

## Problem

The guide hardcodes one project's required corpus criterion, and no project-owned declaration exists for a project to state its own. A project with no definition corpus meets a rule it cannot satisfy, and a project with another required criterion has nowhere to state it.

## Proposal

The epic guide's Fields state what an epic body carries. The long-lived branch declaration, `config/branches`, is the precedent: a project file the skill reads, with a missing statement reported unevaluable and this project's values shown only under a labelled Example.

- **One declaration path.**
  `config/required-criteria.json` at the project root. JSON carries the four fields a criterion needs, which one name per line cannot, and the standard library reads it.
- **One schema.**
  A JSON array; each entry is one required criterion, with four non-empty string fields:
  - `branch`, the long-lived branch whose reach brings the criterion.
  - `criterion`, the text the epic carries after its label.
  - `phrase`, matched case-insensitively, identifying the criterion in an epic that carries it.
  - `row`, the Description of the task row that delivers it.
- **An absent statement is unevaluable.**
  A missing or empty file, an empty array, unreadable JSON or an entry lacking a field leaves the project's required criteria unevaluable. The check reports that, names what is missing, and reports no epic as lacking a criterion.
- **This project's corpus audit is the Example.**
  The guide shows workflow-server's corpus audit as a labelled Example. Its Corpus Audit section and `format.py`'s reading of the declaration lie outside this task.
- **Consumers.**
  The format check's reader and this project's declaration file consume the path and the four field names stated here.
