**Component:** workspace:skills/work-planner/scripts/format.py

## Overview

The required criteria check holds a project that declares nothing to nothing, and reports only an unreadable declaration as unevaluable.

## Problem

- **Nothing declared reads as a fault.**
  `required_criteria` returns the criteria unevaluable for a missing `config/required-criteria.json`, an empty file and `[]`, so every epic of a project requiring no criterion is reported `required criteria unevaluable`.
- **The guide states the same rule.**
  The Required Criteria bullet in artifacts/epic-issue-body.md groups those three with unreadable JSON, and the format.py module and function docstrings repeat it.

## Proposal

A project with no recurring criterion, such as prosiform, runs the epic format check with `--project` and `--revision`.

- **Nothing declared requires nothing.**
  A missing file at the evaluated commit, an empty or whitespace-only file, and `[]` yield no required criterion and no finding.
- **Only an unreadable statement is unevaluable.**
  A revision resolving to no commit, unreadable JSON, a value other than an array, and an entry lacking a field stay unevaluable, each named.
- **One home for the rule.**
  The Required Criteria section of artifacts/epic-issue-body.md states it; the format.py docstrings describe the code's behaviour in the same terms.
