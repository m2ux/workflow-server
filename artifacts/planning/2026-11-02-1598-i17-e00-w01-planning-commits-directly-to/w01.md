**Component:** workspace:skills/work-planner/modes/plan-mode.md

## Overview

Plan Mode commits every planning artifact, draft bodies and work items included, straight to the engineering branch in its planning record's folder. It opens no planning branch and no discussion pull request, which agrees with the planning record's own rule that the engineering branch takes no further branch.

## Problem

- **Two homes for one plan.**
  Plan Mode step 2 populates a discussion body and opens a draft pull request from a planning branch, and step 7 updates that pull request, while the planning record states the engineering branch takes no further worktree and no branch.
- **Drafts outside the record.**
  The skill's Bodies convention keeps body files outside the repository, so a plan's draft initiative and epic bodies never reach its committed record.

## Proposal

A planner runs Plan Mode for a new initiative: the record folder is added on the engineering worktree, drafts and work items are written into it, and each round of edits is committed and pushed there.

- **Drafts live in the record.**
  Plan Mode writes each draft body under the record's folder and registers it in the README, so the local file that is the source for every later edit is the committed one.
- **One publication route.**
  Steps 2, 6 and 7, each of which writes the record, call Publish Planning Record; the discussion body, the draft pull request and the step 7 update of that pull request are removed.
- **Obsolete surface goes with its caller.**
  Open Discussion Pull Request and the planning-discussion kind of Publish Pull Request are removed from the pull request artifact. The planning record's Layout owns the rule that a plan's drafts and work items are files of its record; the Bodies convention and the Check Dependencies command link it rather than placing every body file outside the repository. Plan Mode's prerequisites are recalculated.
