**Component:** skills/work-planner/scripts/board-queue.py

## Overview

The queue moves an inactive epic In Progress under a waiting initiative to Backlog, as board delivery does, and the Backlog cascade test asserts the method of each assignee call.

## Problem

- **An idle epic keeps In Progress.**
  Under an initiative kept In Progress only by its open pull requests, `Queue.activate` returns before placing any startable epic, and `Queue.park` moves only Ready epics. An inactive epic already In Progress keeps In Progress, while `board.py` moves it to Backlog, so the two scripts disagree for one pass. `board-queue.md` does not state the case.
- **The cascade test reads no method.**
  `test_unstarted_epics_return_without_an_assignee_and_done_stays` asserts `repos/o/r/issues/3/assignees -f 'assignees[]=me'`, which a POST call matches as well as a DELETE.

## Proposal

- **Park reads waiting initiatives.**
  `Queue.park` walks each loaded initiative's rows. Under a waiting initiative, a Ready epic and an open epic In Progress that is not active go Backlog; an active epic stays In Progress. Under an initiative ending neither Ready nor In Progress, a Ready epic goes Backlog. The rule covers every waiting initiative, whether next set, lower set or unplanned, since only the next set reaches `activate`.
- **The guide states it.**
  The Epic Status bullet in `board-queue.md` and the module docstring name the inactive In Progress epic.
- **The test asserts the method.**
  Both assignee calls are asserted in full, `gh api --method DELETE ...`, and no POST to an issue's assignees appears.
