## Overview

Work Planner states 79 command specifications in one catalog, and every mode opens that catalog to reach the few operations its procedure runs. This epic puts each specification in the file whose procedure runs it, leaves the catalog holding only what several procedures share, fixes the set of top-level sections a mode file may carry, and reaches both rules through the shared skill-file check so the layout holds without anyone remembering it.

## Problem

- **One catalog answers every mode.**
  [`references/commands.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/commands.md) holds 79 specifications across 870 lines, 30 percent of the skill's markdown, and all ten mode files link into it. 31 of the 79 are cited from one file.
- **The conventions ride on the catalog.**
  The execution conventions every specification assumes sit at the head of that file, so a procedure reaching them opens the file holding all 79.
- **Mode files differ in shape.**
  Eight of the ten carry Prerequisites, Procedure and Rules alone. [`deliver-mode.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/deliver-mode.md#L44) adds Brief and [`hoist-mode.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/hoist-mode.md#L14) adds Placements, so what a mode states and where it states it are not predictable from the file before it.
- **Five links resolve by file order.**
  [`review-criteria.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/review-criteria.md) titles a heading `Proposal` four times and `Acceptance Criteria` three times, once per issue kind. Five of those repeats are cited, and each citation reaches the first heading of that title rather than the kind it names.
- **Two layout faults stand against the shared check.**
  [`hoist-mode.md:81`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/hoist-mode.md#L81) carries a 113-character inline bold lead against a 100-character limit, and [`standup-mode.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/standup-mode.md#L57) ends on a blank line.

## Proposal

- **A specification stands in the file whose procedure runs it.**
  Each mode file gains a Commands section holding the operations only that mode runs, with the conventions governing them above it in the same file. The reader meets the operation at the point of use rather than through a link out.
- **The catalog keeps what several procedures share.**
  Specifications cited from more than one file stay in one place, so an operation two modes run is still stated once and changed once.
- **The conventions become a file of their own.**
  The execution conventions move to `references/command-conventions.md`, read once per session, so reaching them costs the conventions alone.
- **A mode file's top-level sections are a fixed set.**
  The skill's authoring guide names the sections a mode file may carry, and anything a mode needs beyond them is a sub-section under one of them. Brief and Placements become sub-sections of the procedures that use them.
- **One check decides both rules.**
  `skills/scripts/check_skill_files.py` gains a rule for a specification cited from one file other than its own, and a rule for a top-level section outside the named set. Both bind every skill in the repository, so the layout is measured rather than remembered.
- **The reduction is measured.**
  Each mode's retrieval is recorded under the skill's representative scenarios against the layout before the change and the layout after it, so the claim rests on a walk rather than on arithmetic.
