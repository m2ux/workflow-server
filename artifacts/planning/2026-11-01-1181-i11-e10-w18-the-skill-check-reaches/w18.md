**Component:** workspace:.github/workflows/verify-skills.yml

## Overview

The repository holds a skill-file check that measures link resolution, command-specification placement, mode-file section sets and bullet layout across every skill, and nothing runs it. This task gives the branch the skills live on a job that runs the check over every skill on each pull request and push, so a layout fault is reported by the job rather than by an agent that remembers to run it.

## Problem

- **Nothing in the repository invokes the check.**
  A search for `check_skill_files` across the `workspace` tree at [`ba441c2b`](https://github.com/m2ux/workflow-server/tree/ba441c2b) returns the script, its own tests and the prose that tells an agent to run it. The branch carries no `.github/` directory at all.
- **The engine's verify job cannot see the skills.**
  [`verify.yml`](https://github.com/m2ux/workflow-server/blob/main/.github/workflows/verify.yml) lives on `main` and fires on `main`, `i<n>/main` and `i<n>/e<n>/main`. GitHub reads a push's workflows from the branch pushed to, and `workspace` holds none.
- **A skill carries findings today.**
  The check reports six findings over `skills/gitnexus` at `ba441c2b`: five command specifications in the `gitnexus-cli` entry point and one bold lead over the width limit. The other three skills report none.

## Proposal

The skills, the shared guidelines and the check all live on `workspace`, and the epic and initiative bases promoted into it carry the same tree. Each long-lived branch carries the workflows that grade its own tree, as `main` does for the engine and `workflows` for the corpus.

- **A workflow on `workspace` runs the check.**
  `.github/workflows/verify-skills.yml` runs `skills/scripts/check_skill_files.py` once over every folder under `skills/` that holds a `SKILL.md`, and a finding fails the job.
- **It fires where the skills live.**
  It runs on every pull request whose tree carries it and on a push to `workspace`, `i<n>/workspace` or `i<n>/e<n>/workspace`.
- **An excluded skill is named with its reason.**
  A skill the check reports findings over when the job reaches it is listed in the workflow with the findings that keep it out, so the job starts green and a new finding is a new fault. The list is empty once every skill reports none.
- **An exclusion lapses with its reason.**
  A second job runs the check over each excluded skill and fails when one reports no finding, so the change that clears a skill also brings it into scope.
