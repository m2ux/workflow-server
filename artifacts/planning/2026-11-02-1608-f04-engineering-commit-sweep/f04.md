**Component:** workspace:skills/work-planner/artifacts/planning-record.md

## Overview

Every commit on the engineering worktree sweeps it: it stages everything pending, commits when anything is staged, rebases on `origin/engineering` and pushes. Any session can then publish the shared worktree at any time, and no session's record is stranded.

## Problem

Commit Planning Record commits one folder by path, so a session that stops before its own commit leaves its files uncommitted, and a `design.md` edit outside any folder has no operation that commits it. Shared Worktree asks each session to confirm its files sit in a commit of its own, an isolation the user does not want.

## Proposal

Sessions write planning records and design edits into the one engineering worktree and publish them straight to the branch.

- **Commit Planning Record sweeps.** One command runs `git add -A`, commits only when the index differs from `HEAD`, runs `git fetch origin engineering && git rebase origin/engineering`, and pushes. A second run with nothing new changes nothing.
- **Push Engineering Branch is folded in.** The sweep pushes, so the separate push command goes, and Publish Planning Record runs one command.
- **Shared Worktree states the sweep.** A commit may carry other sessions' uncommitted or unpushed work; a session confirms only that its own files reached `origin/engineering`.
- **The plan-mode test reads the sweep.** It asserts the sweep command rather than the path-scoped commit.
