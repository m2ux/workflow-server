## Overview

The script registry's Kind interface carries no review operation, so `agent_review.py` applies one finding rule and one branch currency to every registered kind of work. This issue asks for that rule to come from each kind, matching the Review Before Merge operation the Work Planner entry point registers.

## Problem

- **The script interface lags the registration.**
  `skills/work-planner/SKILL.md` registers Review Before Merge as an operation hot-fix supplies. `scripts/kinds.py` declares no matching operation, so no kind module can supply its own review rule.
- **Every registered kind receives hot-fix's rule.**
  `agent_review.check` selects a pull request's kind with `kind_of` and, for any kind, requires every finding fixed and holds a record current by head SHA and `base_ref`. A second kind with its own review rule means editing `agent_review.py`.

## Proposal

- **A review operation on the Kind interface.**
  `kinds.Kind` declares the operation the review validator needs, with its inputs and results: which record fields make a record current, and the finding fault a kind adds.
- **Hot-fix supplies it.**
  `hotfix.py` supplies the operation with today's rule: currency by head SHA and base branch, and every finding fixed.
- **The validator asks the selected kind.**
  `agent_review.check` reaches the rule through `interface(kind_of(pr))` and keeps no rule of its own for a kind.
