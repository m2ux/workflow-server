**Component:** workspace:skills/work-planner/artifacts/hotfix.md

## Overview

Hot-fix supplies its lifecycle decisions to the shared board-change contract.

## Problem

Its Board Status guidance cites Board Delivery's shared Status Changes policy, coupling subject-owned lifecycle conditions to the current placement of generic board-change derivation.

## Proposal

Keep hot-fix-specific lifecycle conditions with Hot-fix and consume the extracted Board Status result and capabilities from the settlement operation. Fields describe actual data; policy remains Guidance or owning command/operation conditions. No issue-lifecycle protocol substitutes for the status derivation, and no shared file enumerates hot-fix cases.

## Work Breakdown

| Part | Description |
| --- | --- |
| Analysis | The current closure/status guidance reference, settlement operation and existing hot-fix/status consumers and regressions. |
| Plan | Separate subject lifecycle decisions from proposed board changes and from the steps applying and confirming them. |
| Implementation | Revise hotfix.md contract links and performing calls atomically with Board Status and Board Delivery; preserve current role tags and context selected through links. |
| Review | Every condition has one owner, data fields contain no hidden operation, and the former Board Delivery Status Changes target is absent. |
| Test | In the joined extraction, verify completed and other closure, draft/ready/held state, malformed or missing evidence and status write/readback outcomes with existing hot-fix, board, queue and status fixtures. |
