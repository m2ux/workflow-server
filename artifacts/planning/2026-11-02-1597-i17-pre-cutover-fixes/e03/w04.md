**Component:** workspace:skills/work-planner/scripts/deps.py

## Overview

The dependency check reads each work item's lane beside its component and refuses a joined unit whose rows declare different lanes. Its lane reader is the one the delivery survey and the board queue import, as they import its component reader.

## Problem

- **The script reads one declaration.**
  `read_components` matches only the `**Component:**` line, so no script reads a lane.
- **A split unit passes.**
  Nothing stops a joined unit whose rows a later Deliver run in one lane could take only in part.

## Proposal

The dependency check runs over an epic whose joined rows declare lanes 1 and 2.

- **One reader for both declarations.**
  The work-item reader returns each task's lane beside its component, reading `**Lane:** <id>` ahead of the first heading, with the same tolerance for a code span or trailing full stop the component reader has. A work item without the line is unlaned.
- **A split joined unit is a problem.**
  A joined unit whose rows declare different lanes, an unlaned row among laned ones included, is printed under problems naming each row and its lane, and the run exits nonzero.
