**Component:** workspace:skills/work-planner/artifacts/dependency-graph.md

## Overview

Joined rows share one lane. The dependency graph states that as a condition of a joined unit, so Plan and Align, which both run the dependency check, report a unit whose rows carry different Lane indices, and Deliver never meets one.

## Problem

- **A joined unit is one session's work.**
  [Joins](https://github.com/m2ux/workflow-server/blob/b2844c821ce800ed3d12735bdf339049594e5ec5/skills/work-planner/artifacts/dependency-graph.md#joins) makes rows that name each other one pull request, delivered by one session.
- **Lanes can split it.**
  Once rows carry Lane cells, two joined rows can name different lanes, and no lane's run could take the unit whole.

## Proposal

A planner joins two rows that share a component, one planned in lane 1 and the other in lane 2.

- **Joined rows share a lane.**
  Every row of a joined unit has the same Lane index, or every Lane cell is empty.
- **A split unit is a finding to settle.**
  It is settled by moving a row's lane or by unjoining the rows. Plan and Align report it through [Check Dependencies and Numbering](https://github.com/m2ux/workflow-server/blob/b2844c821ce800ed3d12735bdf339049594e5ec5/skills/work-planner/artifacts/dependency-graph.md#check-dependencies-and-numbering), which both already run, so neither mode restates it.
- **The check refuses such a unit.**
  Check Dependencies reports a joined unit whose rows carry different Lane indices as a problem naming its rows and their lanes, and exits nonzero.
