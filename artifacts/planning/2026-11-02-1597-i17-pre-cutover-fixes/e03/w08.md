## Overview

The board queue reports each Ready unit's lane, so the user deciding what each session takes sees the lanes before any run starts.

## Problem

- **The queue stops at epics.**
  The [`next` line](https://github.com/m2ux/workflow-server/blob/b2844c821ce800ed3d12735bdf339049594e5ec5/skills/work-planner/artifacts/board-queue.md#report-lines) names Ready epics, and [Task Eligibility](https://github.com/m2ux/workflow-server/blob/b2844c821ce800ed3d12735bdf339049594e5ec5/skills/work-planner/artifacts/board-queue.md#task-eligibility) decides which rows are Ready, but the queue reads no work item, so it cannot say which lane a Ready unit is in.

## Proposal

A user reads the queue before starting a session for each lane.

- **The queue reads the work items.**
  The queue takes the engineering worktree, where each free row's work item is read for its lane. It reads files there and runs no git.
- **A lane per Ready unit.**
  For each Ready epic, the report names each unit whose rows Task Eligibility makes Ready, with its lane id, or unlaned.
- **Placement is unchanged.**
  Lanes change no Status and no priority; they are reported only.
