## Overview

The available-work survey takes the lane a run serves and offers only the units that lane admits, so two Deliver sessions on one board never confirm the same unit. This is the filter prosiform's I10 waits on to run two sessions.

## Problem

- **The survey offers every unit.**
  `deliver.py` prints a `unit` line for every available unit, whoever the run serves, so a second session is offered the unit the first is about to hold.

## Proposal

Two sessions run the survey on one board, one with `--lane 1` and one with `--lane 2`.

- **A lane input.**
  `--lane <id>` names the lane the run serves. A unit is offered when every row declares that lane or none does; a run without `--lane` is offered only unlaned units. Hot-fix units declare no lane.
- **The lane comes from the work items.**
  Each free row's lane is read from the work item it links in `--engineering`, through the dependency check's reader.
- **The unit line names its lane.**
  Each `unit` line carries the lane id, or names the unit unlaned.
- **Nothing else changes.**
  Availability, holds, blocked rows and merge lines are read as before; the lane filters which units are offered.
