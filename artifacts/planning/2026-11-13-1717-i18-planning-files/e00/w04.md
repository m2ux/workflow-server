## Overview

This task adds a layout check that a new planning record meets Planning Record's general layout, run before the record is published.

## Problem

A record's layout is checked by nobody. Records hold files their README does not list and README rows linking files that are absent, and a record's folder name departs from the dated naming, as the [file-kind survey](../file-kinds.md) shows for the folders it read.

## Proposal

The scene: Plan Mode publishes the record it has just written.

- **One script, general rules only.**
  `scripts/planning-record.py <folder>` reports each departure from Planning Record's general layout: a folder name that is not `<yyyy-mm-dd>[-<ref>]-<slug>`, a README lacking the Template's header or sections, a file the Artifacts table does not link, and an Artifacts row linking a file the folder lacks. It reads no owner's file kind; each owner's template is that owner's.
- **New records only.**
  Planning Record states the date the check took effect; a folder dated earlier is left as written and the check passes it, and a newer folder is checked on every publish.
- **Publish runs the check.**
  Publish Planning Record runs the check on the folder before Engineering Branch's publish operation and stops on a finding.
- **Size.**
  One script of plain directory and Markdown reads, one fixture module and one command specification: one pull request's worth.
