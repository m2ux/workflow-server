## Overview

This task narrows Planning Record to what holds for every record: the collection of files as a whole, its dated folder name, its place in the engineering worktree, its README index, and how a file joins it. It defines no specific file kind.

## Problem

Planning Record mixes a record's contents with general rules.

- **A kind statement in Layout.**
  Layout states that a plan's draft issue bodies and its work items are files of its record, a statement about two kinds whose owners are Initiative Issue Body, Epic Issue Body and Work Item.
- **Joining is implicit.**
  How a file becomes part of a record is spread across Populate Planning Record's registration step and the Artifacts field.

## Proposal

The scene: an owner such as Goal Trace hands Plan Mode a trace file for the record.

- **Fields own the general record.**
  Planning Folder states the dated name and its place under the configured planning directory in the engineering worktree that Engineering Branch finds. Template and Artifacts state the README index. A Joining field states how a file joins: its owner supplies the path and the row text, and Populate Planning Record registers it.
- **No kind in Layout.**
  Layout states README.md and that every other file is an owner's, named by that owner. The draft and work-item sentence leaves.
- **Publication through Engineering Branch.**
  Publish Planning Record applies Engineering Branch's publish operation for the folder.
