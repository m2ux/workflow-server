## Overview

This task gives each file a delivery record holds its owner, as the plan-side owners do for a plan's record.

## Problem

Delivery-side record files are written by habit.

- **Results have no named file.**
  Test Plan's Result Evidence places test procedures and results in "the work's published planning document". Records hold `test-results.md`, `test-evidence.md`, `validation.md` and `evidence.md` for that one content, as the [file-kind survey](../file-kinds.md) shows.
- **Review notes duplicate the review record.**
  Records carry `review-notes.md` beside `agent-review.json`; the notes restate the record's findings and its `scope`'s exclusions, and no artifact defines them.
- **Overviews and review records are placed by the caller.**
  Change Overview and Review Pull Request register the file; Agent Review and Architecture Overview state no path.

## Proposal

The scene: a delivery session runs a unit's tests, opens its pull request, and has it reviewed.

- **Each owner states its record file.**
  A Record File field, shaped as the plan-side owners' field, in each owner:
  - Test Plan: `test-results.md`, one section per Test id with the revision tested, the procedure, the result and its evidence, each section the anchor a Pass link names.
  - Agent Review: `agent-review.json`, the Review Record list.
  - Architecture Overview: `architecture-overview.md`, its Template.
- **Review notes leave.**
  The Review Record holds findings, dispositions, fix evidence and exclusions, so no further review file is written.
- **Callers take the path from the owner.**
  Deliver Mode, Change Overview, Review Pull Request and Hot-fix register each file by its owner's Record File and state no path.
