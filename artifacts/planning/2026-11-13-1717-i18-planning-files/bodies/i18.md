## Overview

Planning is a collection of files with a structure and a location, and each rule about it has one home. Engineering Branch owns where engineering-side content lands and how, Planning Record owns what holds for every record, and each file a record holds is defined by the artifact whose subject it is. The goal the reviews test against: a new planning record is laid out by one general artifact, published through one branch artifact, and holds each file where its owner says, with its owner's template.

## Problem

A record's rules are scattered and its files are written by habit.

- **One artifact holds three subjects.**
  [Planning Record](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/planning-record.md#L60-L89) holds the git commands that publish the engineering branch beside a record's folder and contents, and its [Layout](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/planning-record.md#L145) names two specific file kinds.
- **The branch rule sits apart from the branch.**
  [Rules](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/rules.md#L11-L12) states the engineering branch's direct push, and [Delivery Branches](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/delivery-branches.md#L366) restates its missing epic base.
- **File kinds have no owner.**
  [Plan Mode](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/modes/plan-mode.md#L40-L41) asks for "an output path in the record's folder", and [Goal Trace](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/goal-trace.md#L68) and [Test Plan](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/test-plan.md#L36) name no file, so one content is written under several names across records.
- **Nothing checks a record's layout.**
  Recent records hold files their README does not link and links to files they lack, as the survey in the planning record measures.

## Proposal

- **A branch artifact.**
  Engineering Branch finds the engineering worktree, commits, rebases and pushes it, and states that the branch takes direct pushes with no epic base, task pull request or review pull request. Planning records and every other engineering-side file publish through it.
- **A general record artifact.**
  Planning Record states the record as a collection: its dated folder name, its place in the engineering worktree, its README index and how a file joins it. It defines no file kind.
- **Owners define their files.**
  The artifact whose subject a file is states its path within the record and its template, and links Planning Record for the folder. A kind no artifact owns is a working file kept outside the repository.
- **A layout check.**
  A script checks a new record against Planning Record's general layout before it is published.

## Acceptance Criteria

- [ ] **AC1.** Engineering Branch is the one home of where and how engineering-side content lands, and every step publishing to the engineering branch reaches it there, as the skill's fixture suite shows.
- [ ] **AC2.** Planning Record states only what holds for every record and defines no specific file kind, as the skill's fixture suite shows.
- [ ] **AC3.** Every file kind a planning record holds has one owning artifact stating its path and template, and no other skill file states that path, as the record-file fixture suite shows.
- [ ] **AC4.** A planning record opened once the layout check lands is checked against the general layout before it is published, as the layout check's fixture suite shows.

## Non-Goals

- It does not change or move a record opened before the change.
- It does not check a record file's content against its owner's template.
