## Overview

This epic gives planning's files their owners. It adds Engineering Branch, narrows Planning Record to the general record, has each owning artifact define the file it places in a record, and adds a layout check run before a record is published.

## Problem

- **The branch's rules have no home of their own.**
  [Rules](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/rules.md#L11-L12) states the direct push, [Planning Record](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/planning-record.md#L60-L89) holds the commit and push commands, and [Delivery Branches](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/delivery-branches.md#L385) restates the exception for a unit's files.
- **Planning Record names specific files.**
  Its [Layout](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/planning-record.md#L145) states that draft bodies and work items are files of the record.
- **Plan-side files are placed by the caller.**
  [Plan Mode](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/modes/plan-mode.md#L40-L41) supplies every output path, and [Goal Trace](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/goal-trace.md#L68) names no file.
- **Delivery-side files are placed by habit.**
  [Test Plan](https://github.com/m2ux/workflow-server/blob/31ad621783f0b2cd415b1248f9e33785c698e1b9/skills/work-planner/artifacts/test-plan.md#L36) names "the work's published planning document", which records write under four names.
- **A record's layout goes unchecked.**
  Recent records hold unlinked files and links to absent ones, as the planning record's survey measures.

## Proposal

- **Engineering Branch.**
  A new artifact holds finding the engineering worktree, the commit-rebase-push publication with its shared-worktree sweep, and the branch rule: direct pushes, no epic base, task pull request or review pull request, rows of a unit changing only this branch linking the pushed commit, and the push's bypass notice expected. Every caller links it.
- **Planning Record.**
  It states the record as a collection: dated folder name, place in the engineering worktree, README index, and how a file joins. Publish Planning Record applies Engineering Branch's publish operation.
- **Owners define their files.**
  Work Item, Initiative Issue Body, Epic Issue Body, Goal Trace, Review Finding, Dependency Graph, Plan Change, Test Plan, Agent Review and Architecture Overview each state the path and template of the file they place in a record, as the planning record's file-kind table lists. Modes and protocols take each path from its owner.
- **A layout check.**
  A script reports a new record's departures from the general layout, and Publish Planning Record stops on them. A record dated before the check takes effect is left as written.
- **Delivery.**
  Every finding a unit's tests, audit or review raises is fixed on its task branch before the pull request merges. The user reviews and merges the epic review pull request; no agent merges it.

## Acceptance Criteria

- [ ] **AC1.** Engineering Branch is the one skill file stating that the engineering branch takes direct pushes with no epic base, task pull request or review pull request and that the push's bypass notice is expected, and every other file applying that rule links it, as the skill's fixture suite shows.
- [ ] **AC2.** Engineering Branch holds the commands that find the engineering worktree and that commit, rebase and push it, and no other skill file holds them, as the skill's fixture suite shows.
- [ ] **AC3.** Every step that commits a file to the engineering branch does so through Engineering Branch's publish operation, directly or through Publish Planning Record, as the skill's fixture suite shows.
- [ ] **AC4.** Planning Record's Fields state a record folder's dated name, its place in the engineering worktree, its README index and how a file joins the record, as the skill's fixture suite shows.
- [ ] **AC5.** Planning Record names no file a record holds other than README.md, as the skill's fixture suite shows.
- [ ] **AC6.** Work Item, Initiative Issue Body, Epic Issue Body, Goal Trace, Review Finding, Dependency Graph and Plan Change each state the path and template of the file it places in a planning record and link Planning Record for the folder, as the record-file fixture suite shows.
- [ ] **AC7.** Plan Mode, Rules and Conventions state no record file's path, as the record-file fixture suite shows.
- [ ] **AC8.** The layout check reports a record folder whose name departs from the dated naming, whose README lacks a section of the README template, which holds a file its Artifacts table does not link, or whose Artifacts table links a file the folder lacks, as its fixture suite shows.
- [ ] **AC9.** Publish Planning Record runs the layout check on a record dated on or after the date Planning Record states, before committing it, and stops on a finding, as the skill's fixture suite shows.
- [ ] **AC10.** Test Plan, Agent Review and Architecture Overview each state the path and template of the file it places in a planning record and link Planning Record for the folder, as the record-file fixture suite shows.
- [ ] **AC11.** Deliver Mode, Hot-fix and the protocols that write a record file state no record file's path, as the record-file fixture suite shows.
