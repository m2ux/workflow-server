## Overview

Work Planner loads common rules and conventions before mode selection and keeps deployed values in linked configuration sections. The shared checker validates heading procedures and HTML invocations for each selected model, using the same parser and contract ownership for citation and interface checks. Modes and protocols expose ordered heading steps and explicit artifact and procedure calls.

## Changes

The epic base carries the declared-model checker capability, its acceptance/rejection specimens, Work Planner's common context files and its mode and protocol presentation.

### Declared Models

- **Structure selection.**
  Explicit file entries select entry layouts; typed options describe heading steps, preambles, field contracts and call verbs.
- **Procedure contracts.**
  Step sequences follow their parent procedure, and Inputs/Outputs resolve the owning artifact's field contracts.

### Invocation Reading

- **Literal command payload.**
  One lexical reader owns Markdown fences and HTML invocations, preserving shell text and required bold argument links.
- **Execution and interfaces.**
  Selected invocation models require executing-step placement, with GraphQL REST-gap evidence scoped there and Projects V2 checks preserved.

### Common Context

- **Rules and conventions.**
  `skills/work-planner/SKILL.md` selects modes after loading `rules.md` and `conventions.md`, preserving their operative conditions.
- **Configuration.**
  Board titles and fields, planning-record placement and the reporting default have one documented home; consuming sections select applicable configuration reads.
- **Reader ownership.**
  Guidelines and checkout-vocabulary validation use the extracted homes while installed model declarations remain selected.

### Mode Procedures

- **Ordered actions.**
  Mode procedures use numbered heading steps, scoped flush detail and Rules/Conventions/Outcomes preambles, preserving prerequisite and checkout declarations.
- **Verification procedures.**
  Revise's named verification procedures hold HTML invocations and linked argument contracts with preserved command syntax and explicit examples.
- **Source readers.**
  Mode readers select heading steps and recognize Apply calls while preserving draft-publication, caller-coverage and epic-base assertions.

### Protocol Procedures

- **Ordered coordination.**
  All seven protocols use numbered heading steps, Rules/Conventions preambles and scoped flush conditions while preserving prerequisites, inputs, refusals and return points.
- **Layered invocation.**
  Artifact operations use Apply and whole-protocol calls use Follow, including repeated calls to existing required callees.
- **Evidence boundaries.**
  Literal-head and merged-revision instruments preserve the walked protocol bytes and test the actual source composition. Independent reading observations remain Partial; inherited prerequisite, receipt, authority and live-evidence limits remain recorded.
