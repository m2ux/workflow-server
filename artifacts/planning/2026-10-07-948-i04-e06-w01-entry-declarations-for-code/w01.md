# W01 — Entry Declarations for Code-Graph Operations

## Overview

A code-graph operation whose answer is a list publishes a shape for one entry of it, and a step downstream reads fields off that entry. Twelve operations in the code-graph namespace declare such an output and three of them state what an entry carries, so for the other nine the shape lives in a sentence and a wrong read is measured against nothing. This task settles each of the nine against the operation's own response from an indexed graph — declaring the fields where the response carries them, saying so where the answer has no entry shape at all — and adds the runs that hold the declarations to the responses and the corpus to the check.

## Problem

- **Nine list-returning operations describe their entry in prose.**
  Twelve techniques in the code-graph namespace declare an output that is the collection the caller walks; three declare [`#### entry`](https://github.com/m2ux/workflow-server/blob/860e107b/corpus/support/gitnexus/techniques/list-group-members.md#L26-L38) and the rest carry the fields in a sentence under the output.
- **The check only reaches a declaration.**
  `entry-field-undeclared` measures a read off a loop item against the fields the iterated collection declares, and [only where that collection declares some](https://github.com/m2ux/workflow-server/blob/1caa9ff5/guards/check-binding-fidelity.ts#L1189-L1191). An operation describing its entry in prose puts every read off it outside the check.
- **The prose and the response disagree, and nothing says which is right.**
  Two operations describe an inventory the caller walks where the answer is a report carrying one: `gitnexus_tool_map` answers `{"tools": [], "total": 0, "message": …}` and `gitnexus_route_map` answers `{"routes": [ … ], "total": 1}`. A third names its entry's fields in a query whose answer spells them `s.name` and `s.filePath`.
- **A declaration transcribed from a sentence can be wrong in the way the whole mechanism exists to catch.**
  The defect that opened the work was [a run naming flows by a field the answer does not carry](https://github.com/m2ux/workflow-server/issues/874), which ran to completion reporting success. Absent, a read is unmeasured; wrong, it is measured against a lie and passes.
- **Nothing holds the declarations to the responses.**
  The guard's test file carries fixtures for the check and no run over the corpus, so a declaration naming a field no answer carries would land unmeasured — and no record of any response sits anywhere a later reader can re-check a field name against.

## Proposal

The field names come from calling each operation against an indexed graph and reading what comes back. Where the response has no entry to name, that is the finding and the output says so rather than gaining a declaration that invents one.

- **The subject is derived, not counted.**
  A code-graph operation is a technique of the `support/gitnexus` namespace whose protocol reaches the graph — a `gitnexus_*` call or a `gitnexus://` read. A list-returning one declares an output that is the collection the caller walks. Both are read off the files by a scan, and the roster the scan produces is what the completeness run holds the corpus to.
- **The declaration sits where the response puts the list.**
  An output that is the list declares `#### entry`; an answer that wraps its list in a report declares the fields under the `####` component holding it, which is the notation the schema admits and the only one that reaches a wrapped list.
- **An answer with no entry shape says so.**
  A trace keyed by step number, a single column of paths, and one name holding two different collections each describe something a step cannot read a field off. Each output states that, as the group freshness report already states it of its members, so a step iterating one as a list is told rather than left to find out.
- **An entry no indexed graph can show stays undeclared.**
  The tool inventory answers empty from all eighteen indexed graphs, so its entry's fields cannot be settled. The report's own shape is declared, the entry's is not, and the coverage report names it.
- **The responses are kept, and the declarations are held to them.**
  Each settled operation's response is recorded as captured, with the graph and the call behind it. A run parses each response and holds the technique's declared fields against the keys one entry of it actually carries, so the claim is re-checkable rather than a transcription nobody can audit.

## Work Breakdown

| Part | Description |
| --- | --- |
| Enumerate | Scan the code-graph namespace for the techniques whose protocol reaches the graph and the outputs they declare as the collection the caller walks, and record the roster the scan produces. |
| Probe | Call each operation of the roster against an indexed graph, through the MCP server over stdio where the harness does not serve the tool, and record each response as captured with its graph and call. |
| Settle | Decide each output against its response: the fields an entry carries, the grain the declaration sits at, or the statement that the answer has no entry to name. Record the direction and its evidence per output. |
| Corpus | Write the declarations and the statements into the technique files, alias the composed query so its answer spells the fields it declares, and bump each edited definition's version. |
| Server | Add the fixture of captured responses and the runs over it: each declared field against the keys one entry of its response carries, the roster against the corpus, and the check's entry-field family over the corpus. |
| Review | Re-run the full guard sweep on the edited corpus against the same sweep on the unedited base, so a guard this work turns red is told apart from one already red. |
| Test | The response fixture run; the roster completeness run; the declaration-against-response run; `check-binding-fidelity` over the corpus, with its `entry-field-undeclared` family asserted empty; the existing fixture cases for that family; the full `check:all` sweep, base against edited; `npm run typecheck`; and the whole `vitest run` suite, base against edited. |
