## Problem

Configuration from a different revision can produce a verdict about rules the evaluated change never contained. Missing configuration can also make a skipped check look successful.

## Proposal

- **Source identity.**
  Read the required-criteria declaration at the evaluated commit using the declaration shape supplied by W01. Match declared criterion identifiers without project-specific vocabulary. Record the source repository, commit and path; report missing, empty or unreadable declarations as unevaluable without fallback. Reuse the established source-selection contract without requiring a new cross-epic implementation dependency.
- **Verification cases.**
  Use divergent subject and long-lived values, identical commits invoked from different worktrees, dirty working files, absent and empty declarations, unreadable revisions, and configuration present only at another revision. Assert both selected values and explicit unevaluable results.
