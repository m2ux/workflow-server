# W01 — Guard Imports That Resolve

## Overview

The role-barred-calls guard imports three names `src/loaders/core-ops.js` does not export, so `tsc -p tsconfig.tools.json` exits at those three errors and `tests/role-barred-calls-guard.test.ts` fails to load. This task makes the guard read an orchestrator's technique refs from the place that holds them, so the tools typecheck completes and the guard's test file reports a verdict on each of its cases.

## Problem

- **The guard and the roster it reads were written against different states of `core-ops`.**
  [`guards/check-role-barred-calls.ts`](https://github.com/m2ux/workflow-server/blob/71459f89/guards/check-role-barred-calls.ts#L60-L67) imports `CORE_ORCHESTRATOR_TECHNIQUES`, `FAN_DISPATCH_TECHNIQUES` and `ORCHESTRATOR_CHECKPOINT_TECHNIQUES`.
- **`core-ops` exports none of the three.**
  [`a20e52d9`](https://github.com/m2ux/workflow-server/commit/a20e52d9) retired the orchestrator roster: an orchestrator carries a role activity, `get_activity` serves that activity's own step bindings, and what no step binds is declared on the workflow's `techniques.activity`. The module now exports `CORE_WORKER_TECHNIQUES`, `WORKER_CHECKPOINT_TECHNIQUES`, `FAN_ONLY_RULES`, `LOOP_ONLY_RULES` and `contractOperations`.
- **The subject is not on this epic's base.**
  Measured 2026-10-13: `npm run typecheck` completes on `main` and on `i14/e07/main`, both at `ec05e7f6`, which hold neither the guard nor its test file. `tsc -p tsconfig.tools.json` on `i14/e04/main` at `71459f89` reports the three errors — the only branch the defect is reachable from, and one with an open pull request, [#1382](https://github.com/m2ux/workflow-server/pull/1382).

## Proposal

The guard's `ROLE_BUNDLES` names what each role receives. The worker half holds; the orchestrator half names a roster that no longer exists, and re-exporting it would restore delivery the engine has stopped making — the guard would then measure a bundle no orchestrator is sent.

- **The orchestrator's refs come from the role activity.**
  The guard reads meta's `techniques.activity` and the role activity's step bindings, the two homes `a20e52d9` moved that delivery to. [`guards/check-harness-adapter-set.ts`](https://github.com/m2ux/workflow-server/blob/ec05e7f6/guards/check-harness-adapter-set.ts) already reads a set from the first of them.
- **The unreachable-bundle-ref finding follows the refs.**
  Its remedy names `src/loaders/core-ops.ts`; with the refs read off the corpus, the remedy names the definition that declares them.
- **The fix belongs on the branch that carries the guard.**
  The file, its test and the failing typecheck all live on `i14/e04/main`. Delivering the correction anywhere else puts two copies of one guard on two branches and a conflict between them at merge.
