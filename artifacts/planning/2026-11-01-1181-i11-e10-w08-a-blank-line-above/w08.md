**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check reports a heading that carries no blank line above it, so a heading cannot sit flush against the line before it and a strict reader is never left to decide whether it still opens a section.

## Problem

- **A heading can sit flush against the line above it.**
  [`planning-record.md`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/work-planner/artifacts/planning-record.md#L37-L38) puts `## Fields` directly beneath a list item's continuation line. A reader that carries the run into the list never sees the heading, so the section and its anchor are not there for it.
- **The check reads the line as a heading regardless.**
  [`scan`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/scripts/check_skill_files.py#L83) matches a heading by its leading hashes alone, so a citation to `#fields` resolves for the check while a strict reader may find nothing.
- **Nothing else measures the spacing.**
  The check already measures a trailing blank line, bold-lead width, bullet shape and prose length, so file layout is its concern; this is the one spacing fault it passes over.
- **The fault also stands in a fixture corpus.**
  The Workflow Canon audit-qualification [`produce.md`](https://github.com/m2ux/workflow-server/blob/ba441c2b8/skills/workflow-canon/test/fixtures/audit-qualification/clean/corpus/qualification/techniques/produce.md#L4-L5) in each case puts `### report` or `### summary` directly beneath `## Outputs`. The check runs over every skill, its test fixtures included, so the new rule reports both.

## Proposal

The check walks each file's lines once for layout, skipping fenced content and the frontmatter.

- **A heading needs a blank line above it.**
  The check reports a heading whose preceding line is neither blank, nor the start of the file, nor the close of its frontmatter, naming the heading. A fenced block's contents stay exempt, as they are for every other layout rule.
- **The headings that fail it are separated.**
  `## Fields` in the planning-record artifact gets its blank line.
- **The fixture corpus takes the blank line and keeps its expectations.**
  Each `produce.md` gets the blank line under `## Outputs`. The qualification's expected outcomes and its adversarial script address that file by line, so each line they name below the insertion moves down one.
