## Overview

The shared skill-file check gains the two rules that decide skill layout: a command specification belongs in the file whose procedure runs it, and a mode file carries a fixed set of top-level sections in a fixed order. Both are decidable from the skill's own markdown, so the check that already reads every skill is where they belong. The rules land before the restructures measured against them.

## Problem

- **A specification with one caller elsewhere is found by reading.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/guidelines.md#L97-L100) states that a specification sits in the file whose procedure runs it and that a catalog holds only what several procedures share. Nothing measures it: [`references/commands.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/work-planner/references/commands.md) holds 79 specifications, 31 of them cited from one file.
- **The set of top-level sections a mode file may carry is unstated.**
  [`skills/guidelines.md`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/guidelines.md#L51) says a section the procedure draws on sits beside it under a heading of its own, which fixes nothing. Eight such sections stand across the two skills, so what a mode states, and where, is not predictable from the file before it.
- **The check counts anchors, not callers.**
  [`cited`](https://github.com/m2ux/workflow-server/blob/fae97e9e/skills/scripts/check_skill_files.py#L85-L96) records the set of anchors each file is linked to by name and discards which file linked it. A rule about how many files cite a specification cannot be asked of that shape.

## Proposal

The check reads every markdown file of a skill, resolves every link and already judges one rule by use — a duplicate anchor is reported only where something cites it. Both new rules are of that kind, so they extend what the check already holds rather than adding a second instrument.

- **The citation index names its callers.**
  `cited` maps each destination file to each anchor and the set of files citing it, so the callers of a specification are countable. The duplicate-anchor rule reads the same index unchanged.
- **A specification with one caller elsewhere is reported.**
  A sub-section of a file's `## Commands` section cited from exactly one file other than the one holding it is reported against that heading, naming the caller. A specification no file cites, and one two files cite, stand.
- **A mode file carries a named set of top-level sections.**
  Prerequisites, Procedure, Reference, Rules and Commands, in that order. A `<name>-mode.md` carrying a second-level heading outside that set is reported, and so is one carrying those headings out of that order.
- **The shared guidelines state the set and the placement test.**
  The Mode files section names the five sections and what the reader does with a heading to place it: Reference holds what a step consults or produces, Rules what binds the mode whatever step it is on. The next author places a heading from the test rather than from a precedent.
- **The specimens carry the faults.**
  Each rule is shown against a skill seeded in a temporary tree carrying that fault alone, and against a conforming skill that reports nothing, which is how the suite already shows every other rule.

## Work Breakdown

| Part | Description |
| --- | --- |
| Guidelines | The Mode files section of `skills/guidelines.md` names the five top-level sections, their order, and the test that places a heading |
| Citation index | `cited` records the files citing each anchor, and the duplicate-anchor rule reads the index in its new shape |
| Command rule | A `## Commands` sub-section cited from exactly one file other than its own is reported against its heading |
| Section rule | A mode file's second-level heading outside the named set, and the set out of order, are each reported |
| Test | The check's suite seeds a specimen skill per fault — a specification with one caller elsewhere, a mode file with a foreign section, a mode file with the sections out of order — and a conforming specimen for each rule; the whole suite and the check over every skill in the repository both run |
