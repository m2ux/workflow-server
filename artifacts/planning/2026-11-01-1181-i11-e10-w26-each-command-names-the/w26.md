## Overview

Each command acting on its checkout names which one. A closed vocabulary of checkouts, a declaration on each command and procedure, and a test over the citation graph make a call site's intended checkout machine-checkable. Source: [#1458](https://github.com/m2ux/workflow-server/issues/1458).

## Problem

A command whose working directory decides what it changes, such as Merge Remote Branch, is called from procedures that name the intended worktree only in prose. Merge Task Pull Requests ran Update Epic Base with no checkout named, and the structure check and two read-only walks passed over it.

## Proposal

A unit session works in its own worktree and merges through the project's main working tree; a command run in the wrong one merges or places a worktree somewhere else without error.

- **Vocabulary.**
  The entry point's Conventions name five checkouts: `project` (the main working tree), `epic base`, `unit`, `engineering` and `review` (a pull request's detached review worktree). `review` covers the GitNexus commands, which act on the directory they run in as git does.
- **Commands.**
  A command whose block runs git without `-C`, or GitNexus, carries `**Acts on:** the checkout it runs in.` beside Inputs, and its Inputs drop the checkout they could not express. A command taking its checkout as an argument (`git -C`, `cd`) carries none; Find Engineering Worktree takes that form.
- **Operations.**
  An artifact operation declares no checkout of its own. One whose steps run an acting command acts on a checkout too, and every call to either names one as `the <name> checkout` on the line that makes it.
- **Procedures.**
  Each mode and protocol carries `**Runs in:** the <name> checkout.` under its opening paragraph. Every one runs in `project`; Run Delivery Session runs in `unit`.
- **Calls into another checkout.**
  A call naming a checkout other than its procedure's passes it: the operation called names it among its Inputs, the protocol or mode called runs in it, or the command called acts wherever it runs. A call to a protocol or mode running elsewhere names that checkout.

### Decisions

- **Artifact operations declare no context.** Neither declare nor inherit: an operation's own calls each name their checkout, so the check reads one line per call and needs no caller-context walk.
- **`project` is the main working tree.** Worktree paths are anchored to it, so it is distinct from every linked worktree; a script's `--project` still takes any checkout, as the Example values state.
- **Merge Task Pull Requests takes the unit checkout.** Its Update Task Branch call needs the worktree holding the task branch, which its Inputs did not supply.
- **The delivery brief carries the project checkout.** Run Delivery Session passes it to Merge Task Pull Requests.
