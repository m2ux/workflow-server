## Overview

Each command acting on its checkout names which one. A closed vocabulary of checkouts, a declaration on each command and procedure, and a test over the citation graph make a call site's intended checkout machine-checkable. Source: [#1458](https://github.com/m2ux/workflow-server/issues/1458).

## Problem

A command whose working directory decides what it changes, such as Merge Remote Branch, is called from procedures that name the intended worktree only in prose. Merge Task Pull Requests ran Update Epic Base with no checkout named, and the structure check and two read-only walks passed over it.

## Proposal

The entry point's Conventions name the checkouts once: `project`, `epic base`, `unit` and `engineering`. A command whose behaviour depends on its working directory carries `**Acts on:** the checkout it runs in` beside its Inputs. Each mode and protocol, and each procedure subsection whose context differs from its file's, carries `**Runs in:** the <name> checkout`. Each call to a declaring command names a checkout from the vocabulary, and a call naming a checkout other than its procedure's own passes it among its named inputs. A test walks the citation graph the suite already reads and enforces all four.
