## Overview

Measure Repository Change leaves its review worktree reusable and measures a pull request against the commit its change starts from. Index Repository writes the index alone, and Change Surface compares against the merge base of the verified head and the pull request's base commit.

## Problem

- **Indexing dirties the review worktree.**
  `gitnexus analyze` rewrites the GitNexus section of AGENTS.md and CLAUDE.md and installs skill files in the checkout it indexes, so Create Pull Request Worktree refuses to reuse an indexed review worktree.
- **The base branch name moves.**
  Change Surface passes the base branch name to `--base-ref`; once that branch moves past the pull request, as a merge moves it, the surface is empty or carries unrelated changes.

## Proposal

- **The scene.**
  Understand mode measures a pull request in a detached review worktree, through Change Overview's call to Measure Repository Change with the pull request's head and base.
- **Indexing writes only the index.**
  Index Repository runs `gitnexus analyze --index-only`, GitNexus's pure index mode, which skips AGENTS.md, CLAUDE.md and every skill file.
- **The surface compares against the merge base.**
  A Merge Base command takes the verified head and the snapshot's `base.sha` and prints their merge base; Change Surface passes that commit to `--base-ref`. Base Commit and Comparison Base replace the Base Branch field, and Change Overview supplies the base commit.
