## Overview

Work Planner loads common rules and conventions before mode selection and keeps deployed values in linked configuration sections. The shared checker validates heading procedures and HTML invocations for each selected model, using the same parser and contract ownership for citation and interface checks. Modes and protocols expose ordered heading steps and explicit artifact and procedure calls. Issue and body artifacts link accepted record shapes and execute their commands within ordered steps. Delivery, branch, pull-request, board, queue, planning and review artifacts expose linked contracts and execute commands in their owning steps.

## Changes

The epic base carries the declared-model checker capability, its acceptance/rejection specimens, Work Planner's common context files and its mode, protocol and artifact presentation under the installed Work Planner style declaration.

### Declared Models

- **Structure selection.**
  Explicit file entries select entry layouts; typed options describe heading steps, preambles, field contracts and call verbs.
- **Procedure contracts.**
  Step sequences follow their parent procedure, and Inputs/Outputs resolve the owning artifact's field contracts.

### Invocation Reading

- **Literal command payload.**
  One lexical reader owns Markdown fences and HTML invocations, preserving shell text and required bold argument links.
- **Execution and interfaces.**
  Selected invocation models require executing-step placement, with GraphQL REST-gap evidence scoped there and Projects V2 checks preserved.

- **Argument classification.**
  Bold contract arguments are validated before ordinary Markdown links, preserving literal title-prefix filters and rejection of unsupported contract targets.

### Common Context

- **Rules and conventions.**
  `skills/work-planner/SKILL.md` selects modes after loading `rules.md` and `conventions.md`, preserving their operative conditions.
- **Configuration.**
  Board titles and fields, planning-record placement and the reporting default have one documented home; consuming sections select applicable configuration reads.
- **Reader ownership.**
  Guidelines and checkout-vocabulary validation use their declared homes and the installed Work Planner model.

### Mode Procedures

  Revise's named verification procedures hold HTML invocations and linked argument contracts with preserved command syntax and explicit examples.
- **Source readers.**

### Protocol Procedures

- **Ordered coordination.**
  Protocols use numbered heading steps, Rules/Conventions preambles and scoped flush conditions while preserving prerequisites, inputs, refusals and return points.

- **Evidence boundaries.**

  Operations link their accepted inputs and returned states, distinguishing complete JSON records, body text, identities and supplied versus posted values.

  Commands use raw HTML within ordered heading steps, with linked argument contracts and preserved literal syntax, examples and prerequisites.
- **Template and interface readers.**
  Body-template fences recognize valid closing indentation; document readers verify linked contracts, step order, fetched-base inputs and cited executable reach.
- **Evidence boundaries.**

### Delivery Artifacts

- **Contracted operations.**
  Delivery plans, briefs, dispatch batches, branches and pull requests link accepted input and result contracts, with distinct record, identity, metadata and destination shapes.
- **Executing steps.**

  Board, queue, planning and review operations link accepted shapes once, with runtime guards and flag bindings in executing steps.

  Board Queue owns Ready Units and Report Lines and links Lane's task-lane reading, unit-lane checks and report labels.

  Required style, suite and preservation checks pass; all six supplementary repeated walks remain Partial, with unmeasured sketches excluded from formal graph claims and bounded goal concerns unapplied.
