**Component:** workspace:skills/scripts/check_skill_files.py

## Overview

The shared skill-file check places a command specification by how many procedures run it. A specification no procedure runs falls outside that count, so the check said nothing about it, and a reader could not tell a section deliberately kept with its subject from one nothing reaches. This task states what holds at zero callers and reports the one case that is a defect: a specification nothing cites.

## Problem

- **The rule reads a count it cannot interpret at zero.**
  A specification moves to its caller where exactly one procedure runs it. Zero is neither one nor several, so the rule passed over every such section silently.
- **Zero-caller specifications are common and mostly deliberate.**
  Measured with the check's own citation relations over every skill at `707c1bb2`: Work Planner has none, since its sections were rehomed by earlier tasks; Workflow Canon has thirty, twenty-eight of them named only by reference prose of their own subject (Coverage, Canon Context, Change Surface) and two reached by a sibling specification.
- **Two of them have no reader at all.**
  `Render Audit Surface` and `Run Audit Script Tests` in `workflow-canon/references/change-surface.md` are cited from nowhere, so no route a reader follows arrives at them.

## Proposal

- **The scene.**
  A reader of Change Surface's reference prose is told to inspect status, refresh, reset and retry; each link lands on a command beside that prose. No numbered step runs any of them, and none needs to move, because no caller exists to move it to.
- **State the exclusion in the shared guidelines.**
  A specification no procedure runs has no caller to place it, so it stays with the subject of the file whose prose or sibling specification names it. One nothing cites has no reader, whatever structure holds it.
- **Report the uncited specification.**
  The check reports `command specification nothing cites` for a specification no file cites, subject-owned structures included. The entry point's specifications are already reported as misplaced, so they are not reported twice.
- **Give the two orphans a reader.**
  Revise Mode runs the audit script tests beside the other skill suites, so `Run Audit Script Tests` moves into its Commands and its Verify step cites it. Freshness and Resume names `Render Audit Surface` as the regeneration of views a reader finds missing or hand-edited, since every state change already renders them.
