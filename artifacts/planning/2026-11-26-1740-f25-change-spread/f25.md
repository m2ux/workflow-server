## Overview

A work-planner change touches the code it changes, its tests and the one place its rule is stated. The test index maps scripts and documents to the modules that reach them without counts, every `config/` declaration is read at the tooling branch's remote head as one field states, and a step calling a reader names what it supplies and reacts to the reader's result.

## Problem

- The test index carried each module's test count on every row naming it, and `test_readme` held each count to the module's test methods: adding three tests to `test_documents` in #1739 edited nine rows.
- Callers restated where a reader reads: Prepare Delivery Bases and Read Delivery Branches restated that `config/branches` sits on the tooling branch, `epic.md`'s Sync Epic delivery fields did the same, and Sync Mode's unevaluable route named the tooling branch twice.
- `format.py` read `config/required-criteria.json` at a `--revision` each caller supplied, the epic base on the configuration's long-lived branch. A project keeping `config/` on its tooling branch alone, as workflow-server does (`origin/workflows` carries no declaration, yet the declared criterion targets `workflows`), had its required criteria skipped without a finding.

## Proposal

- **The index maps; the suite counts.** Counts leave the coverage table and its prose; `test_each_count_is_the_modules_test_methods`, `test_each_named_module_carries_its_count`, `test_count` and `COUNT` leave `test_readme.py`. The script count in the README's opening goes with them.
- **One field states where declarations are read.** A [Tooling Branch](https://github.com/m2ux/workflow-server/blob/f25-change-spread/skills/work-planner/artifacts/delivery-branches.md#tooling-branch) field holds the rule F24 put in Branches, for every `config/` declaration. Branches and Required Criteria link it; fetch steps name it.
- **Required criteria at the tooling branch.** `TOOLING_BRANCH` lives in `format.py`, which `sync.py` imports; `required_criteria(project)` reads there; `format.py` takes no `--revision`. The Evaluated Revision fields of `epic-issue-body.md` and `issue-body.md` go. Check Body Format states the tooling-branch fetch before a run with `--project`, as Sync Epic does: a fetch step in Validate Epic Body would make it an acting operation and require every caller up its call chain to name a checkout.
- **Callers react to results.** Prepare Delivery Bases reacts to the listing reporting unevaluable names; Read Delivery Branches retains them; `epic.md` Source and Unevaluable link Branches; Sync Mode fetches each branch or head the run names unread.

## Added Scope

Two pre-existing faults in files F25 declares, added at the user's request:

- **One module by name.** `test/README.md`'s Run one module by name command, `python3 -m unittest -v test.test.format`, errors: `test/` is not a package. It reads `python3 -m unittest discover -v -s test -p test_format.py`.
- **Declaration before the paths it selects.** Validate Epic Body read changed paths for the branches the Required Criteria declare before the step that read the declaration. The declaration read and its unevaluable case are step 1; changed paths are step 2; the gate that an unevaluable declaration reports no epic as lacking a criterion sits in Identify Required Criteria, the step that reports lacking criteria.
