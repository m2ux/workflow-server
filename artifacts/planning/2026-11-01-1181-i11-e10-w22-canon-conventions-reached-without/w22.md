**Component:** workspace:skills/workflow-canon/SKILL.md

## Overview

Workflow Canon's skill-wide execution conventions stand in its entry point, which every mode opens to be selected, and Run Project Check stands as a command specification in the mode file whose procedure runs it. The separate conventions file goes, so no mode opens a file to learn how its commands run.

## Problem

- **Conventions cost a file.**
  `references/command-conventions.md` holds the skill-wide conventions, so each mode opens a file it needs for nothing else before its first command.
- **Run Project Check is no specification.**
  It stands as a second-level section of that file, outside any Commands section, so the checker recognizes no specification and its placement rule never reaches it.
- **A caller and a reader are distinct.**
  Review Mode's procedure runs Run Project Check. Revise Mode's Run Skill Checks specification and Canon Context's prose cite it without running it, so they add no caller.

## Proposal

- **Conventions stand in the entry point.**
  SKILL.md takes a Conventions section between Rules and Dependencies, as the shared guidelines name it, holding the Common conventions whole. The Commands rule and each mode's Prerequisites citation of the conventions file go, since the reader already holds SKILL.md.
- **Run Project Check stands with its caller.**
  It moves under Review Mode's Commands section as a third-level specification. Revise Mode and Canon Context link it there.
- **The conventions file goes.**
  Once both subjects have their homes, `references/command-conventions.md` is removed, and every description of a separate conventions file is rewritten: Workflow Canon's guidelines and the shared guidelines' SKILL.md structure.
